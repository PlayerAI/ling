# RFC-0044: Bounded Transactional LSP Code Action Preview / 有界事务式 LSP 代码动作 Preview

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-24
> 目标版本：v0.1 Preview
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001，GAP-SEMANTIC-PROTOCOL-LIFECYCLE-001，GAP-FORMATTER-AUTHOR-SOURCE-001，GAP-UNICODE-ALIAS-SYNTAX-001，GAP-AUTHOR-SOURCE-LOCALIZATION-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines Ling's bounded Seed `textDocument/codeAction` behavior. It
exposes one checked whole-document formatter action through a versioned,
transactional Workspace Edit. It does not turn diagnostic `Repair` metadata
into edits, infer fixes from messages, or authorize unsupported semantic
rewrites.

本 RFC 定义 Ling 有界的 Seed `textDocument/codeAction` 行为。它通过带版本的事务式
Workspace Edit 暴露一个已检查的整文档格式化动作；它不会把诊断 `Repair` 元数据直接
变成编辑，不从消息推断修复，也不授权尚不受支持的语义重写。

## Summary

`ling.lsp.code-action/0.1` is a capability-negotiated Preview protocol. For an
open writable document, the server may return exactly one
`source.fixAll.ling.format` Code Action. The action is derived from the accepted
compiler-CST formatter and its in-process `FormatEdit`, is bound to the complete
immutable request snapshot and client document version, and contains one
versioned `documentChanges` edit. The server never applies the edit.

This bounded action closes IDE-2309 for the v0.0.1 Seed implementation. Missing
imports, confusable renames, mutability changes, match-case synthesis, and stale
syntax replacement remain unavailable because the current compiler has no
Accepted checked edit producers for them. Adding any such action requires a new
protocol marker and conformance evidence.

- In scope:
  - standard `textDocument/codeAction` with static capability negotiation;
  - exactly the custom standard-hierarchy kind
    `source.fixAll.ling.format`;

## Normative changes

### 1. Capability validation and discovery

Initialize recognizes optional `capabilities.textDocument.codeAction`. When
present it MUST be an object. Optional `dynamicRegistration` MUST be boolean.
Optional `codeActionLiteralSupport` MUST be an object containing an object
`codeActionKind`, whose required `valueSet` is a non-empty array of strings.
Unknown ordinary members are ignored; a malformed known member rejects
initialize without state mutation.

The formatter action is capability-enabled only when all of these hold:

1. `codeActionLiteralSupport.codeActionKind.valueSet` contains the exact string
   `source.fixAll.ling.format`;
2. RFC-0041 workspace-edit negotiation has `documentChanges: true`; and
3. `failureHandling` is exactly `transactional`.

The negotiation result is fixed for the session. For a client without all
three capabilities, initialize omits `codeActionProvider` and
`lingCodeAction`; `textDocument/codeAction` fails as unavailable. Existing
initialize results therefore remain unchanged for incapable clients.

For a capable client, initialize adds exactly:

```json
"codeActionProvider": {
  "codeActionKinds": ["source.fixAll.ling.format"],
  "resolveProvider": false
},
"lingCodeAction": {
  "actionKinds": ["source.fixAll.ling.format"],
  "maxActions": 1,
  "result": "versionedDocumentChanges",
  "source": "compiler-cst-format-plan",
  "transactional": true,
  "version": "ling.lsp.code-action/0.1"
}
```

The discovery object adds no custom request and does not advertise quick fixes,
refactorings, commands, resolve, or dynamic registration.

### 2. Request and kind filtering

`textDocument/codeAction` is request-only and available only in Ready state
after successful capability negotiation. Notifications produce no response and
perform no work.

Params MUST be an object containing:

- `textDocument.uri`: string;
- `range.start` and `range.end`: unsigned-u32 `line` and `character` pairs; and
- `context.diagnostics`: array.

Optional `context.only` MUST be a non-empty array of strings. Optional
`context.triggerKind` MUST be integer `1` or `2`. Unknown ordinary fields are
ignored. Malformed known fields, reversed or unprojectable ranges, unknown
documents, and positions that cannot map exactly through the negotiated
encoding are InvalidParams; positions are never clamped.

The requested source action is eligible when `only` is absent or contains one
of `source`, `source.fixAll`, or `source.fixAll.ling.format`. Other filters
return an empty result. The request range is validated but does not narrow the
whole-document source action.

Every `context.diagnostics` element is opaque filter context. Version 0.1 does
not inspect its message, code, range, `data`, Facts, repairs, Semantic ID, or
unknown fields. Client-supplied diagnostics can neither create nor modify a
plan. The server does not parse diagnostic text under any circumstance.

### 3. Immutable snapshot and eligibility

The server captures one complete path-free Request Snapshot when dispatching
the request. The URI MUST identify a currently open writable workspace or
temporary overlay. Closed, dependency, generated, virtual, read-only, missing,
or invalid documents cannot produce an action.

The captured request document supplies the exact URI, logical source name,
bytes, origin, writability, VFS revision, and integer client version. Project
inputs and every visible document remain part of freshness even though the
bounded action edits one document. No disk, environment, clock, network, cache,
or client state may be consulted.

### 4. Structured formatter FixPlan

The server MUST construct a `SourceFile` from the captured bytes, parse with the
compiler lexer/parser, build the compiler-CST `FormatDocument`, and invoke
`format_core_edit`. Regexes, Tree-sitter, a second parser, textual heuristics,
unchecked AST evaluation, and client diagnostics are forbidden as plan
producers.

An invalid or recovery source, rejected formatter candidate, or unchanged
source produces no plan and returns `[]`. A changed accepted result produces
one immutable internal `FixPlan` containing exactly:

1. protocol version and action kind;
2. captured URI and integer client version;
3. the `FormatEdit` source identity and complete original UTF-8 byte range;
4. exact replacement text; and
5. the complete originating Request Snapshot.

The plan contains no title text as authority, diagnostic message, host path,
resolver/Semantic ID, compiler debug output, timestamp, or executable command.
The implementation MUST validate that the `FormatEdit` source identity equals
the request source, its range is exactly `0..original_byte_length`, and its
replacement satisfies the existing formatter publication result. Any mismatch
fails atomically.

At most one plan, one document, and one edit may be returned. Version 0.1 has no
multi-file ordering or overlap surface; adding either is incompatible.

### 5. Versioned Workspace Edit projection

The result is an array containing zero or one standard Code Action. The one
action has exactly this shape, with values derived as specified below:

```json
{
  "edit": {
    "documentChanges": [{
      "edits": [{
        "newText": "let value = 1\n",
        "range": {
          "end": {"character": 12, "line": 0},
          "start": {"character": 0, "line": 0}
        }
      }],
      "textDocument": {
        "uri": "ling://workspace/src/Main.ling",
        "version": 7
      }
    }]
  },
  "isPreferred": true,
  "kind": "source.fixAll.ling.format",
  "title": "格式化文档 / Format document"
}
```

The action contains no `command`, `data`, `diagnostics`, `disabled`, extension
field, or second edit. `title` is fixed bilingual display text and is not an
identity or localization key. Consumers select behavior through `kind` and the
versioned discovery contract, never by parsing `title`.

The edit is the RFC-0026 whole-document projection. `range.start` is
`{line: 0, character: 0}` and `range.end` is the original document end under
the negotiated encoding. `newText` is the exact accepted formatter
replacement. A leading UTF-8 BOM remains outside the lexical LSP range and is
removed exactly once from `newText`, as in RFC-0026. CRLF input positions derive
from original bytes while accepted formatter output remains LF.

`textDocument.uri` is the exact captured URI and `version` is the captured open
document's integer client version. The Workspace Edit contains only
`documentChanges`; it has no `changes`, resource operation, or annotation. The
server never applies it. Transactional application and rollback are the
negotiated client's responsibility.

### 6. Freshness, bounds, and failures

Before every successful response, including `[]`, the server recaptures and
compares the complete Request Snapshot. Any lifecycle, encoding, workspace
revision, document URI/logical name/version/origin/open/writable/temporary/
bytes, or project-input difference makes the request stale. A stale or failed
request publishes no partial action and mutates no state.

The RFC-0004 1 MiB encoded response bound applies. The one-action, one-document,
one-edit cardinality is fixed. No replacement is truncated to fit a bound.

Malformed params use InvalidParams `-32602` with
`代码动作参数无效 / invalid code-action parameters`. Unnegotiated capability,
ineligible document state, formatter/projection/plan failure, stale completion,
or response-bound failure uses RequestFailed `-32803` with
`代码动作不可用 / code action unavailable`. A valid request with a nonmatching
kind filter, invalid/recovery/unchanged source, or no accepted plan returns
`[]`. No Ling compiler diagnostic is allocated.

Any incompatible capability, discovery, params, kind/filter, diagnostic
opacity, eligibility, plan, projection, title, version, result, empty-result,
freshness, bound, or failure change requires a new protocol marker and
migration evidence.

## Conformance plan

- Verify capable and incapable initialize shapes, malformed capability cases,
  static discovery, lifecycle, notification silence, and unnegotiated failure.
- Verify exact params, unknown ordinary fields, invalid URI/range/position,
  trigger kinds, source-kind filters, and fixed bilingual failures.
- Verify one exact action and versioned Workspace Edit for changed valid input;
  unchanged, invalid, recovery, closed, read-only dependency, and unsupported
  filter cases return no action or the specified failure.
- Prove client diagnostics and localized message changes cannot create or
  alter an action, `Repair` metadata is not treated as an edit, and no internal
  identity, path, diagnostic, command, annotation, or server mutation appears.
- Cover UTF-8/16/32, Chinese, combining characters, emoji prefixes, BOM, CRLF,
  exact document versions, stale version/bytes/workspace inputs, repeated
  determinism, response bounds, and formatter idempotence.
- Add exact protocol transcripts and run locked offline workspace tests, strict
  Clippy, CI, governance, LSP, support, status, RC0, traceability, formatting,
  and diff gates.

## Compatibility impact

- **Protocol:** adds capability-negotiated Preview
  `ling.lsp.code-action/0.1` with no predecessor; incapable clients retain the
  prior initialize response and have no provider.
- **Formatter/query:** composes the existing compiler-CST formatter and
  `FormatEdit` into one request-local internal plan without changing formatter
  output or promising a persistent cache.
- **Diagnostics/identity:** diagnostic data is opaque input context; no code,
  Repair kind, Facts schema, Semantic ID, or canonical-byte change is made.
- **Language/runtime/data:** no Ling syntax/semantics, Typed Core evaluation,
  interpreter, runtime, bytecode, VM, ABI, package, filesystem/network, or
  Unicode 17.0.0 behavior changes.

## Unresolved alternatives

Missing-import, confusable-rename, mutability, match-case, and stale-syntax
actions remain deferred until Accepted checked producers define their semantic
safety and exact edits. Diagnostic quick fixes, multi-document plans, Code
Action resolve, commands, annotations, generated/dependency mutation,
asynchronous cancellation, general Semantic Transactions, and Stable lifecycle
also require later authority and migration evidence.
