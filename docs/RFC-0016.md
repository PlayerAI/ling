## Summary

This RFC extends Accepted RFC-0015 with the backward-compatible
`ling.bytecode/1.2` aggregate and pattern-matching slice owned by VM-1206.
It defines portable value types and instructions for tuples, nominal records,
nominal variants, constructors, immutable record updates, field projection,
variant-case tests, and variant-payload projection. Checked Core supplies the
already-typed match decision tree; the VM does not re-run type inference or
exhaustiveness analysis.

The revision preserves RFC-0014/RFC-0015 register, block, source-map, Effect,
Capability, limit, and Runtime Fault rules. It describes values abstractly and
does not expose Rust layout, pointers, hash-map order, or an ABI.

## Normative changes

### 1. Version boundary

The protocol identifier is `ling.bytecode/1.2`, encoded as format tuple
`(1, 2)` in the unchanged 40-byte RFC-0014 header. A 1.2 reader MUST accept
and verify every valid 1.0 and 1.1 artifact under their original rules. A 1.0
or 1.1 reader MUST reject 1.2 before decoding version-specific tables or
instructions. A 1.2 writer emits only `(1, 2)` and migration means verified
decode followed by verified re-encoding; header patching is forbidden.

All 1.0/1.1 bytes retain their meaning. The new types and instructions are
illegal in earlier revisions. The revision remains Experimental and does not
create an N-1 release promise or Stable ABI.

### 2. Aggregate value types

The first four scalar records and the 1.1 function records retain their exact
wire representation. Version 1.2 adds these type tags:

```text
TupleType {
    tag:             u8 = 0x11
    reserved:        [u8; 3] = zero
    elements:        vector<TypeIndex>
}

RecordType {
    tag:             u8 = 0x12
    reserved:        [u8; 3] = zero
    module:          ModuleIndex
    name:            StringIndex
    arguments:       vector<TypeIndex>
    fields:          vector<RecordField>
}

RecordField {
    name:             StringIndex
    value_type:       TypeIndex
    flags:            u8       # bit 0 = source mutable declaration
    reserved:         [u8; 3] = zero
}

VariantType {
    tag:             u8 = 0x13
    reserved:        [u8; 3] = zero
    module:          ModuleIndex
    name:            StringIndex
    arguments:       vector<TypeIndex>
    cases:           vector<VariantCase>
}

VariantCase {
    name:             StringIndex
    has_payload:      u8       # 0 or 1
    reserved:         [u8; 3] = zero
    payload_type:     TypeIndex  # NO_INDEX exactly when has_payload = 0
}
```

Every referenced type index MUST be smaller than the containing type index.
This makes the wire type graph acyclic and permits bounded single-pass
verification. Generic source declarations are represented only after checked
instantiation; type arguments are recorded so two nominal instantiations are
never structurally interchangeable. Record fields and variant cases retain
declaration order; field names and case names are unique NFC strings. A record
or variant identity is `(module, name, arguments)` and its shape MUST agree
with the corresponding checked nominal declaration. The mutable flag is
metadata only in 1.2; mutation is owned by VM-1207.

Type records are unique and sorted by `(tag, module, name, arguments, shape)`
after the scalar prefix. Tuple elements and aggregate fields/case payloads
are strict values, not references to host objects. Aggregate values have no
observable identity and are not compared, ordered, hashed, or serialized by
this revision.

### 3. New instructions

Every instruction keeps RFC-0014 record framing and the one-byte opcode plus
three zero reserved bytes. Version 1.2 adds:

| Opcode | Name | Operands after prefix | Static result and behavior |
| ---: | --- | --- | --- |
| `0x14` | `MakeTuple` | `dest, tuple_type, element_count, elements...` | constructs the exact tuple type in `dest`; evaluates elements in encoded order |
| `0x15` | `GetTuple` | `dest, tuple, element_index` | projects one checked tuple element |
| `0x16` | `MakeRecord` | `dest, record_type, field_count, field_values...` | constructs the nominal record in declaration-field order |
| `0x17` | `GetField` | `dest, record, field_index` | projects one checked record field |
| `0x18` | `UpdateRecord` | `dest, base, update_count, (field_index, value)...` | copies the base and replaces named fields; updates are applied in source order |
| `0x19` | `MakeVariant` | `dest, variant_type, case_index, payload_register_or_NO_INDEX` | constructs one nominal variant case; payload arity is exact |
| `0x1A` | `VariantIs` | `dest, variant, case_index` | produces `Bool`; succeeds only for the verified variant type/case |
| `0x1B` | `GetVariantPayload` | `dest, variant, case_index` | projects the payload of a verified payload-bearing case |

`MakeTuple`, `MakeRecord`, `UpdateRecord`, `MakeVariant`, `GetTuple`,
`GetField`, and `GetVariantPayload` are Pure. `VariantIs` is Pure. No new
instruction contributes an Effect or Capability. A constructor with a payload
is lowered directly to `MakeVariant`; first-class polymorphic constructor
values remain outside this revision.

`UpdateRecord` is an immutable value operation even when the source declaration
contains a mutable field. It allocates one logical aggregate value and does
not mutate or alias the base value. Assignment to a mutable Place is not
accepted by 1.2 and remains VM-1207.

### 4. Checked match decision trees

Lowering MUST consume a checked, typed decision tree whose clauses retain
source order and guards. It MAY represent a tree with ordinary blocks and
`Branch`, using `VariantIs`, `GetVariantPayload`, `GetField`, and `GetTuple`.
It MUST evaluate the scrutinee once, test clauses top-to-bottom, evaluate a
guard only after its pattern succeeds, and never evaluate a skipped body or
guard. Binding environments created by a successful pattern are immutable
register values. Exhaustiveness and unreachable-case decisions are checker
responsibilities; the VM does not infer or repair them.

The tree MUST contain a path for every checker-proven case. If a verified
aggregate value contains an impossible case index, wrong nominal type, missing
payload, or invalid field index, the VM raises an internal verifier/runtime
fault without exposing a host panic. A normal non-match is not a Runtime Fault
because checked Seed match is exhaustive.

### 5. Verification

The verifier extends RFC-0015's ordered phases with:

- aggregate type tag, reserved bytes, topological references, nominal identity,
  field/case uniqueness, declaration order, mutable flags, and payload sentinel
  checks;
- exact instruction result/operand types, tuple arity, field/case bounds,
  update uniqueness, payload presence, and source-map coverage;
- proof that `UpdateRecord` targets an immutable value operation and that all
  `VariantIs`/`GetVariantPayload` operations refer to the same verified variant
  type;
- exact aggregate construction and projection shapes, with no host-layout
  assumptions.

Malformed aggregate bytes are `L-BYTECODE-*`. Compiler-produced invalid
aggregate bytecode is `L-INTERNAL-0001`. An impossible aggregate invariant
after `VerifiedProgramV1` construction is an internal VM error, not a user
source fault.

### 6. Runtime, limits, and determinism

The VM stores aggregate values in an abstract value representation and uses
the existing iterative frame stack. It charges one logical step before every
new instruction and applies the existing heap/frame limits before publishing a
constructed aggregate. Allocation failure is `L-RUNTIME-0001` with category
`out_of_memory` or `resource_limit`, retaining the instruction's original
source span and commit ordering.

Field/case order, type-table order, update order, instruction order, source-map
order, and disassembly MUST be byte-identical for the same checked snapshot and
lowering options across processes, hash seeds, paths, and supported hosts.
Aggregate allocation identity, pointer topology, Rust enum layout, map order,
and debug output are not Ling semantics.

## Conformance plan

- Freeze independently constructed 1.2 bytes and disassembly for tuples,
  records, nullary and payload variants, field projection, immutable update,
  nested patterns, guards, and an exhaustive match; require decode-verify-
  encode byte equality.
- Lower and execute checked source for declaration-order-independent record
  literals, nominal record rejection, ADT constructors, nested constructor and
  record patterns, tuple payloads, wildcard/binding patterns, guard order, and
  immutable update alias isolation.
- Differentially compare interpreter and VM results, Console events, Runtime
  Fault category/operation/commit state, and original UTF-8 source spans.
- Add malformed vectors for forward/cyclic type references, duplicate fields or
  cases, wrong nominal identity, invalid mutable flags, tuple arity, field/case
  bounds, payload sentinel/arity, duplicate updates, invalid projections,
  missing source maps, and 1.0/1.1 reader rejection of 1.2.
- Run arbitrary-byte and valid-model mutation tests with bounded allocation,
  deterministic first-error ordering, no panic, and deterministic output across
  source roots, line endings, process hash seeds, and host paths.

## Compatibility impact

- **Source:** no syntax or checker rule changes. Existing checked Seed aggregate
  and exhaustive-match programs gain an Experimental VM representation; the
  interpreter remains authoritative.
- **Binary protocol:** adds backward-compatible `ling.bytecode/1.2`; earlier
  readers reject it and a 1.2 reader preserves valid 1.0/1.1 meaning. No Stable
  or N-1 release promise is created.
- **CLI:** none; no default backend or bytecode artifact command is added.
- **Diagnostics:** no existing diagnostic meaning changes. New malformed-input
  reasons use registered bilingual `L-BYTECODE-*` codes; Runtime Fault mapping
  remains `L-RUNTIME-0001`.
- **Schema/Semantic IDs:** none. Aggregate type and bytecode indexes are
  artifact-local and do not alter Semantic IDs or DEC-0012 canonical bytes.
- **ABI/FFI:** none. The abstract aggregate representation is not a native or
  foreign layout.
- **Determinism/Unicode:** type, field, case, update, and source-map order is
  canonical; Unicode remains 17.0.0 and original UTF-8 spans are preserved.

## Unresolved alternatives

- A runtime tag exposed as an ordinary user `Int` was rejected because it would
  make verifier-generated discriminants forgeable; `VariantIs` keeps tags
  internal to verified operations.
- In-place record mutation was rejected because Seed record update is a new
  Value and mutable Place ordering belongs to VM-1207.
- Runtime reflection or structural record compatibility was rejected because
  records are nominal and their identity must remain stable across modules.
- Tuple/aggregate equality, list layout, recursive wire types, first-class
  polymorphic constructors, and native layout remain separately governed work.
