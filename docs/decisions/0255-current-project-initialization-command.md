# DEC-0255: Current project initialization command / 当前工程初始化命令

> 状态：Accepted
> 提出日期：2026-08-23
> 决定日期：2026-08-23
> Owner role：cli-design
> 相关 RFC/缺口：RFC-0002 | DEC-0038 | DEC-0253 | DEC-0254 | CLI-1703
> 生命周期记录：`docs/governance/lifecycle.toml`

This decision closes CLI-1703 by accepting the already implemented DEC-0038
offline scaffold as the complete current project-initialization command. It
resolves lower-authority planning drift without extending the RFC-0002 manifest
or generating an editor file whose schema is not accepted.

本决定接受已实现的 DEC-0038 离线脚手架作为当前完整工程初始化命令，从而关闭
CLI-1703。它解决低层级计划漂移，但不扩展 RFC-0002 manifest，也不生成尚无
Accepted schema 的编辑器文件。

## Question

Does CLI-1703 require a second initializer layer for the execution plan's
manifest template field and optional `.zed/tasks.json`, or may the accepted,
failure-atomic four-file `ling init` command close the task?

## Decision

1. CLI-1703 is exactly the current `ling init` command accepted by DEC-0038:
   one missing destination, optional package/display names, and the four files
   `.gitignore`, `ling.lock`, `ling.toml`, and `src/Main.ling`.
2. The command is offline, deterministic, and failure-atomic. It writes and
   validates a private sibling staging directory, publishes by one rename, and
   removes its private staging directory after any pre-publication failure.
   Existing destinations are never reused or overwritten.
3. RFC-0002 remains authoritative for manifest-v1. The initializer MUST NOT add
   a template field to `ling.toml`. Template version `1` remains metadata in the
   `ling.init/0.1` success report, where DEC-0038 placed it.
4. The execution plan calls `.zed/tasks.json` optional. The current command
   omits it because no Accepted editor-task schema, binary-discovery contract,
   or support policy owns those bytes. Omission satisfies the current command;
   a future opt-in editor template requires its own Accepted authority and
   protocol inventory entry.
5. The public spellings remain `ling`, `ling.toml`, `ling.lock`, and `.ling`.
   Stale `zero`, `.zero`, and `zero.*` plan placeholders remain invalid.
6. DEC-0254 applies to the command's human success summary and diagnostics.
   Its existing `ling.init/0.1` JSON object, diagnostic mappings, stdout/stderr
   ownership, and exit classes remain unchanged.
7. `--force`, existing-empty-directory reuse, current-directory defaulting,
   custom versions/templates, workspaces, dependencies, editor generation, and
   ambient discovery are separate future features, not incomplete CLI-1703
   acceptance criteria.

## Conformance plan

- Retain exact generated-byte, manifest, module-discovery, canonical-lock,
  report-schema, package/display-name, and existing-destination tests.
- Retain invalid metadata, missing/non-directory parent, staging cleanup,
  deterministic file-list, offline, and no-partial-publication evidence.
- Verify output-policy quiet/JSON behavior composes without altering generated
  files, report fields, diagnostics, or exits.
- Verify help advertises `ling init` and no stale `zero`/`.zero` spelling.
- Run workspace, CI, governance, support, status, RC0, traceability, Clippy,
  formatting, and deterministic-diff gates.

## Compatibility impact

- **CLI:** closes the existing Preview command; no option or generated byte is
  added or removed.
- **Protocols:** `ling.init/0.1`, manifest-v1, and `ling.lock/1` remain at their
  current versions and stability.
- **Language/compiler:** no syntax, type, Effect, Checked Core, runtime,
  diagnostic allocation, Semantic ID, Audit, bytecode, VM, ABI, or span change.
- **Determinism/offline:** no environment lookup, parent search, shell, network,
  clock-derived output, or unordered file enumeration is introduced.
- **Unicode:** remains 17.0.0; display-name validation and UTF-8 source bytes are
  unchanged.
- **Migration:** none; this accepts current bytes and explicitly rejects stale
  lower-authority template assumptions.

## Unresolved alternatives

In-place initialization, selectable templates, workspaces, dependency prompts,
editor task generation, language-server acquisition, and Stable scaffold
compatibility remain deferred.
