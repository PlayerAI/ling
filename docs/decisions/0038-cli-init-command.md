# DEC-0038: `ling init` project scaffold / `ling init` 工程脚手架

> Status: Accepted

This decision closes only the first, offline project-scaffold command. It does
not define project discovery, `test`, `build`, `query`, `patch`, workspace
selection, registry access, editor integration, or an in-place overwrite mode.

## Question

The execution plan requests a deterministic `init` command, but the accepted
CLI decisions do not define its destination, generated bytes, lock behavior,
or failure boundary. RFC-0002 already defines the manifest and lock protocols;
the command must compose those protocols without adding manifest fields or
ambient project discovery.

## Decision

1. The command is `ling init [--format human|json] [--name <package>] [--display-name <text>] <directory>`.
   Exactly one directory operand is required. The operand is used verbatim for
   user-facing output and is never written into package or lock identities.
   The parent directory must already exist and be a directory; the destination
   itself must not exist. `-`, an empty operand, overwrite, `--force`, parent
   search, environment lookup, and network access are rejected.
2. When `--name` is absent, the final destination component is the package
   name. It must satisfy RFC-0002's ASCII package-name grammar. `--name` uses
   the same validation. The package version is always `0.1.0` and the language
   version is always `0.1`; there are no version-selection flags. An optional
   `--display-name` is passed through RFC-0002's existing Unicode/NFC and
   security validation. Invalid manifest metadata uses the existing
   `L-PROJECT-*` diagnostics.
3. A successful invocation creates exactly these four paths, with UTF-8 bytes,
   LF line endings, and one final LF where shown: `ling.toml`,
   `src/Main.ling`, `.gitignore`, and `ling.lock`. The manifest is the
   RFC-0002 version-1 shape with package name/version/language, source root
   `src`, and entry module `Main`. The source contains `let main () = ()`.
   `.gitignore` contains the fixed two lines `target/` and `.ling-cache/`.
   No `.zed` or other editor file is generated because no accepted editor-file
   schema owns that output.
4. The scaffold is first written below a private sibling staging directory.
   The generated manifest is parsed, `src/Main.ling` is discovered, and the
   lock is produced through `resolve_package_graph_with_lock(..., Update)`.
   Only after all four files and the lock validate is the staging directory
   renamed to the missing destination. A failed operation removes only its
   private staging directory and publishes no partial destination. Host
   filesystem failures use `L-IO-0003` and exit class `4`; command misuse
   remains exit class `2`.
5. Human success output is one bilingual line. JSON success output is exactly
   one `ling.init/0.1` object containing `schema`, `status`, the operand
   `directory`, `template_version = "1"`, package name/version, and the sorted
   generated relative `files` list. The template version is report metadata;
   RFC-0002's manifest version-1 shape is not extended with an unregistered
   field. JSON failures use the existing bilingual Diagnostic JSON on stderr
   and do not emit a partial success object.

## Conformance plan

- Create a new destination with a derived ASCII name and with explicit ASCII,
  Unicode display-name, and CRLF-parent scenarios; verify exact generated
  bytes, the valid manifest, the discovered `Main` module, and canonical lock.
- Verify repeated runs with different process IDs and directory enumeration
  order produce identical file bytes and JSON fields for identical operands.
- Reject an existing file or directory, missing/non-directory parent, `-`,
  duplicate options, invalid package names, unknown options, and missing
  operands without creating files.
- Exercise filesystem failure/rename failure boundaries and verify no target
  directory or staging residue remains; prove no network or shell execution.
- Validate `ling.init/0.1` JSON against its schema and register the protocol,
  diagnostic allocation, fixtures, and release traceability.

## Compatibility impact

- Adds the Preview `ling init` command and `ling.init/0.1` success report;
  existing commands, output, diagnostics, schemas, Semantic IDs, runtime,
  bytecode, VM, and Unicode 17.0.0 behavior are unchanged.
- Adds `L-IO-0003` for scaffold filesystem failures without changing existing
  diagnostic meanings. RFC-0002 manifest and `ling.lock/1` bytes are reused,
  not extended.
- The command is offline, current-writer-only, and has no migration or
  overwrite promise. A future template, editor file, or in-place mode needs a
  new accepted decision and protocol/schema evidence.

## Unresolved alternatives

`--force`, empty-directory reuse, defaulting to the current working directory,
custom versions, template selection, `.zed/tasks.json`, workspace manifests,
parent/sibling dependencies, and project `test`/`build` behavior remain outside
this decision.
