# RFC-0040: Checked LSP Prepare Rename Preview / 已检查 LSP 重命名准备 Preview

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-23
> 目标版本：v0.1 Preview
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines Ling's bounded `textDocument/prepareRename` behavior. It
closes IDE-2305 as a read-only checked target-and-range query; it does not
accept a new identifier, compute edits, or promise identity preservation.

本 RFC 定义 Ling 有界的 `textDocument/prepareRename` 行为。它将 IDE-2305
限定为只读的已检查目标与范围查询；它不接收新标识符、不计算编辑，也不承诺身份保持。

## Summary

`ling.lsp.prepare-rename/0.1` selects one exact declaration or resolved
expression reference in a complete checked snapshot. A writable source-backed
target returns the selected identifier's exact range and original spelling as
the placeholder. Non-target, source-less, or read-only selections return
`null`.

## Normative changes

### 1. Capability validation and discovery

Initialize recognizes optional `capabilities.textDocument.rename`. When
present it MUST be an object. Optional `dynamicRegistration` and
`prepareSupport` MUST be booleans. Optional `prepareSupportDefaultBehavior`
MUST be the integer `1`. Unknown ordinary members are ignored. Malformed known
members reject initialize without state mutation. Version 0.1 uses static
registration.

Every successful initialize MUST advertise:

```json
"renameProvider": {
  "prepareProvider": true,
  "workDoneProgress": false
}
```

and:

```json
"lingPrepareRename": {
  "result": "rangeWithPlaceholder",
  "version": "ling.lsp.prepare-rename/0.1"
}
```

The Experimental object adds no custom request and does not advertise
`textDocument/rename` behavior.

### 2. Request and snapshot

`textDocument/prepareRename` accepts an object with required string
`textDocument.uri` and required unsigned-u32 `position.line` and `character`.
Unknown ordinary fields are ignored. Malformed known fields, unknown
documents, or positions that cannot map exactly through the negotiated
encoding return InvalidParams `-32602`; positions are never clamped.
Notifications perform no work.

The server MUST be Ready and capture one immutable path-free snapshot. A
non-temporary request checks the complete non-temporary source set. A
temporary request checks only that exact temporary source plus project inputs.
Before every success, including `null`, the complete snapshot MUST be
recaptured and compared; a difference fails without partial output or state
mutation.

### 3. Checked target selection

The compiler MUST complete resolution, type checking, and Effect checking and
build the same exact target grouping used by RFC-0039. The grouping MUST also
contain every source-backed definition and binding declaration even when it
has zero references. Selectors are exact original UTF-8 identifier spans and
use the RFC-0039 smallest-containing-span and canonical tie-breaking rules.
The existing 16384-selector bound applies atomically.

A selection is eligible only when it resolves to one source-backed declaration
and both the selected document and declaration document are writable. Thus
source-less builtin/Prelude targets, read-only dependency declarations,
dependency selections, unresolved names, keywords, literals, comments,
whitespace, generated/virtual sources, and non-resolver fields return `null`.
No target is inferred from spelling, types, coherence candidates, or Semantic
Graph data.

### 4. Exact result

An eligible selection returns exactly:

```json
{
  "range": {
    "start": {"line": 2, "character": 4},
    "end": {"line": 2, "character": 10}
  },
  "placeholder": "helper"
}
```

The range is the selected declaration or reference identifier span, projected
from original UTF-8 bytes through the negotiated encoding. `placeholder` is
the exact UTF-8 spelling inside that selected span, not the declaration's
spelling and not a normalized rewrite. The selected and declaration spellings
MUST both pass the existing Unicode 17.0.0 identifier observation and have the
same NFC name; inconsistency fails the request atomically. Existing
Identifier_Status or mixed-script facts do not create a new rename policy.

An ineligible or absent selection returns exactly `null`. Version 0.1 returns
neither a bare Range nor a default-behavior object and exposes no URI, version,
identity, mutability, provenance, package, host path, edit, or custom field.

### 5. Failures and plan drift

Resolution/type/Effect failure, invalid or oversized target grouping, missing
or duplicate source mapping, invalid span/projection/identifier invariant,
stale completion, or a response above RFC-0004's 1 MiB limit returns
RequestFailed `-32803` with fixed bilingual message
`重命名准备不可用 / prepare rename unavailable`. Invalid request data uses
`重命名准备参数无效 / invalid prepare-rename parameters`. No compiler
diagnostic is allocated.

Standard `prepareRename` has no `newName` field. Therefore the execution plan's
new-name legality/confusable/collision and visibility/coherence checks are
requirements of IDE-2306 `textDocument/rename`, not this read-only request.
Moving those checks does not weaken them and avoids pretending to validate data
the method never receives. An incompatible selection, writability, range,
placeholder, null, bound, snapshot, or failure behavior requires a new marker
and migration evidence.

## Conformance plan

- Verify exact discovery, malformed capabilities, lifecycle, notification
  silence, params, unknown URI, invalid positions, null, and fixed failures.
- Cover declarations and references for values, parameters, locals, Trait and
  implementation members, including unreferenced declarations.
- Cover source-less builtins, read-only dependency selections and targets,
  workspace and temporary sources, complete checked failure, and freshness.
- Cover UTF-8/16/32, Chinese, decomposed/NFC identifiers, emoji prefixes,
  combining marks, BOM, CRLF, exact placeholders, repeated determinism, bounds,
  and absence of IDs, paths, edits, versions, and custom fields.
- Migrate exact initialize transcripts and run locked offline workspace tests,
  strict Clippy, CI, governance, LSP, support, status, RC0, traceability,
  formatting, and diff gates.

## Compatibility impact

- **Protocol:** adds Preview `ling.lsp.prepare-rename/0.1`; no predecessor.
- **Compiler query:** makes unreferenced checked declarations selectable in the
  existing bounded reference grouping and adds a borrowed selection view; it
  promises no persistence or incremental cache.
- **Diagnostics/identity:** no diagnostic allocation and no Semantic/resolver
  ID schema or DefinitionId behavior change.
- **Language/runtime/data:** no Ling syntax/semantics, Typed Core evaluation,
  interpreter, runtime, bytecode, VM, ABI, package, filesystem/network, or
  Unicode 17.0.0 table change.

## Unresolved alternatives

Returning an error for ordinary non-renamable targets was rejected in favor of
the standard `null` result. Normalizing the placeholder was rejected because
the result range names the author's exact source spelling. New-name validation,
aliases, collisions, visibility/coherence simulation, generated documents,
multi-file edits, DefinitionId migration, cancellation, Workspace Edits,
Semantic Transactions, and Stable lifecycle remain IDE-2306 or later work.
