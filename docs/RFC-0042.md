> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines Ling's bounded `textDocument/completion` behavior. It closes
IDE-2307 with checked, deterministic candidates over one immutable source
snapshot. It does not define lazy completion-item resolution, documentation,
signature rendering, speculative recovery, AI completion, or a Stable editor
protocol.

本 RFC 定义 Ling 有界的 `textDocument/completion` 行为。它通过一个不可变源码
快照上的已检查、确定性候选项关闭 IDE-2307；它不定义延迟补全项解析、文档、
签名渲染、推测性恢复、AI 补全或 Stable 编辑器协议。

## Summary

`ling.lsp.completion/0.1` classifies one exact checked source position into an
expression, member, type, pattern/variant, import/module, or keyword context;
derives a bounded candidate pool from resolver and checked-type facts; validates
candidate edits against a fresh compiler; and returns a deterministic standard
Completion List containing only insertion-critical fields.

## Normative changes

### 1. Discovery and request shape

Every successful initialize advertises standard `completionProvider` with
`resolveProvider: false`, `triggerCharacters: ["."]`, and no additional
trigger or commit characters. It also advertises:

```json
"lingCompletion": {
  "contexts": ["expression", "member", "type", "pattern", "module", "keyword"],
  "maxItems": 256,
  "source": "checked",
  "version": "ling.lsp.completion/0.1"
}
```

The Experimental object adds no custom request. `textDocument/completion`
accepts required string `textDocument.uri`, required unsigned-u32
`position.line` and `position.character`, and optional object `context`.
Known `context.triggerKind` is required when `context` is present and MUST be
1, 2, or 3. `triggerCharacter` is permitted only for trigger kind 2 and MUST
be exactly `.`. Unknown ordinary fields are ignored; malformed known fields
return InvalidParams `-32602`. Notifications perform no work.

### 2. Immutable checked request boundary

The server MUST be Ready and capture one complete immutable path-free request
snapshot. A non-temporary request checks all visible non-temporary sources; a
temporary request checks only that exact temporary source plus project inputs.
The snapshot MUST lex, parse, lower, resolve, type-check, and Effect-check
completely before candidates are derived. Unknown documents, invalid exact
position projections, positions outside an existing identifier or fixed
language keyword, and incomplete source use InvalidParams or RequestFailed as
specified below; positions are never clamped.

The selected token's full original UTF-8 byte span is the replacement span,
except that `module` context replaces the complete containing Qualified Name.
Its bytes MUST decode as the exact token or Qualified Name spelling. Prefixes
are the bytes from replacement start through the requested scalar boundary. A
position inside a UTF code unit or scalar is invalid.

Before every successful response the complete snapshot MUST be recaptured and
compared. Any difference fails atomically; no document, VFS, diagnostic ledger,
or client state is mutated.

### 3. Context classification

Classification uses the valid compiler CST and the smallest containing
structural context, in this precedence:

1. an identifier after `.` in a Projection Expression is `member`;
2. a token in a Type Expression is `type`;
3. a token in a Pattern is `pattern`;
4. a token in an Import Declaration or its Qualified Name is `module`;
5. a fixed lexer keyword token is `keyword`;
6. a token in an expression is `expression`.

A Module Declaration header is not an import target and remains ineligible.
Ambiguous, recovery, comment, literal, punctuation, declaration-name, or other
positions return an empty complete list; the server never guesses from nearby
text. `pattern` covers variant constructors and the wildcard spelling `_`.

### 4. Candidate sources and validation

The compiler constructs one immutable catalog from the same checked program:

- resolver definitions retain kind, origin, module, normalized name, and
  existing identity;
- bindings retain module, exact source span, and binding identity;
- resolved import aliases retain importer module and target module;
- modules retain normalized module name and module identity;
- checked record fields retain owner definition and normalized field name.

The catalog is internal and MUST NOT expose identities, paths, spans,
provenance, types, Effects, or Capabilities. Context filters are:

- `expression`: values, constructors, builtins, Prelude constructors, visible
  bindings, and resolved import aliases;
- `member`: definitions owned by the resolved module qualifier, or checked
  record fields accepted for the target expression;
- `type`: user and Prelude type definitions, including a qualified imported
  type selected through member access;
- `pattern`: constructors and `_`;
- `module`: complete normalized module names excluding the importing module;
- `keyword`: the fixed Seed lexer keywords.

For every non-keyword candidate, the server replaces exactly the selected
token in owned bytes, builds a fresh compiler with the same project inputs and
visible-source policy, and requires complete resolution, type checking, and
Effect checking. This probe is the visibility, shadowing, member-owner,
type-fit, Effect-fit, Capability-fit, and ambiguity authority. A candidate that
does not produce a complete checked program is omitted. Keyword candidates
must produce a valid parse and complete checked program under the same probe.
No spelling search, partial resolver result, unchecked AST interpretation,
Semantic Graph inference, remote call, model, heuristic AI, or HashMap order is
permitted.

Candidates with the same insertion spelling are collapsed after validation.
The winning internal source is the best-ranked source below; internal identity
never distinguishes duplicate wire items.

### 5. Deterministic ranking and bounds

Candidates are ordered by this total tuple:

1. prefix class: exact spelling, case-sensitive prefix, then no prefix match;
2. scope proximity: same-module binding by nearest preceding declaration byte,
   other same-module binding, same-module definition, explicit import alias,
   imported definition/member, Prelude/builtin, module, field, keyword;
3. checked fit: complete checked replacement before any non-emitted source;
4. explicit-import priority: explicit alias/member before implicit
   Prelude/builtin candidates;
5. Unicode scalar-value lexicographic insertion spelling;
6. stable internal kind and identity ordering.

Only candidates whose insertion spelling has the requested case-sensitive
prefix are emitted. The candidate catalog and replacement-probe count are each
bounded to 512. The response contains at most 256 items. When more valid items
remain, `isIncomplete` is `true`; otherwise it is `false`. Bounds are applied
after deterministic sorting and duplicate collapse. RFC-0004's 1 MiB body
limit also applies. No wall clock, random seed, allocation address, filesystem
iteration, or locale participates in ordering.

### 6. Completion List and text edits

Success returns a standard Completion List object with exactly `isIncomplete`
and `items`. Every item contains exactly:

- `label`: the normalized candidate spelling;
- `kind`: standard CompletionItemKind `Constructor` (4), `Field` (5),
  `Variable` (6), `Class` (7), `Module` (9), `Value` (12), `Keyword` (14), or
  `Function` (3), according to the internal candidate category;
- `sortText`: a fixed-width ASCII encoding of the total rank plus ordinal;
- `filterText`: exactly `label`;
- `insertTextFormat`: PlainText (1);
- `textEdit`: standard `{range, newText}` replacing the exact selected token.

`newText` equals `label`. The range is single-line, contains the request
position, and is projected from original bytes using the negotiated UTF-8,
UTF-16, or UTF-32 encoding. Items contain no `detail`, `documentation`,
`insertText`, `insertTextMode`, `additionalTextEdits`, `command`, `data`, custom
field, identity, type, Effect, Capability, path, package, revision, or source
provenance. Clients gate on the exact Preview marker; resolve is unsupported.

### 7. Failures and compatibility

Invalid request shape, unknown document, invalid position projection, malformed
known context, or unsupported trigger uses `补全参数无效 / invalid completion
parameters` with InvalidParams `-32602`. Snapshot, compiler, source, catalog,
probe, projection, stale, bound, or response-size failure uses `补全不可用 /
completion unavailable` with RequestFailed `-32803`. An ordinary eligible
position with no valid prefix-matching candidate returns an empty complete
list. No compiler diagnostic is allocated.

Any incompatible request, context, candidate source, validation, ranking,
field, kind, edit, bound, snapshot, failure, or null/list change requires a new
protocol marker and migration evidence.

## Conformance plan

- Verify exact provider/discovery shapes, lifecycle, notification silence,
  params/context validation, URI/position rejection, empty lists, fixed
  failures, response bounds, and absence of resolve.
- Cover expression, module-member, record-member, type, variant-pattern,
  import-module, and keyword contexts; locals/parameters, shadowing,
  same/imported/Prelude/builtin sources, duplicate collapse, and visibility.
- Cover checked type/Effect/Capability filtering, invalid replacement probes,
  deterministic rank ties, prefix filtering, item cap/incomplete behavior,
  repeated requests, and insertion-order independence without AI.
- Cover UTF-8/16/32, Chinese identifiers, combining marks, emoji prefixes, BOM,
  CRLF, exact single-line replacement ranges, temporary isolation, stale
  snapshots, and absence of identities, paths, types, and metadata.
- Migrate exact initialize transcripts and run locked offline workspace tests,
  strict Clippy, CI, governance, LSP, support, status, RC0, traceability,
  formatting, and diff gates.

## Compatibility impact

- **Protocol:** adds Preview `ling.lsp.completion/0.1`; no predecessor.
- **Compiler query:** adds one bounded immutable checked completion catalog;
  existing DEC-0079/DEC-0080 observations remain unchanged.
- **Identity/schema:** resolver identities remain internal; no Semantic ID or
  serialized schema change.
- **Diagnostics/language/runtime:** no diagnostic allocation, Ling syntax or
  semantics, Typed Core evaluation, interpreter, runtime, bytecode, VM, ABI,
  package, filesystem/network, or Unicode 17.0.0 table change.

## Unresolved alternatives

Incomplete-source recovery was rejected for 0.1 because it would require an
accepted recovery and speculative-identity contract. Server-provided labels
that differ from inserted text, auto-imports, snippets, and lazy metadata were
rejected because they require additional edit and presentation lifecycles.
Completion resolve, documentation/signature rendering, AI ranking, generated
sources, cancellation, dynamic registration, and Stable lifecycle remain later
work.
