# RFC-0038: Resolver-backed LSP Navigation Preview / Resolver 驱动的 LSP 导航 Preview

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-23
> 目标版本：v0.1 Preview
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001; GAP-SEMANTIC-PROTOCOL-LIFECYCLE-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines Ling's bounded `textDocument/definition`,
`textDocument/declaration`, and `textDocument/typeDefinition` behavior. It
closes IDE-2303 by composing accepted resolver identity, original-byte source
spans, checked nominal types, immutable request snapshots, and negotiated
position projection without publishing resolver or Semantic IDs.

本 RFC 定义 Ling 有界的 `textDocument/definition`、
`textDocument/declaration` 与 `textDocument/typeDefinition` 行为。它组合已
接受的 resolver 身份、原始字节 span、已检查名义类型、不可变请求快照与协商位置
投影，同时不发布 resolver ID 或 Semantic ID，从而关闭 IDE-2303。

## Summary

`ling.lsp.navigation/0.1` selects one exact resolver reference in one current
snapshot. Definition and declaration return the exact user definition or local
binding identifier. Type-definition checks the complete workspace and returns
the direct nominal record/variant type, after peeling function result layers.
An absent source target, unsupported target class, or non-reference position
returns `null`; a successful location contains only exact URI and range.

## Normative changes

### 1. Capability validation and discovery

Initialize recognizes optional `capabilities.textDocument.definition`,
`declaration`, and `typeDefinition`. Each present member MUST be an object; an
optional `dynamicRegistration` member MUST be boolean. Unknown ordinary
members are ignored. Malformed known shapes reject initialize without state
mutation. Version 0.1 uses static registration regardless of the boolean.

Every successful initialize MUST advertise `definitionProvider: true`,
`declarationProvider: true`, `typeDefinitionProvider: true`, and:

```json
"lingNavigation": {
  "maxTargets": 1,
  "version": "ling.lsp.navigation/0.1"
}
```

The discovery object adds no custom request.

### 2. Requests, positions, and snapshots

All three methods accept a request object containing required string
`textDocument.uri` and required `position` with unsigned-u32 `line` and
`character`. Unknown ordinary fields are ignored. Wrong known shapes, unknown
documents, or positions that cannot map exactly through the negotiated
UTF-8/16/32 source map return InvalidParams `-32602`; positions are never
clamped. A notification with any navigation method does no work.

The server MUST be Ready and capture one immutable path-free request snapshot.
A non-temporary request resolves the complete non-temporary source set. A
temporary request resolves only that exact temporary source plus project
inputs, so it cannot navigate into another temporary or workspace source.

Before any success, including `null`, the server MUST recapture and compare the
complete snapshot. Any difference returns RequestFailed without partial output
or mutation. Version 0.1 exposes no progress, partial-result, or observable
later-cancellation channel in the synchronous host.

### 3. Resolver navigation index

The compiler builds a complete immutable index from validated resolver
references and exact HIR name spans. Each entry joins the reference's exact
original-byte identifier span to an optional definition/declaration location.
User definitions and bindings retain canonical logical source name plus exact
identifier span. Trait and implementation member locations MUST use their HIR
member-name spans; public names and locations MUST NOT contain implementation
ordinals. Prelude/builtin definitions with no source location retain no target.

Entries sort by logical source name, SourceId, start byte, end byte, and
internal resolver reference order. At most 16384 entries are allowed. Missing
reference spans, inconsistent member metadata, partial source/span locations,
missing bindings/modules, or overflow reject the complete index.

The request position selects entries start-inclusive and end-exclusive. The
smallest containing span wins, followed by canonical index order. Only
resolver references are selectable; declaration identifiers themselves return
`null` in 0.1.

### 4. Definition and declaration

`textDocument/definition` and `textDocument/declaration` use the same resolved
index and are identical in Seed because Seed has no distinct forward
declaration or alias-declaration hop. A user definition or binding target
returns its exact identifier location. A target with no source location—such
as Prelude or a builtin—returns `null` rather than a fabricated document.

The target logical source name MUST map uniquely to a document in the captured
snapshot. Workspace targets reuse their exact tracked `ling://workspace/` URI;
dependency targets reuse their exact read-only `ling://dependency/` URI. A
missing or duplicate mapping is an invariant failure. Host filesystem paths
and synthesized URI bytes are forbidden.

### 5. Type definition

`textDocument/typeDefinition` builds the index only after type and Effect
checking complete. It obtains the selected resolver target's checked type,
peels zero or more outer function result layers, and returns the exact user
definition location only when the remaining type is a nominal record or
variant. This makes constructor and function-result navigation deterministic.

Primitive types, unresolved variables, error sentinels, tuples, lists,
non-nominal values, Trait signatures without a checked target type, and nominal
types without a user source location return `null`. Version 0.1 does not search
inside tuple/list/function-parameter types because that could select multiple
or policy-dependent targets.

### 6. Result and failures

A location result is exactly:

```json
{
  "uri": "ling://workspace/src/Item.ling",
  "range": {
    "start": {"line": 2, "character": 5},
    "end": {"line": 2, "character": 9}
  }
}
```

The range is projected from the target's original UTF-8 identifier span using
the session encoding. A missing target returns exactly `null`. Version 0.1
never returns an array or `LocationLink` and includes no version, source kind,
mutability, identity, provenance, or edit data.

Resolution/type/Effect failure, invalid index join, missing/duplicate target
document mapping, source/projection failure, overflow, stale completion, or an
encoded response above RFC-0004's 1 MiB maximum returns RequestFailed `-32803`
with fixed bilingual message `导航不可用 / navigation unavailable`. Invalid
request data uses `导航参数无效 / invalid navigation parameters`. No compiler
diagnostic is allocated and no document/diagnostic/publication state changes.

An incompatible method mapping, target policy, span, type peeling, field,
cardinality, bound, snapshot, URI, error, or null behavior requires a new
protocol marker and migration evidence.

  silence, params, unknown URI, invalid positions, null, and fixed failures.
- Cover same-file and cross-workspace definition/declaration, local and
  parameter bindings, records, variants, constructors, Trait members,
  read-only dependency targets, and absent Prelude/builtin targets.

  function results plus null primitive/list/tuple/generic cases.

  bounds, checked failure/recovery, freshness, and absence of IDs, ordinals,
  paths, arrays, and `LocationLink` fields.
- Migrate exact initialize transcripts and run locked offline workspace tests,
  strict Clippy, CI, governance, LSP, support, status, RC0, traceability,
  formatting, and diff gates.

## Compatibility impact

- **Protocol:** adds Preview `ling.lsp.navigation/0.1`; no predecessor.
- **Compiler query:** adds bounded immutable resolved and checked navigation
  indexes using existing resolver/type observations; no identity becomes wire
  data.
- **Diagnostics/identity:** no code allocation or Semantic/resolver ID schema
  change.
- **Language/runtime/data:** no Ling syntax/semantics, Typed Core evaluation,
  interpreter, runtime, bytecode, VM, ABI, filesystem/network/cache, package
  format, or Unicode 17.0.0 behavior changes.

## Unresolved alternatives

Virtual generated/primitive documents were rejected for 0.1 because no
accepted content or URI lifecycle exists. Returning arrays or `LocationLink`
was rejected because resolver identity is unique and origin-selection metadata
would add no accepted behavior. Searching nested composite types was rejected
because target selection becomes ambiguous or policy-dependent.

Generated and primitive documents, alias hops, multiple targets, declaration
source selection, nested composite type search, implementation witnesses,
dynamic registration, progress, partial results, asynchronous cancellation,
caching promises, Workspace Edits, Semantic Transactions, and Stable lifecycle
remain future work.
