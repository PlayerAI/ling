# RFC-0039: Checked LSP References Preview / 已检查 LSP 引用 Preview

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-23
> 目标版本：v0.1 Preview
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001; GAP-SEMANTIC-PROTOCOL-LIFECYCLE-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines Ling's bounded `textDocument/references` behavior. It closes
IDE-2304 by composing checked resolver targets, exact declaration/reference
spans, immutable request snapshots, and negotiated position projection without
publishing resolver or Semantic IDs.

本 RFC 定义 Ling 有界的 `textDocument/references` 行为。它组合已检查的
resolver 目标、精确声明/引用 span、不可变请求快照与协商位置投影，同时不发布
resolver ID 或 Semantic ID，从而关闭 IDE-2304。

## Summary

`ling.lsp.references/0.1` selects either one exact source-backed declaration or
one exact resolved expression reference in a complete checked snapshot. It
returns every exact resolved expression reference to the same target and,
when requested, its declaration. Results are deterministic `Location` arrays;
an unselected position returns `[]`.

## Normative changes

### 1. Capability validation and discovery

Initialize recognizes optional `capabilities.textDocument.references`. When
present it MUST be an object; optional `dynamicRegistration` MUST be boolean.
Unknown ordinary members are ignored. A malformed known shape rejects
initialize without state mutation. Version 0.1 uses static registration.

Every successful initialize MUST advertise `referencesProvider: true` and:

```json
"lingReferences": {
  "emittedRelationKinds": ["read", "write", "call"],
  "maxLocations": 16384,
  "relationKinds": ["read", "write", "call", "type", "implementation"],
  "version": "ling.lsp.references/0.1"
}
```

The relation arrays are ordered compatibility facts. `relationKinds` fixes the
complete vocabulary; `emittedRelationKinds` fixes the subset for which Seed
has exact resolver-owned occurrences. A newly emitted kind requires a new
marker and migration evidence. The object adds no custom request.

### 2. Request, position, and snapshot

`textDocument/references` accepts a request object with required string
`textDocument.uri`, required unsigned-u32 `position.line` and `character`, and
required object `context` containing boolean `includeDeclaration`. Unknown
ordinary fields are ignored. Malformed known fields, unknown documents, or
positions that cannot map exactly through negotiated UTF-8/16/32 return
InvalidParams `-32602`; positions are never clamped. Notifications do no work.

The server MUST be Ready and capture one immutable path-free snapshot. A
non-temporary request checks the complete non-temporary source set. A temporary
request checks only that exact temporary source plus project inputs. Before
any success, including `[]`, the server MUST recapture and compare the complete
snapshot; a difference returns RequestFailed with no partial output or state
mutation.

### 3. Checked reference index and relation taxonomy

The compiler MUST complete resolution, type checking, and Effect checking
before building the immutable index. Every resolver reference is joined
atomically to its exact HIR identifier span and target identity. Every
source-backed target is joined to its exact declaration identifier span;
Trait and implementation members use exact member-name spans and MUST NOT
expose implementation ordinals.

Expression references are classified syntax-directed as follows:

1. `write`: the root identifier of an accepted assignment place;
2. `call`: the selected name or projection in application function position;
3. `read`: every other resolved expression name or projection.

The rules are mutually exclusive and precedence is `write`, then `call`, then
`read` at the exact occurrence. Nested projection receivers and call arguments
are independently `read`. `type` and `implementation` are reserved and MUST
NOT be inferred from spelling, type display, coherence candidates, or Semantic
Graph data; version 0.1 emits neither.

Targets group by existing internal definition or binding identity. Source-less
builtin/Prelude targets have no declaration but their resolved expression uses
remain queryable. Partial joins, inconsistent member metadata, missing
bindings/modules, or partial source/span pairs reject the entire index.

Selectors and result locations sort by canonical logical source name,
SourceId, start byte, end byte, relation, and internal target order. Selection
is start-inclusive/end-exclusive; the smallest containing span wins. At most
16384 declaration/reference selectors and at most 16384 locations per target
are allowed. The index is rebuilt from the immutable request compiler and
makes no persistence, cross-request reuse, or incremental-complexity promise.

### 4. Result projection

A declaration or reference occurrence selects its target group. When
`includeDeclaration` is true and the target has a source declaration, that
location is included exactly once. All resolved expression-reference
locations are included regardless of relation. When false, no declaration is
included. A position with no selectable target returns exactly `[]`.

Each result element contains only `uri` and `range`. The logical source MUST
map uniquely to an exact document in the captured snapshot. Workspace and
dependency targets reuse their registered URI bytes. Ranges project original
UTF-8 identifier spans using the negotiated encoding. Results sort by logical
source and original-byte range, not URI, registration order, hash-map order,
or host path. Duplicate locations are forbidden.

Version 0.1 exposes no relation, declaration flag, identity, version,
mutability, provenance, package, host path, or custom data field.

### 5. Failures and compatibility

Resolution/type/Effect failure, invalid or oversized index, missing/duplicate
target document mapping, invalid span/source projection, stale completion, or
an encoded response above RFC-0004's 1 MiB maximum returns RequestFailed
`-32803` with fixed bilingual message
`引用查询不可用 / references unavailable`. Invalid request data uses
`引用参数无效 / invalid references parameters`. No diagnostic is allocated and
no document, diagnostic, or publication state changes.

An incompatible capability, relation vocabulary/emission, precedence,
selection, declaration policy, ordering, cardinality, bound, snapshot, URI,
range, empty-result, or failure behavior requires a new marker and migration
evidence.

## Conformance plan

- Verify exact discovery, malformed capabilities, lifecycle, notification
  silence, params, unknown URI, invalid positions, empty results, and failures.
- Cover declaration/reference selection, include/exclude declaration, values,
  parameters, locals, constructors, Trait members, reads, writes, calls,
  source-less builtins, and complete checked failure.
- Cover workspace/dependency and temporary isolation, insertion-order and
  repeated-result determinism, UTF-8/16/32, Chinese, emoji, combining marks,
  BOM, CRLF, exact member spans, bounds, freshness, and URI reuse.
- Prove type/implementation are not inferred, result objects contain only
  URI/range, and resolver/Semantic IDs, ordinals, paths, relation metadata,
  custom data, and partial results do not enter the wire.
- Migrate exact initialize transcripts and run locked offline workspace tests,
  strict Clippy, CI, governance, LSP, support, status, RC0, traceability,
  formatting, and diff gates.

## Compatibility impact

- **Protocol:** adds Preview `ling.lsp.references/0.1`; no predecessor.
- **Compiler query:** adds a bounded checked declaration/reference grouping and
  exact syntax-directed expression relation classification; it reuses the
  request-scoped compiler and promises no persistent/incremental cache.
- **Diagnostics/identity:** no code allocation or Semantic/resolver ID schema
  change.
- **Language/runtime/data:** no Ling syntax/semantics, Typed Core evaluation,
  interpreter, runtime, bytecode, VM, ABI, package format, filesystem/network,
  or Unicode 17.0.0 behavior change.

## Unresolved alternatives

Type and implementation occurrences were not inferred from names because
those surfaces lack resolver-owned occurrence identities. Relation metadata
was not added to standard `Location` results. Persistent/incremental indexes
were not promised because request-scoped immutable rebuilds already provide
correct current-snapshot behavior without freezing a cache format.

Emitting type/implementation occurrences, generated documents, custom relation
results, partial/progress channels, asynchronous cancellation, persistent
caches, Workspace Edits, Semantic Transactions, and Stable lifecycle remain
future work requiring separate Accepted authority.
