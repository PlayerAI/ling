# RFC-0023: LSP Preview document overlay / LSP Preview 文档覆盖

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-22
> 目标版本：v0.1 Preview
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001 | GAP-SEMANTIC-PROTOCOL-LIFECYCLE-001
> 生命周期记录：`docs/governance/lifecycle.toml`

RFC-0023 is a bounded Preview authority for full-document editor overlays. It
extends the already accepted `ling lsp --stdio` lifecycle without claiming a
complete Language Server Protocol, a filesystem workspace resolver, or a
Semantic Transaction protocol.

## Summary

The overlay extension adds deterministic `textDocument/didOpen`,
`textDocument/didChange`, and `textDocument/didClose` handling to the existing
LSP server. It maps a restricted, path-free Ling URI to one session-local VFS
file, preserves exact UTF-8 text, and associates an editor version with each
open document. Only full-text changes are accepted. Version regressions,
duplicate versions, malformed URIs, closed documents, and dependency edits are
rejected before the VFS changes.

本 RFC 为已接受的 `ling lsp --stdio` 生命周期增加受限的 Preview 文档覆盖能力：
URI、版本、打开/关闭状态和完整文本变更均有确定性规则，同时不宣称完整 LSP、增量
编辑、诊断、Workspace Edit 或 Semantic Transaction 支持。

## Status and scope

- Current lifecycle state: `Accepted`
- Stable implementation basis: `yes` for the Experimental `ling.lsp.overlay/0.1`
  Preview extension only
- In scope:
  - the `ling.lsp.overlay/0.1` marker and three document synchronization methods;
  - restricted `ling://workspace/`, `ling://dependency/`, and
    `untitled://ling/` URI forms with path-free logical names;
  - immutable session-local VFS snapshots, overlay precedence, and monotonic
    document versions;
  - full-text `didChange`, deterministic read-only dependency rejection, and
    disk updates hidden by an open overlay;
  - request-form error responses, notification response suppression, and
    deterministic Rust integration views for tests and host adapters;
- Out of scope:
  - incremental/range edits, save notifications, diagnostics, semantic tokens,
    symbols, hover, completion, definitions, references, formatting, code
    actions, rename, cancellation, or compiler query scheduling;
  - host filesystem access, `file://` path resolution, workspace-root discovery,
    package discovery, network access, or URI percent-decoding;
  - Workspace Edits, Semantic Transactions, stale compiler-result handling,
    stable compatibility, or changes to the v0.0.1 Seed support matrix;
- Normative documents and clauses affected:
  - RFC-0004 lifecycle and transport boundary;
  - DEC-0002 source-position authority and DEC-0019 VFS/revision boundary;
  - DEC-0029 position projection for later range-edit work;
  - `docs/SEMANTICS.md`, `docs/LANGUAGE.md`, and `docs/ROADMAP-1.0.md` only
    for existing command, source-extension, and compatibility constraints.

## Normative changes

1. The extension marker is the ASCII string `ling.lsp.overlay/0.1`. It is a
   separate Experimental protocol record. A client MUST NOT infer support from
   the lifecycle marker alone; a server MAY advertise the marker in an
   optional `experimental.lingOverlay` capability field, and its absence does
   not change lifecycle behavior.
2. The methods `textDocument/didOpen`, `textDocument/didChange`, and
   `textDocument/didClose` MAY be sent as notifications or as requests during
   Preview. A valid notification receives no response. A valid request returns
   JSON `null`; invalid requests return JSON-RPC `-32602` or one of the stable
   overlay errors `-32004` through `-32006`. The request ID is preserved.
3. A document URI MUST be one of these exact, host-independent forms, with no
   query, fragment, percent escape, control character, or empty path:
   - `ling://workspace/<canonical-logical-name>`: writable workspace source;
   - `ling://dependency/<package>/<canonical-logical-name>`: readable and
     permanently read-only dependency source;
   - `untitled://ling/<canonical-logical-name>`: writable temporary source.
   The logical name MUST be canonical under DEC-0019's VFS rules and MUST end
   in `.ling`. The URI string is retained exactly as the editor identity and
   is never converted to a host path.
4. `didOpen.params` MUST be an object containing `textDocument` with `uri`, a
   non-negative signed integer `version`, and a UTF-8 `text` string no larger
   than 1 MiB. A URI may be opened only once at a time. Reopening a closed URI
   MUST use a version strictly greater than its last accepted version. The
   initial text becomes the visible overlay and the session-local VFS snapshot
   is immutable after publication.
5. `didChange.params` MUST contain `textDocument.uri`, a strictly greater
   non-negative `version`, and exactly one `contentChanges` entry containing
   only full replacement `text`. A `range` or `rangeLength` is invalid in this
   revision. The server MUST validate URI, state, writability, text size, and
   version before calling the VFS; failure MUST leave bytes, version, and
   revision unchanged.
6. `didClose.params` MUST contain an open `textDocument.uri`. Closing a
   workspace or dependency document removes only its overlay and reveals the
   latest disk layer. Closing an untitled document removes its temporary VFS
   file. A second close is rejected without changing any other document.
7. Dependency documents MAY be opened for read-only analysis, but
   `didChange` MUST fail with `-32005` and MUST NOT mutate the VFS. The host
   integration MAY publish a disk snapshot through the Rust adapter; while a
   workspace overlay is open, disk changes are retained but hidden until
   `didClose`.
8. Error meanings are stable and bilingual: `-32004` is a stale or
   non-monotonic document version, `-32005` is a read-only dependency edit,
   and `-32006` is an invalid or unsupported document URI. These are
   JSON-RPC protocol errors, not Ling `L-<DOMAIN>-<NUMBER>` compiler
   diagnostics, and they do not allocate a diagnostic code.
9. Overlay data is observational input to future compiler queries. It MUST
   preserve original UTF-8 bytes and VFS revisions, MUST NOT alter Semantic
   IDs, canonical program identity, bytecode, interpreter/VM behavior, Unicode
   tables, or the lifecycle protocol's existing fields, and MUST NOT expose
   `SourceId`, host paths, allocation addresses, or hash-map order as wire
   semantics.

## Conformance plan

- Add direct server tests for workspace, dependency, and untitled URI mapping,
  open/change/close transitions, version monotonicity, duplicate/reopen rules,
  and request versus notification response behavior.
- Verify full replacement only, malformed text/URI/params, unknown and closed
  documents, read-only dependency rejection, 1 MiB limits, and no VFS mutation
  after rejected changes.
- Verify disk updates are hidden by an open overlay and become visible after
  close; verify untitled files are removed; verify sorted document views and
  repeated-run determinism.
- Add framed lifecycle-plus-overlay transcripts and a protocol README. Keep
  range-edit, diagnostics, query, stale-result, Workspace Edit, and transaction
  fixtures deferred to their governing tasks.

## Compatibility impact

- Source and language: no syntax, type, effect, runtime, source-span, or
  Unicode 17.0.0 behavior changes.
- CLI and transport: the existing `ling lsp --stdio` command and framing remain
  unchanged; only the explicitly versioned Preview methods are added.
- Diagnostics: no registry allocation; protocol errors remain bilingual and
  separate from compiler diagnostics.
- Semantic Graph, Semantic IDs, bytecode, VM, package identity, ABI, and cache
  formats: unchanged.
- Lifecycle: the overlay marker is Experimental and current-writer-only;
  incompatible evolution requires a new protocol version and migration
  evidence.

## Unresolved alternatives

- `file://` URI and workspace-root mapping are deferred because they require a
  host path and package-root policy.
- Incremental range edits may be added only after LSP-2104 accepts encoding,
  bounds, and transaction semantics; they MUST NOT be inferred from full-sync
  `didChange`.
- Diagnostics, compiler snapshots, stale-result rejection, Workspace Edits,
  and Semantic Transactions remain open under the registered governance gaps.
