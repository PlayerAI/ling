# CLI-1703 Authority Audit: Project initialization

## Outcome

`CLI-1703` remains the parent planning row, while Accepted DEC-0038 closes the
bounded `CLI-1703-INIT` child. The child defines and implements an offline
`ling init` scaffold using the accepted RFC-0002 manifest and lock protocols.
The execution-plan references to `zero init`, a manifest template field, and
optional `.zed/tasks.json` are not used: the public names remain `ling` and
`.ling`, the template version is report metadata, and no unregistered editor
schema is generated.

The implementation creates a missing destination atomically with
`ling.toml`, `src/Main.ling`, `.gitignore`, and `ling.lock`; it rejects existing
destinations and leaves no staging residue after failure. The broader project
CLI surface remains outside this child.

## Normative traceability

- Accepted RFC-0002 defines the library-only manifest, package graph, module
  visibility, lock, and content/graph identity protocols. It does not define a
  CLI initializer, template files, generated metadata, or project-root
  selection.
- Accepted DEC-0003 fixes the current hand-written CLI parser and rejects
  unimplemented commands from help; it does not authorize `init`.
- Accepted DEC-0007 fixes source/module file boundaries and package graph
  semantics, not a project scaffold or template version field.
- Accepted DEC-0038 defines the exact `ling init` destination, options,
  generated bytes, lock update, report, diagnostics, and failure-atomicity
  boundary implemented by `CLI-1703-INIT`.
- `GAP-PROJECT-CLI-INTERFACE-001` keeps manifest-path precedence, project mode,
  lock/offline selection, and project command behavior open until an accepted
  CLI decision exists.
- `docs/SEMANTICS.md` and `docs/LANGUAGE.md` require deterministic logical
  names, path-free identities, source-span preservation, and no ambient
  network behavior. They do not define generated files or editor task
  metadata.
- Lower-authority execution material uses `zero`; the accepted public command
  and source names remain `ling` and `.ling`.

## Current interface evidence

The current repository confirms the bounded boundary:

- `crates/ling-cli/src/main.rs` and `crates/ling-cli/src/init.rs` implement the
  accepted `init` branch and keep all later commands out of the catalog.
- `ling-project` can read and validate explicit manifests and locks, but it has
  no template writer; `init` composes its existing reader, discovery, and lock
  update APIs in a private staging directory.
- `PROTO-CLI-INIT` and `ling.init/0.1` now freeze the generated file list and
  success report. No `.zed` or other editor protocol is claimed.

## Remaining authority boundary

DEC-0038 supplies the authority required for the child. The following remain
intentionally outside it and require later accepted decisions:

1. overwrite/force or existing-directory reuse;
2. current-working-directory defaulting, template selection, and custom
   package versions;
3. `.zed/tasks.json`, workspace manifests, project test/build behavior, and
   any editor-file schema;
4. parent/sibling/registry dependencies and ambient project discovery.

## Intentionally deferred

`CLI-1703` as a broader planning row remains blocked by the unresolved project
CLI interface. The completed child is offline, failure-atomic, deterministic,
and uses the accepted `ling`/`.ling` names without introducing an unregistered
editor file format.
