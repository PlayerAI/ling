# CLI-1703 Authority Audit: Project initialization

## Outcome

CLI-1703 now has sufficient Accepted authority and a complete implementation.
DEC-0255 composes the already completed DEC-0038 initializer as the full current
task. The command creates the RFC-0002 four-file scaffold offline,
deterministically, and failure-atomically.

The lower-authority plan's proposed manifest template field conflicts with
RFC-0002 manifest-v1 and is not implemented. Its `.zed/tasks.json` item is
optional and remains omitted because no Accepted editor-task schema or binary
acquisition contract owns those bytes.

## Normative traceability

- RFC-0002 defines manifest-v1, `ling.lock/1`, package identity, source roots,
  entry modules, and graph validation.
- DEC-0007 fixes source/module file boundaries.
- DEC-0038 defines exact `ling init` operands, metadata, generated bytes,
  staging, validation, publication, report, diagnostics, and exits.
- DEC-0253 places `init` in the single current parser/dispatcher.
- DEC-0254 governs its human/JSON, language, color, quiet, and verbose output.
- DEC-0255 accepts that composed surface as complete CLI-1703 and records why
  stale template/editor assumptions do not authorize additional output.

## Implementation evidence

`crates/ling-cli/src/init.rs` derives and validates metadata, writes exact files
under a private sibling staging directory, invokes the real manifest parser,
module discovery, and lock writer, then publishes by one rename. Its drop guard
removes an unpublished private staging directory.

Parser, initializer, integration, schema, protocol, help, and output-policy
tests cover success and invalid inputs, generated bytes, canonical lock, file
order, JSON, existing-target nonmutation, staging cleanup, offline behavior,
quiet output, and diagnostic visibility.

## Compatibility and gap disposition

`ling.init/0.1`, manifest-v1, and `ling.lock/1` remain unchanged. No diagnostic
allocation, Semantic ID, source span, language semantic, runtime, artifact,
bytecode, VM, ABI, or Unicode 17.0.0 behavior changes.

The project CLI gap has Accepted coverage for the current explicit project
forms through RFC-0024/RFC-0025 and does not require initializer overwrite,
workspace, editor, registry, or discovery features. Those remain separately
deferred rather than blockers for the current initialization command.
