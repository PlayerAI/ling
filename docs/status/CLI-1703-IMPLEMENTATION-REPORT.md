# CLI-1703 implementation report

## Result

CLI-1703 is complete under RFC-0002, DEC-0038, and DEC-0255. The current
`ling init` command creates one deterministic, offline, failure-atomic project
scaffold and exposes the Preview `ling.init/0.1` success report.

## Implemented surface

- exactly one missing destination directory;
- derived or explicit RFC-0002 package name and optional validated display name;
- exact LF-terminated `.gitignore`, `ling.toml`, `src/Main.ling`, and canonical
  `ling.lock` bytes;
- validation through the real manifest parser, module discovery, and locked
  package-graph writer before publication;
- private sibling staging followed by one rename, with cleanup on failure;
- bilingual human output plus JSON, language, color, quiet, and verbose behavior
  through DEC-0254; and
- stable invalid-usage, diagnostic, host-failure, and success exit classes.

## Plan-drift disposition

RFC-0002 does not allow the execution plan's proposed template field in
manifest-v1, so template version `1` remains report metadata. The optional
`.zed/tasks.json` is omitted because no Accepted editor-task schema or binary
acquisition contract exists. Stale `zero` and `.zero` spellings remain rejected.

## Evidence

`crates/ling-cli/src/init.rs`, parser tests, `crates/ling-cli/tests/init.rs`,
`crates/ling-cli/tests/output_policy.rs`, the `ling.init/0.1` schema corpus, and
the protocol fixture README cover generated bytes, reports, errors, atomicity,
determinism, output composition, and non-overwrite behavior. Repository-wide
evidence is bound to the implementation commit after all gates pass.

## Compatibility and deferred work

No generated byte, JSON field, diagnostic code, exit, Semantic ID, source span,
runtime behavior, package identity, bytecode, VM, ABI, or Unicode 17.0.0 data is
changed. Force/reuse modes, templates, custom versions, workspaces,
dependencies, editor files, ambient discovery, and Stable scaffold compatibility
remain intentionally deferred.
