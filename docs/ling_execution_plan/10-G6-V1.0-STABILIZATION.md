# G6 / Ling 1.0 稳定化与发布执行计划

> 目标版本：`v1.0`  
> 前置门禁：G0～G5 各自出口标准闭合  
> 阶段原则：默认不再加入新语义；宁可收缩 Stable 支持面，也不以未验证实现换取功能数量

## 1. 1.0 的完成定义

Ling 1.0 不是“远景功能全部实现”，而是：

- Stable 核心具有 Accepted RFC、规范、实现、conformance 和发布证据；
- Explore、Native、Critical 的支持范围和拒绝行为明确；
- CLI、Diagnostic、Semantic Graph、Audit、Transaction、包/锁、Replay、Evidence 等协议有兼容策略；
- 支持平台可离线、锁定、可重复构建；
- Interpreter、VM、Native、设备路径在各自承诺范围完成差分验证；
- Zed/LSP/Formatter/CLI 形成可稳定使用的工程闭环；
- Preview/Experimental 不会伪装为 Stable。

## 2. 稳定化冻结规则

进入 G6 后：

1. 只允许修复正确性、安全、兼容、诊断、性能回归和文档缺口；
2. 新语法/Effect/ABI/Schema 字段默认推迟到 1.x/2.0 RFC；
3. 若某能力证据不足，降级为 Preview/Experimental 或从默认构建移除；
4. 所有 protocol writer 冻结前先具备 reader/migration/golden corpus；
5. RC 期间 Semantic ID/Canonical Bytes 不允许未经迁移的变化；
6. release branch 只接受带回归测试和风险说明的变更。

# 3. STAB：冻结 Stable 支持面

## STAB-6101：逐项支持矩阵审计

为每一项候选 Stable 能力填写：

| 字段 | 内容 |
| --- | --- |
| Feature/Profile/Target | 精确名称 |
| RFC/规范 | Accepted 链接 |
| Parser/Checker/Core | 实现位置 |
| Interpreter/VM/Native/Device | 支持情况 |
| Conformance | 正例/反例/差分 |
| Diagnostics | 稳定错误码 |
| LSP/Zed | 支持或明确无 |
| Compatibility | 1.x 承诺 |
| Known limitations | 公开 |
| Evidence | CI/release artifact |

缺任何关键字段不得标记 Stable。

## STAB-6102：删除虚假入口

搜索并处理：

- 空实现/`todo!()`；
- 返回成功但未执行语义的占位 API；
- 文档中未实现命令；
- Zed completion 中不可用关键字；
- 未支持 backend/profile；
- “未来会支持”的默认配置；
- 未经 RFC 的语法 alias。

## STAB-6103：Feature State 元数据

所有公开能力机器可读标记：

```text
Experimental
Preview
Stable
Deprecated
Removed
```

状态出现在：

- `zero features --json`；
- build manifest；
- LSP hover/completion；
- 文档；
- package metadata；
- Zed extension 兼容表。

## STD-6302：删除过度便利 API

重点审查：

- 隐式 I/O/Clock/Random；
- 无界 collection；
- 默认全局 runtime；
- 隐式网络重试；

- 未说明 ownership 的 FFI helper；
- 无复杂度承诺的核心操作。

不成熟 API 保留在 Preview 包，不进入 `core`。

## STD-6303：Unicode 与中文编程稳定性

固定并验证：

- Unicode 17.0.0 数据表；
- XID_Start/XID_Continue；
- NFC；
- confusable/bidi/hidden character diagnostics；
- Text/Scalar/Byte 区分；
- 中文 package/module/symbol；
- formatter、LSP、Zed、CLI、Windows 路径；
- 升级 Unicode 的 RFC 流程。

## PKG-6402：Hermetic Build

禁止任意依赖 build script 执行 shell。允许的构建步骤必须：

- 声明输入/输出；
- 显式 Capability；
- sandbox；
- deterministic；
- hashed；
- 可离线重放；
- 不访问未声明环境变量/网络。

## PKG-6403：Registry 最小实现或推迟策略

1.0 可以选择：

- 发布最小只读/上传 registry；或
- 只稳定包/锁/本地源协议，registry 保持 Preview。

不能因为中心服务尚未成熟而阻止锁定项目离线构建。

## PKG-6404：供应链攻击测试

- dependency confusion；

- Unicode confusable package；
- malicious manifest；
- archive traversal；
- decompression bomb；
- signature/key mismatch；
- yanked package；
- compromised cache；
- build capability escalation。

# 12. v1.0 最终 Go/No-Go 清单

- [ ] Stable 矩阵每项都有 Accepted RFC、规范和可执行 conformance；
- [ ] 规范→实现→测试→发布证据可双向追踪；
- [ ] Tier 1 平台运行同一稳定 Core conformance；
- [ ] Interpreter/VM/Native/device 在承诺范围完成差分验证；
- [ ] Explore/Native/Critical 的允许、拒绝与 fallback 行为完整测试；
- [ ] Diagnostic/Graph/Audit/Transaction/package/replay/evidence 协议完成版本与损坏输入测试；
- [ ] 公共诊断中英双语、错误码注册完整、UTF-8 byte span 正确；
- [ ] Unicode 版本固定或已按 RFC 迁移；
- [ ] 锁定依赖后可离线构建和测试；
- [ ] package/build 不允许任意 shell/未声明网络；
- [ ] unsafe/TCB/FFI/依赖/许可证完成审计；
- [ ] 所有已知 P0/P1 正确性、安全、数据损坏问题关闭；
- [ ] Preview/Experimental 不在文档、CLI、LSP、Zed 中冒充 Stable；
- [ ] 1.x 兼容、弃用、支持和安全响应政策发布；
- [ ] release tag、artifact、manifest、evidence 身份一致；
- [ ] 独立验证完成并签署 Go；
- [ ] 若任一关键项不满足，选择延后或收缩支持面，而非降低门禁。
