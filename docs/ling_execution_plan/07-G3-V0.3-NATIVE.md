# G3 / Ling v0.3 Native 详细执行计划

> 目标版本：`v0.3 Native`  
> 前置门禁：G1 工具链稳定；G2 的 Effect、取消与资源清理语义冻结  
> 本阶段结果：Value / Managed / Resource、Ownership / Region、Native IR、首个 Native backend 与 Typed FFI 形成一致执行路径  
> 非目标：一次支持全部 LLVM target、在首版实现最复杂 lifetime 语法、以 Rust 内部布局替代 Ling 规范

## 1. 阶段原则

1. Ling 的内存语义由 Ling 规范决定，不由 Rust 所有权、`repr(Rust)`、某个 GC 或某个 backend 偶然决定；
2. 大多数普通值代码保持 ML/F# 式简洁，只有资源边界和无法安全推导的公共生命周期需要显式语法；
3. 自动 Borrow 可以省略书写，但 Audit Source 和 Checked Core 必须展开；
4. Resource 在正常返回、Error、Fault、取消和 Actor 终止路径上都必须有确定清理；
5. Managed 并不等于“Native 禁止 GC”，而是明确的 Managed island；Critical Profile 另行禁止通用 GC；
6. Native backend 只 lower 已验证的 Core，不负责补做 ownership/type/effect 检查；
7. FFI 是能力边界和 TCB 边界，禁止普通源码随意进入 `unsafe`；
8. Interpreter、VM 与 Native 的差异必须由规范列举，不能用 snapshot 模糊处理。

## 2. 规范门禁

| RFC | 主要决定 | 阻断 |
| --- | --- | --- |
| RFC-N301 Value/Managed/Resource | 三类身份、可复制性、分配与 Drop | MEM-* |
| RFC-N302 Ownership/Borrow/Region | move、borrow、alias、region、escape、public lifetime | OWN-* |
| RFC-N303 Managed Runtime | roots、cycles、finalization、pinning、OOM、profile | GC-* |
| RFC-N304 Native ABI | layout、calling convention、Fault、threading、unwind | NIR-*、FFI-* |
| RFC-N305 Target Primitive/FFI | typed boundary、capability、audit、TCB、generated shim | FFI-* |
| RFC-N306 Native Backend Support | baseline backend、target tier、reproducibility | BACK-* |

## 3. 目标编译链

```text
Checked Typed Core
    ↓
Memory Classification Pass
    ↓
Ownership / Borrow / Region Check
    ↓
Explicit Drop + Cleanup Core
    ↓
Backend-neutral Native IR
    ├── baseline native backend
    └── future optimized backend
    ↓
object / executable / library
```

新增 crate 建议：

```text
crates/
├── ling-memory-model
├── ling-ownership
├── ling-region
├── ling-drop-lowering
├── ling-managed-runtime
├── ling-native-ir
├── ling-native-backend
├── ling-abi
├── ling-ffi
├── ling-target-package
└── ling-native-test
```

# 4. MEM：Value / Managed / Resource

## MEM-3101：类型分类模型

**规模：M；依赖：RFC-N301。**

每个类型在 Checked Core 中具有明确 memory kind：

```text
Value
Managed
Resource
```

需要定义：

- primitive、record、tuple、ADT、array、closure 的默认/推导 kind；
- 泛型 kind constraint；
- kind composition；
- copy/move 能力；
- equality/hash/serialization 是否受 kind 影响；
- Semantic Graph 与 Audit Source 表示。

## MEM-3102：Value 布局与 Copy/Move

实现：

- 小值 inline；
- 用户不可观察的寄存器/栈优化；
- `Copy` 不等于 Rust `Copy`，需由 Ling Trait/规则决定；
- 隐式复制只发生在规范允许的类型；
- 大值 move/copy 性能提示不能改变语义；
- overflow、padding、endianness 只在 ABI/序列化边界显式。

## MEM-3103：Resource 定义与 Drop 契约

Resource 至少包含：

- 唯一 ownership；
- move 后不可使用；
- 显式或推导 drop；
- drop 的 Effect/Fault 规则；
- cancellation-safe cleanup；
- FFI transfer mode；
- 禁止 GC finalizer 替代确定清理。

## MEM-3104：Managed 类型和 Island 边界

定义：

- Managed reference；
- Managed graph；
- 从 Value/Resource 指向 Managed 的规则；
- Managed 指向 Resource 的禁止或封装规则；
- island root；
- 跨线程/Actor/FFI 规则；
- pinning 与 borrowed view。

# 5. OWN：Ownership、Borrow 与 Region

## OWN-3201：Place 与 Move Analysis

**规模：L，拆分。**

在 Typed Core 中统一表示：

```text
local place
field place
index place
projection
move
copy
borrow
borrow_mut
```

实现 dataflow：

- initialized / moved / partially moved；
- 分支 join；
- loop fixed point；
- match destructuring；
- closure capture；
- task/actor boundary；
- 诊断展示第一次 move 与非法使用位置。

## OWN-3202：Borrow Exclusivity

规则：

```text
任意数量 immutable borrow
或一个 mutable borrow
但不能同时存在冲突 alias
```

具体兼容规则由 RFC 决定。实现：

- place overlap；
- field splitting；
- index alias 的保守处理；
- call-site automatic borrow；
- temporary lifetime；
- mutable place requirement；
- 容器迭代期间 mutation 冲突。

## OWN-3203：Region Inference

目标不是让用户到处写 lifetime，而是推导：

- lexical/non-lexical region；
- returned borrow；
- closure capture；
- public API region parameter；
- region outlives constraints；
- escape from local/actor turn/task scope；
- suspension point crossing。

无法稳定推导的 public lifetime 需显式并进入 API。

## OWN-3204：跨 `await` / Actor Turn 的 Borrow

高风险检查：

- 指向 stack/turn-local state 的 borrow 默认不得跨 suspension；
- 允许的 pinned/owned state machine field 必须显式 lower；
- Actor state borrow 不得在释放 turn 后存活；
- Remote/消息边界不得携带普通 borrow；
- 诊断给出“复制值、缩短 borrow、move ownership、拆分 state”等建议。

## OWN-3205：Drop 顺序 Lowering

把隐式 Drop 显式插入 Cleanup Core：

- reverse declaration order 或 RFC 规定顺序；
- 分支/早退；
- `?`/Error；
- Fault；
- cancellation；
- partial initialization；
- panic/unwind 不作为 Ling 语言机制；
- drop 失败规则明确。

## OWN-3206：Ownership 诊断与修复

错误至少包含：

```text
resource origin
move/borrow start
conflicting use
region boundary
why conflict persists
ranked fixes
```

JSON diagnostics 需给 LSP code action 结构化数据，而不是让编辑器解析人类字符串。

## OWN-3207：负向 corpus 与 property tests

覆盖：

- use-after-move；
- double drop；
- mutable alias；
- partial move；
- match/loop/closure；
- cancellation；
- task/actor；
- FFI transfer；
- region escape；
- automatic borrow 误判。

# 6. GC：Managed Runtime

## GC-3301：最小对象模型

**依赖：RFC-N303。**

规范化：

- object header 是否可见：不可见；
- type metadata；
- root interface；
- write barrier interface；
- weak reference 是否首版支持；
- finalization 是否禁止或受限；
- OOM 作为 Fault；
- pointer identity 的可观察规则。

## GC-3302：第一版 Collector

选择一个最容易验证和集成的实现，不以理论最优为先。实现选择不得进入语言语义。

必须提供：

- stop-the-world 或其他 pause 行为文档；
- root registration；
- cycle handling；
- safe point；
- Actor/task interaction；
- memory limit；
- metrics；
- stress/fuzz。

## GC-3303：Managed 与 Native/FFI 边界

- pin/unpin；
- handle table；
- no raw pointer escape；
- callback root；
- thread attachment；
- foreign ownership；
- GC during FFI call；
- deterministic cleanup 与 finalizer 区分。

## GC-3304：Profile 检查

- Explore：允许 Managed；
- Native：允许声明的 Managed island；
- Critical：拒绝通用 Managed/GC，除非未来 RFC 定义受限区域；
- `no_gc` function/module 的静态检查与运行时断言。

# 7. NIR：Backend-neutral Native IR

## NIR-3401：Native IR 设计

**规模：L；依赖：RFC-N304。**

IR 必须表达：

- typed SSA/control flow；
- value/resource representation；
- explicit borrow provenance 或检查后别名事实；
- explicit drop/cleanup；
- function ABI；
- Fault edge；
- source mapping；
- debug variable location；
- Effect boundary；
- deterministic serialization。

## NIR-3402：Core → Native IR Lowering

按纵向切片逐步支持：

1. integer/bool/function call；
2. record/tuple；
3. ADT/match；
4. mutable place；
5. closure；
6. Effect operation；
7. Resource/drop；
8. Managed handle；
9. task/actor runtime ABI。

每一步都有 interpreter/VM/native differential test。

## NIR-3403：IR Verifier

独立验证：

- block/phi/SSA；
- type consistency；
- resource ownership；
- cleanup coverage；
- legal ABI；
- source ids；
- no invalid reference；
- no backend-specific unresolved op。

无效 IR 必须安全拒绝，不触发 host UB。

# 8. BACK：首个 Native Backend

## BACK-3501：Backend 选择 Spike

在 RFC-N306 前做隔离比较：

- Cranelift；
- LLVM；
- 自有最小 C/wasm 过渡后端（如需要）；
- build time、debug info、target coverage、JIT/AOT、license、可重复构建。

Spike 只输出数据和建议，不形成 public API。

## BACK-3502：Baseline Codegen

只接一个 backend，覆盖稳定 Core：

- target machine；
- function/data emission；
- relocations；
- runtime linking；
- object/executable；
- debug/source map；
- deterministic metadata；
- explicit unsupported diagnostic。

## BACK-3503：Runtime ABI

冻结第一版内部 ABI：

- value passing；
- ADT tag；
- closure env；
- Fault/result；
- GC handle；
- Resource drop；
- task/actor calls；
- string/text ABI。

内部 ABI 可版本化，不自动成为跨版本稳定 public ABI。

## BACK-3504：基础优化与验证

首批只做：

- constant folding；
- dead block elimination；
- trivial inlining；
- bounds-check elimination（有证明时）；
- copy propagation；
- tail call 仅在语义明确时。

每个 pass 需要 pre/post verifier 和 differential/property tests。

## BACK-3505：Reproducible Native Build

记录并控制：

- toolchain；
- target；
- linker；
- environment；
- absolute path；
- timestamp；
- build id；
- dependency lock；
- codegen options。

相同声明输入应生成 byte-identical 产物，或 manifest 明确列出不可消除差异。

# 9. FFI：Typed FFI 与 Target Primitive Package

## FFI-3601：FFI 声明模型

**依赖：RFC-N305。**

每个声明必须包含：

```text
ABI
symbol
argument/result layout
ownership transfer
borrow duration
threading
reentrancy
Error/Fault mapping
Capability
profile availability
target constraints
```

## FFI-3602：C ABI 最小互操作

先支持有限、安全、可测试的 C ABI：

- scalar；
- fixed-layout record；
- pointer + length span；
- callback；
- opaque handle；
- explicit allocator pair；
- error code mapping。

不支持的 variadic、bitfield、platform-dependent layout 应编译期拒绝。

## FFI-3603：Shim Generator

自动生成：

- layout assertions；
- bounds/null checks；
- ownership conversion；
- string encoding；
- callback trampoline；
- Fault mapping；
- capability check；
- audit metadata。

生成物有 provenance，并参与构建 hash。

## FFI-3604：Target Primitive Package

目录建议：

```text
targets/<target>/
├── package.toml
├── primitives.lingabi
├── implementation/
├── proofs-or-tests/
├── capabilities.toml
└── TCB.md
```

普通 Ling 包无法声明任意 primitive；只有受信 target package 经过显式构建配置进入 TCB。

## FFI-3605：FFI fuzz/sanitizer 套件

覆盖：

- malformed ABI metadata；
- wrong layout；
- callback after owner drop；
- double free；
- pinning；
- concurrent callback；
- exception/unwind crossing；
- hostile C library return；
- capability denial。

# 10. 多执行引擎一致性

## DIFF-3701：三方 Harness

统一执行同一 conformance：

```text
Interpreter
VM
Native
```

比较：

- return value；
- stdout/event；
- Fault category/code；
- Resource cleanup trace；
- deterministic replay；
- declared floating-point tolerance；
- Semantic ID/source mapping。

## DIFF-3702：已允许差异登记表

只允许规范明示差异，例如：

- 性能；
- 内存地址；
- GC timing（不可观察时）；
- BestEffort 调度；
- target-specific NaN payload（如规范允许）。

所有差异必须在机器可读 registry 中，不得散落 `if backend ==` 的测试豁免。

# 11. LSP、Zed 与调试器工作

本阶段增加：

- move/borrow/region 错误的 related information；
- 自动 borrow 的 Audit 展开和 hover；
- Resource/Managed/Value semantic token modifiers；
- “缩短 borrow”“复制字段”“move ownership”等 code action；
- Native build/run Zed tasks；
- source map；
- `zero dap` Preview：breakpoint、stack、locals、step、Fault、actor/task inspection。

DAP 必须消费 Native debug metadata 或 VM debug protocol，不得在 Zed 插件中重新解释程序。

# 13. v0.3 出口门禁

- [ ] Value/Managed/Resource 的规范、Checker 与 Graph 表示一致；
- [ ] move/use-after-move、borrow exclusivity、region escape 和 drop order 全部有稳定诊断；
- [ ] Resource 在返回、Error、Fault、取消和 Actor 终止路径有清理证据；
- [ ] Managed runtime 的 root、OOM、pinning、FFI 和 Profile 边界明确；
- [ ] Native IR verifier 可独立拒绝非法 IR；
- [ ] 至少一个 Native backend 覆盖稳定语言核心；
- [ ] build manifest 记录全部非确定输入，承诺范围内可重复；
- [ ] Typed FFI 不允许未声明 ownership/Capability 的边界；
- [ ] unsafe/TCB 只存在于列明的 Target Primitive Package；
- [ ] Interpreter、VM、Native 通过支持范围内差分测试；
- [ ] sanitizer、fuzz、跨目标和 hostile FFI 测试无未分类内存安全问题；
- [ ] LSP/Zed 能正确显示中文标识符中的 ownership 诊断与 UTF-16 position；
- [ ] v0.3 追踪矩阵、支持矩阵、ABI/Schema version 更新。
