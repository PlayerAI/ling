# G1：Ling v0.1 Living 详细执行计划

> 目标：把 Seed 从单文件解释器扩展为可承载多模块工程、VM、增量检查、Formatter、LSP、Zed 和基础 Trait 的完整开发闭环。  
> 核心约束：解释器、VM、LSP、Formatter 与 Zed 不得形成不同语言方言。

## 1. G1 的完成形态

用户可以在一个锁定依赖的项目中执行：

```bash
zero init
zero check
zero run
zero test
zero fmt --check
zero semantic
zero audit
zero build --profile explore
zero lsp --stdio
```

Zed 中能够：

- 高亮 `.ling`；
- 显示 parser/type/effect/capability 错误；
- hover、跳转定义、references、rename；
- completion、code action、format；
- 运行文件/项目/测试；
- 对中文标识符和 emoji 前缀保持正确位置。

## 2. 规范门禁

开始对应实现前必须接受：

- project/package/module/lock；
- bytecode + verifier；
- Trait coherence/orphan/lowering；
- incremental key/invalidation；
- Formatter 保留边界；
- LSP fields 与 Semantic Transaction 版本；
- CLI 子命令和退出码变化。

没有门禁的任务只能做隔离 spike，不得合入默认路径。

# 3. Workstream A：Project 与 Module Graph

## PRJ-1101：最小项目 manifest

**规模：M。**

定义建议文件名（需 decision 确认）：`ling.toml`。

最小字段：

```toml
[package]
name = "hello"
version = "0.1.0"
language = "0.1"

[source]
roots = ["src"]
entry = "Main"

[dependencies]
# 初期只允许 path/content-locked dependency
```

实施：

- parser 与结构化 manifest diagnostics；
- 不允许任意 shell build script；
- logical package identity 与 display name 分离；
- profile/target 为显式输入；
- 未知 Stable 字段行为由 Schema policy 决定。

测试：valid/invalid manifest、中文包 display name、路径穿越、重复字段、CRLF。

## PRJ-1102：Module discovery

- 从 source roots 发现 `.ling`；
- 定义文件路径↔module name 的规范映射；
- 处理显式 `module` 声明；
- 同一 module 多文件规则若未决定则拒绝；
- 诊断重复 module、大小写冲突和不可移植路径。

输出确定性 `ModuleGraph`，节点和边排序稳定。

## PRJ-1103：Import 与 visibility

- 在 HIR/resolve 层实现跨模块 import；
- 区分 public/private；
- 输出 unresolved/ambiguous/private access/cycle root-cause diagnostics；
- Semantic Graph 记录 package/module/definition identity；
- LSP definition 可跨文件。

## PRJ-1104：Dependency graph

初期范围：本地 path dependency + 内容 identity。

- 禁止 registry 自动联网；
- cycle、同名不同 identity、版本冲突；
- dependency source 只读；
- build graph canonical sorting；
- manifest 和 lock 中不记录主机绝对路径为 identity。

## PRJ-1105：Lock file

- 生成 `ling.lock`（名称需 decision）；
- byte-identical writer；
- `--locked`、`--offline`；
- lock mismatch 稳定错误；
- corruption tests；
- package service 不可用时已缓存项目仍可 build。

## PRJ-1106：Project fixtures

建立：

```text
tests/projects/single-package
tests/projects/multi-module
tests/projects/path-dependency
tests/projects/cycle
tests/projects/visibility
tests/projects/offline-lock
tests/projects/unicode-names
```

每个 fixture 有 expected diagnostics/graph/lock。

## PRJ-1107：Project API 与 CLI 接入

- `CompilerHost::load_workspace`；
- `zero check/run/test/build` 统一 workspace selection；
- `--manifest-path`；
- 退出码与 JSON output；
- 不复制 package resolution。

## PRJ-1108：Project graph fuzz/property

- manifest decoder fuzz；
- 随机 module graph cycle property；
- 路径 normalization；
- lock round-trip；
- 相同逻辑输入不同文件枚举顺序→相同结果。

# 4. Workstream B：Bytecode 与 VM

## VM-1201：bytecode RFC 与模型

定义：

- format/version magic；
- module/function/constant/type tables；
- instruction encoding；
- evaluation order；
- stack/register model；
- Fault 与 source map；
- verifier guarantees；
- resource limits；
- compatibility boundary。

禁止直接复制 Rust enum 的内存布局作为文件格式。

## VM-1202：Checked Core → bytecode 最小 lowering

第一条切片只支持：

```text
Unit/Bool/Int/Text
function call
local binding
Console.Write
return
```

实现 debug disassembly 和 golden fixture。

## VM-1203：独立 decoder/verifier

Verifier 检查：

- version/magic；
- table bounds；
- instruction boundaries；
- jump target；
- stack/register type state；
- function signature；
- constant kind；
- capability declaration；
- resource limits。

任意 bytes 只能返回结构化错误，不 panic。

## VM-1204：VM 基础执行

- 验证后才能执行；
- 显式 value representation；
- deterministic left-to-right；
- host capability adapter；
- execution budget hooks；
- source span Fault mapping。

## VM-1205：函数、closure、recursion

按规范逐项扩展；先固定 closure capture 语义，再选择实现布局。递归深度/OOM 必须成为定义的 Fault 或 host limit，不得栈溢出崩溃。

## VM-1206：Record、ADT、match

- nominal record/variant；
- constructor；
- field access/update；
- match decision tree 由 Checked Core 提供；
- exhaustiveness 已由 checker 证明；
- 非法 runtime tag 视为 verifier/internal fault。

## VM-1207：Mutable place 与基础 borrow

- 明确 local/field place；
- 自动短 borrow 已在 Checked Core 展开；
- VM 不重新做 borrow inference；
- mutation observable order 与解释器一致。

## VM-1208：Effect/Capability/Fault

- bytecode function metadata 记录 Effect/Capability；
- host operation 在 capability table 中解析；
- 缺 capability 在执行前或边界稳定拒绝；
- Fault 保留 code/provenance/source；
- 不允许 host panic 泄漏为用户 Fault。

## VM-1209：Interpreter ↔ VM differential

每个 conformance 程序比较：

- stdout/stderr logical events；
- return value；
- structured Fault；
- state mutation；
- diagnostics（compile phase）；
- semantic snapshot identity。

明确不比较实现内存地址和内部 instruction count。

## VM-1210：Fuzz 与资源限制

- decoder/verifier fuzz；
- valid bytecode mutator；
- step budget；
- stack/heap limit；
- oversized tables；
- malformed UTF-8 metadata；
- cancellation。

VM 成为默认 Explore 路径前，必须覆盖全部 Seed 稳定语义。

# 5. Workstream C：基础 Trait

## TRAIT-1301：Trait RFC 收口

必须决定：

- declaration/impl syntax；
- nominal vs structural；
- constraint form；
- coherence；
- orphan；
- overlap；
- inference boundary；
- public API 如何显示约束；
- lowering 方式；
- Semantic ID 是否包含 impl selection。

首版明确不做 specialization、任意动态分派和高级类型级计算。

## TRAIT-1302：AST/HIR 表示

- parser/CST/AST；
- resolved TraitId/ImplId；
- source origin；
- duplicate member diagnostics；
- compiler parser 与 Tree-sitter 同步 corpus。

## TRAIT-1303：Constraint collection

类型推断生成规范化 obligations；错误保留来源链，不在收集阶段选择 impl。

## TRAIT-1304：Coherence/orphan checker

- 跨包 impl index；
- duplicate/overlap/orphan；
- deterministic candidate order 只用于诊断，不改变选择；
- 负向 cross-package fixtures。

## TRAIT-1305：Solver v0

只支持已接受的有限规则：唯一候选、递归深度保护、cycle detection、稳定 unsatisfied/ambiguous diagnostics。

## TRAIT-1306：Checked Core 显式化

所有已选择 impl/dictionary 在 Checked Core 中明确表示。后端不得重新搜索实例。

## TRAIT-1307：Interpreter/VM lowering

统一 dictionary passing 或 Accepted 替代方案；建立 differential tests。

## TRAIT-1308：IDE 支持

- hover 显示 inferred constraints 和 selected impl；
- go-to impl/trait；
- completion member；
- rename 保持 identity；
- errors 可提供 imports/constraint fixes，但不生成不安全 orphan impl。

## TRAIT-1309：性能与终止

建立 solver benchmark：深链、菱形、失败、跨包；设置可解释 resource limit，避免病态程序拖死 LSP。

# 6. Workstream D：增量编译

## INC-1401：Query boundary ADR

评估并决定 query engine；无论使用第三方还是自研，公开行为只依赖规范输入。记录：cancellation、parallelism、persistence、cycle、debugging、license。

## INC-1402：VFS 与 revision

- immutable file version；
- open overlay；
- disk snapshot；
- package manifest revision；
- config/profile/target revision；
- change event dedup。

## INC-1403：Parse queries

```text
source_bytes(FileId)
line_index(FileId)
tokens(FileId)
parse(FileId)
ast(FileId)
```

验证 comment-only、whitespace、body edit 的失效边界。

## INC-1404：Resolve/module queries

- module graph；
- exports；
- scope；
- resolved body；
- public signature change 使 dependents 失效；
- private body 不应重查无关模块。

## INC-1405：Type/effect queries

分离 public signature 与 body check；防止一个函数体改动使整个 workspace 重算。

## INC-1406：Semantic queries

- definition graph fragment；
- ProgramSnapshot；
- canonical writer；
- identity invalidation；
- comment/alias 变化是否影响何种 ID 按规范测试。

## INC-1407：Clean ↔ incremental equivalence

随机编辑序列后比较：

- diagnostics；
- checked signatures；
- semantic graph；
- canonical bytes；
- formatter output；
- VM result。

## INC-1408：Deterministic parallel scheduling

随机任务调度/HashMap seed，多次运行输出 byte-identical。发现顺序泄漏立即修复。

## INC-1409：Persistent cache（若 RFC 接受）

- cache key 包含 toolchain/language/unicode/schema/profile/target；
- corruption 安全回退；
- 不反序列化不可信任为 unchecked IR；
- cache miss 不改变行为。

## INC-1410：增量性能基线

记录 cold/warm check、单字符编辑、签名编辑、跨包编辑、10k 文件 synthetic workspace；门禁基于回归趋势，而不是未经测量的绝对承诺。

# 7. Workstream E：Formatter 与 Audit

## FMT-1501：Formatter preservation RFC

决定：comments、blank lines、parentheses、Unicode spelling、line endings、trailing commas、error nodes、offside blocks 的保留/规范化边界。

## FMT-1502：Format IR

从 compiler CST 构建 doc tree；不使用 Tree-sitter 或 regex 作为权威 parser。

## FMT-1503：核心语法格式化

按 Seed corpus 覆盖 let/function/type/record/ADT/match/if/pipeline/module/import/mutable。

## FMT-1504：Comment attachment

文档注释、行尾注释、嵌套块注释、中文注释；不得跨定义漂移。

## FMT-1505：不完整源码

定义稳定策略：尽量格式化完整节点，对 error region 保守保留；不得损坏用户文本。

## FMT-1506：性质测试

```text
fmt(fmt(x)) == fmt(x)
parse(fmt(x)) equivalent parse(x)
resolve/type checked core equivalent（对合法程序）
comments preserved
```

## FMT-1507：CLI/LSP 接入

- `zero fmt [--check]`；
- stdin + logical filename；
- document/range formatting（range 可后置）；
- format-on-save；
- JSON report。

## FMT-1508：Audit 分离

Audit Source 继续由 Semantic/Audit renderer 产生。测试证明 Formatter 不会替代或改变 canonical Audit。

# 9. Workstream G：CLI 与开发命令

## CLI-1701：命令模型统一

一个 parser/dispatch 层；每个命令只调用共享服务。禁止 `check`、`run`、`lsp` 各自构建不同 CompilerHost。

## CLI-1702：输出与退出码

统一 `--format human|json`、语言选择、颜色、quiet/verbose。稳定错误码和 program Fault 与 tool failure 分离。

## CLI-1703：`init`

创建最小项目、`.gitignore`、示例 `.ling`、可选 `.zed/tasks.json`。模板版本进入 manifest，不联网也可创建。

## CLI-1704：`test`

首版测试声明语法若未规范，`zero test` 只运行已接受 test convention；不得由 CLI 发明注解。输出结构化 test events。

## CLI-1705：`query/patch`

仅暴露已有版本化 Semantic Query/Transaction；默认只读 query，patch 检查 ProgramSnapshot 和 preserve constraints。

## CLI-1706：Shell completion 与 help fixtures

help 输出不要求永久字节兼容，但命令/flag/exit code 有 inventory；生成 bash/zsh/fish/PowerShell completion 可后置为 Preview。
