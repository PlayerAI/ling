# G2 / Ling v0.2 Concurrent 详细执行计划

> 目标版本：`v0.2 Concurrent`  
> 前置门禁：`v0.1 Living` 全部出口标准通过  
> 本阶段结果：显式 Effect、结构化任务、Actor、监督、确定性重放与最小 Remote Actor 形成一个可测试闭环  
> 非目标：通用分布式一致性平台、无限透明远程调用、生产级集群编排、Actor 代替所有并行模型

## 1. 阶段不变量

本阶段必须始终遵守：

1. 时间、随机数、网络、调度、取消和外部输入不得成为隐藏副作用；
2. Task、Actor、Replay 全部消费 Checked Typed Core，不直接解释 AST；
3. Actor mailbox 必须有界，背压必须进入类型、Effect、Fault 或显式返回值；
4. 本地 Actor 与 Remote Actor 语法可以相近，但身份、延迟和失败语义不能伪装相同；
5. Replay 记录外部可观察 Effect，不把某次线程调度顺序误定义为语言语义；
6. 所有公开事件日志、消息 Envelope 和远程协议都必须版本化；
7. 并发 Runtime 不得使用 host panic 表达 Ling Fault；
8. 新增诊断保持中英双语、稳定错误码与原始 UTF-8 byte span。

## 2. 规范门禁与 RFC 顺序

在写 Runtime 前，按以下顺序关闭 RFC：

| RFC | 必须决定 | 阻断 |
| --- | --- | --- |
| RFC-C201 Effect Row | row 表示、推导、消除、polymorphism、handler 作用域 | EFF-*、Task、Actor |
| RFC-C202 Structured Task | 父子生命周期、join、取消、detach、Fault 聚合、suspension | TASK-* |
| RFC-C203 Actor Semantics | identity、state isolation、turn、`await` 重入、message ownership | ACT-* |
| RFC-C204 Mailbox & Supervision | 容量、背压、顺序、退出、重启预算、升级策略 | ACT-*、SUP-* |
| RFC-C205 Determinism & Replay | determinism class、effect log、Program ID、隐私和损坏规则 | REP-* |
| RFC-C206 Remote Actor | RemoteRef、delivery guarantee、重试、重复、认证与 transport boundary | REM-* |

任何 RFC 未 Accepted 时，只允许在 `experimental/` 或 feature gate 下做验证性原型，不得形成稳定公开 API。

## 3. 目标架构

```text
Ling Source
    ↓
Parser / Resolve / Type + Effect Check
    ↓
Checked Typed Core
    ├── Effect operations + handler regions
    ├── Task scopes + suspension points
    ├── Actor declarations + typed messages
    └── Determinism metadata
    ↓
Concurrency IR
    ├── Task state machines
    ├── Actor turn handlers
    ├── Supervisor graph
    └── Replay event boundaries
    ↓
Reference Runtime
    ├── deterministic test scheduler
    ├── production local scheduler
    ├── bounded mailbox runtime
    ├── replay recorder/player
    └── reference remote transport
```

需要新增或扩展的 crate：

```text
crates/
├── ling-effects
├── ling-concurrency-ir
├── ling-task-runtime
├── ling-actor-runtime
├── ling-supervision
├── ling-replay
├── ling-remote
└── ling-model-test
```

不要让 `ling-actor-runtime` 反向依赖 parser/typechecker；它只接受已经验证并 lowered 的并发表示。

# 4. EFF：Effect Row 与 Handler

## EFF-2101：Effect 核心模型冻结

**规模：M；依赖：RFC-C201；单一集成者。**

交付：

- `EffectId`、`EffectRow`、row variable、closed/open row；
- operation signature；
- handler 输入、恢复类型和作用域；
- Capability 与 Effect 的明确分工；
- canonical ordering 与 Semantic Graph Schema；
- 至少覆盖 `Clock`、`Random`、`Console`、`State<T>`、`Task`、`ActorSend<T>` 的示例。

验收：

```text
pure function                         → {}
Clock.now                             → {Clock}
handler Clock within expression       → effect correctly discharged
polymorphic map                       → preserves caller effect row
missing Capability                    → stable compile-time diagnostic
unhandled effect at profile boundary  → stable rejection
```

## EFF-2102：Effect 推导和约束求解

**规模：L，拆成 3 个 PR。**

1. 收集 operation/调用产生的 row constraints；
2. row unification、occurs check、泛化与实例化；
3. 错误解释、最小冲突集和中英双语诊断。

不得把 Effect 退化为无序字符串集合；输出顺序必须 canonical。

## EFF-2103：Handler Typed Core 表示

显式表示：

```text
handle <body>
with operation <op>(args, resume) -> <handler-body>
```

要求：

- `resume` 的线性/多次恢复规则由 RFC 决定并检查；
- handler 能否跨 Task/Actor 边界必须显式；
- 未处理 Effect 不得由 runtime 随意 fallback；
- Audit Source 展开 handler 和已消除/残留 Effect。

## EFF-2104：解释器与 VM Handler 执行

先实现解释器参考路径，再实现 VM；建立 differential corpus：

- 单层 handler；
- 嵌套 handler；
- 传播；
- resume；
- handler 内 Fault；
- handler 与 mutable state；
- handler 与取消。

## EFF-2105：Effect fuzz/property tests

生成小型 well-typed Core，比较：

```text
interpreter result
VM result
residual effect row
Fault category
```

随机输入不得导致 host panic、无限递归或 canonical 输出漂移。

# 5. TASK：Structured Task

## TASK-2201：Task 语法与 Checked Core

**规模：M；依赖：RFC-C202、EFF-2103。**

只实现已接受的最小语法：

```fsharp
task 加载资料 id =
    scope
        let! 人物 = 读取人物 id
        let! 历史 = 读取历史 id
        return 合并 人物 历史
```

Checked Core 必须显式包含：

- scope id；
- parent/child relation；
- spawn/join；
- suspension point；
- cancellation token；
- cleanup region；
- detach capability（若 RFC 接受）。

## TASK-2202：Task 状态机 Lowering

把每个 suspension point lowered 为版本化 state machine：

- 局部变量活跃集；
- continuation state；
- cancellation edge；
- cleanup edge；
- Fault edge；
- source map。

测试需覆盖多次 suspension、match 分支、循环、资源清理和嵌套 scope。

## TASK-2203：结构化生命周期 Runtime

实现：

- scope 创建/关闭；
- 子任务注册；
- 默认 join；
- 父取消向子传播；
- 子 Fault 聚合；
- 超时作为 `Clock` + cancellation 组合，而非隐藏线程 API；
- 退出时无 orphan task。

## TASK-2204：确定性测试调度器

提供测试专用 scheduler：

```text
seeded scheduling
virtual clock
controlled wake order
bounded interleaving exploration
trace export
```

该 scheduler 用于可重复触发竞态、取消和清理路径；不得承诺生产调度顺序也是语言语义。

## TASK-2205：生产本地调度器

第一版优先正确性：

- 固定 worker pool；
- work queue；
- 唤醒/park；
- cancellation；
- 可查询 task tree；
- 每 scope 的任务数和资源上限；
- runtime metrics 不影响程序语义。

后续 work stealing 作为独立性能任务，不能和首个语义实现混在一个 PR。

## TASK-2206：Task conformance 与压力测试

必须覆盖：

- 父任务提前退出；
- 子任务取消期间释放 Resource；
- 两个子任务同时 Fault；
- 超时与正常完成竞争；
- scope 嵌套；
- 明确拒绝非法 detach；
- 100 万短任务的资源上限；
- scheduler 关闭时无丢失清理。

# 6. ACT：Actor 与有界 Mailbox

## ACT-2301：Actor 身份与状态隔离

**规模：M；依赖：RFC-C203。**

定义：

- `ActorTypeId`：类型级身份；
- `ActorId`：运行时实例身份；
- `ActorRef<Message>`：类型化引用；
- state 只能在 actor turn 内被修改；
- 外部只能发送消息，不得借出 `&mut state`；
- ActorRef 的序列化与 RemoteRef 分开。

## ACT-2302：消息可发送性检查

Checker 验证消息：

- 不携带跨 turn 活跃 borrow；
- Resource 的 move/copy 规则明确；
- Managed graph 的共享规则由 profile 决定；
- Capability 不得通过普通消息伪造；
- message schema 进入 Semantic Graph。

## ACT-2303：有界 Mailbox 与背压

每个 actor 声明或 profile 必须确定容量/策略：

```fsharp
actor 记录器
    mailbox capacity 1024
    overflow Wait
```

允许的策略只能来自 RFC，例如：

- `Wait`：send 产生 suspension/Backpressure Effect；
- `Reject`：返回 `MailboxFull`；
- `DropNewest` / `DropOldest`：仅显式允许并产生日志/metric；
- Critical/可靠消息默认禁止静默 drop。

## ACT-2304：Turn 与重入规则

这是高风险语义，必须单独实现和测试：

- actor 每次只执行一个 turn；
- actor turn 内 `await` 是冻结当前 turn、释放 turn，还是禁止重入，由 RFC 决定；
- 如果允许重入，必须标记 state version/guard；
- self-send 与递归处理不得绕过 mailbox；
- 长 turn 需有可观测 watchdog，不得强制杀死并破坏资源语义。

## ACT-2305：Actor Runtime

实现最小本地 runtime：

- spawn/stop；
- bounded mailbox；
- typed envelope；
- turn dispatch；
- lifecycle event；
- Fault provenance；
- task runtime 集成；
- actor registry 不成为全局可变语言状态。

## ACT-2306：Actor 性质与压力测试

- 同一 actor state 修改串行；
- 不同 actor 可并行；
- 满邮箱无内存无限增长；
- 慢消费者有稳定背压；
- stop 后 send 的行为确定；
- turn Fault 不泄露 host unwind；
- 随机 interleaving 下消息顺序符合声明；
- 进程终止前 actor 资源被清理或明确标记非正常终止。

# 7. SUP：监督树

## SUP-2401：Supervisor 模型

**依赖：RFC-C204、ACT-2305。**

定义：

- child spec；
- restart/stop/escalate；
- one-for-one、rest-for-one 等策略是否纳入首版；
- transient/permanent/temporary child；
- restart budget 和时间窗口；
- state restore 来源；
- parent Fault channel。

## SUP-2402：重启预算与熔断

禁止无限高速重启。实现：

```text
restart_count
window
backoff
max_restarts
last_fault_provenance
circuit_state
```

全部可由 `zero query runtime` 或调试接口读取。

## SUP-2403：监督测试

覆盖：

- 单 child Fault；
- 多 child 连续 Fault；
- 重启期间再次 Fault；
- 超出预算后 escalate；
- parent 终止；
- actor state snapshot 恢复失败；
- cleanup 与 mailbox 中未处理消息的明确策略。

# 8. REP：确定性等级与 Replay

## REP-2501：Determinism Class

**依赖：RFC-C205。**

最小建议分类：

```text
Strict              同一规范输入必须完全一致
Seeded              给定随机种子一致
RecordedEffects     给定外部 Effect log 一致
BestEffort          不承诺可重放
```

最终名称以 RFC 为准。类别必须进入构建元数据、Semantic Graph 和 replay header。

## REP-2502：Replay Log Schema

版本化事件至少包含：

- Program/Semantic ID；
- toolchain/runtime version；
- profile/target；
- effect operation id；
- logical actor/task id；
- logical sequence；
- input/result/Fault；
- schema version；
- redaction/privacy metadata；
- integrity checksum。

不得直接记录指针地址、host 路径、OS thread id 或不稳定 debug 文本。

## REP-2503：Effect Recorder

在声明的 Effect boundary 记录：

- `Clock`；
- `Random`；
- 外部输入；
- 网络接收；
- 文件/设备读取；
- 用户选择的调度 nondeterminism（仅当规范需要）。

纯计算和可由输入重建的中间状态不应全部写入日志。

## REP-2504：Replay Player

启动前验证：

```text
Program ID
Schema
profile
capabilities
config
message schema
```

不匹配时明确拒绝，不能“尽量播放”。支持 checkpoint + event log。

## REP-2505：隐私、裁剪与损坏

实现：

- 字段级 redaction；
- secret/PII 不允许进入默认日志；
- 日志裁剪保留依赖边界；
- chunk checksum；
- 截断/损坏诊断；
- replay 工具默认离线工作。

## REP-2506：跨进程重放验收

在两个独立进程、清洁缓存和固定工具链上：

- 运行原始程序生成日志；
- replay；
- 比较规范可观察结果；
- 重复 N 次；
- 变更 Program ID/Schema 后验证拒绝。

# 9. REM：Remote Actor

## REM-2601：RemoteRef 与 Endpoint

禁止把 `ActorRef` 直接序列化成网络地址。定义：

```text
RemoteRef<Message>
EndpointId
RemoteActorId
ProtocolVersion
CapabilityToken
```

发送操作产生 `Network + ActorSend` Effect，并返回明确 delivery/Fault 类型。

## REM-2602：Transport-neutral Envelope

Envelope 至少包含：

- protocol version；
- sender/receiver semantic type id；
- message schema id；
- message id；
- correlation id；
- deadline/cancellation；
- delivery policy；
- authentication metadata；
- payload checksum。

序列化格式通过 RFC 决定；不要把第一种实现格式等同语言语义。

## REM-2603：Delivery 语义

首版只承诺 RFC 明确支持的模式，例如 at-most-once 或显式可重复 delivery。不得把重试写成“exactly once”。

需要测试：

- timeout；
- disconnect；
- duplicate；
- reorder；
- stale actor incarnation；
- remote restart；
- incompatible message schema；
- capability revoke。

## REM-2604：最小参考传输

选择一个参考 transport，仅用于验证协议：

- loopback/in-process transport 用于 deterministic tests；
- TCP/QUIC 等真实 transport 作为独立 adapter；
- transport 不得拥有业务消息反序列化权限之外的 Capability；
- 编解码失败是 Typed Fault。

## REM-2605：安全与资源限制

- 最大 frame/message；
- decoder depth；
- mailbox ingress limit；
- authentication/authorization hook；
- replay protection；
- rate limit；
- 拒绝未知 schema；
- 模糊测试所有 decoder。

# 10. LSP、Zed 与工具链同步

本阶段需要同步：

| 能力 | LSP | Zed |
| --- | --- | --- |
| `task` / `actor` / `supervisor` | symbols、hover、completion、diagnostics | Tree-sitter/highlight/outline |
| Effect Row | hover、inlay hint（Preview）、semantic token | token rules |
| mailbox/backpressure | diagnostics、code action | diagnostics 展示 |
| actor message | definition/references/rename | semantic highlighting |
| replay | custom `zero replay` command、code lens 可后置 | Zed task/runnable |
| RemoteRef | type hover、network Effect | token/diagnostic |

编辑器不得自行判断 mailbox 容量、消息可发送性或 Effect；只展示 compiler/LSP 结果。

# 12. v0.2 出口门禁

- [ ] Effect Row、Handler 与 Capability 规则有 Accepted RFC 和 conformance；
- [ ] Task 无结构化作用域泄露，取消和清理有性质测试；
- [ ] Actor state 隔离，mailbox 始终有界；
- [ ] 背压、消息顺序和 turn 重入行为可见且可诊断；
- [ ] Supervisor 有重启预算和 Fault provenance；
- [ ] Replay 能在支持范围内跨独立进程复现；
- [ ] Program/Schema/Capability 不匹配会明确拒绝；
- [ ] Remote Actor 显式暴露网络 Effect 与部分失败；
- [ ] 解析器、解释器、VM、LSP、Zed corpus 同步；
- [ ] 并发 fuzz、压力和交错测试无未分类 host panic、无限内存增长或死锁；
- [ ] v0.2 traceability、支持矩阵和公开协议版本已更新。
