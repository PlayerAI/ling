# G5 / Ling v0.5 Critical 详细执行计划

> 目标版本：`v0.5 Critical`  
> 前置门禁：G2 Replay、G3 Resource/Native、G4 受限 Lowering 均已有稳定边界  
> 本阶段结果：Critical Profile、同步 `node`、Contract、有界模型检查与 Evidence Bundle 形成可信工程闭环  
> 非目标：宣称整门语言已获得航空/航天认证、证明任意程序完全正确、让 AI 或测试结果替代独立验证

## 1. 阶段原则

1. Critical 是明确受限的 Profile，不是给普通程序加一个“安全”标签；
2. 未证明、假设和运行时检查必须清楚区分，绝不把 `Assumed/Unknown` 显示为 `Proved`；
3. 硬实时控制优先采用同步 `node`，Actor 主要承担监督、容错和非硬实时协作；
4. 通用 GC、无界分配、无界队列、隐藏 I/O、动态代码和不可审计 FFI 默认禁止；
5. Deadline/WCET 结论必须绑定 target、工具链、调度、假设和证据；
6. 模型检查必须披露状态空间、搜索界和未覆盖区域；
7. Evidence Bundle 必须可由独立、较小的验证工具离线检查；
8. AI 可以生成实现、Contract 和证明候选，但不进入可信计算基（TCB）。

## 2. 规范门禁

| RFC | 决定内容 | 阻断 |
| --- | --- | --- |
| RFC-K501 Critical Core/Profile | 允许/禁止能力、边界、target profile | PROF-* |
| RFC-K502 Synchronous Node | tick、state、clock、deadline、overrun、Fault | NODE-* |
| RFC-K503 Contract | requires/ensures/invariant、purity、status、runtime/static | CTR-* |
| RFC-K504 Boundedness | loop/recursion/queue/task/allocation bounds | BND-* |
| RFC-K505 Verification Interface | proof obligations、solver/proof checker、trusted assumptions | PROOF-* |
| RFC-K506 Model Checking | finite projection、bounds、report semantics | MC-* |
| RFC-K507 Evidence Bundle | schema、identity、provenance、independent verification | EVD-* |
| RFC-K508 Critical Backend | verified/validated lowering、supported target、TCB | CBK-* |

# 4. PROF：Critical Profile Checker

## PROF-5101：机器可读 Profile

**规模：M；依赖：RFC-K501。**

Profile 文件至少声明：

```text
language/spec version
compiler version range
standard library set
target architecture
scheduler
allowed effects/capabilities
memory policy
numeric policy
concurrency policy
FFI target packages
verification requirements
```

示例（仅结构示意）：

```toml
name = "FlightCritical-0"
profile_version = 1
heap = "forbidden"
dynamic_code = false
network = false
random = "explicit-seeded-only"
```

## PROF-5102：禁止能力检查

在 Lowering 前稳定拒绝：

- 通用 Managed/GC；
- 未界定 allocation；
- 未声明 Clock/Random/IO/Network/Device；
- 动态加载、反射、任意 shell/build step；
- 不受限 Task/Actor topology；
- unbounded mailbox；
- 未审计 FFI；
- 非确定 numeric/placement；
- 未处理 Fault/fallback。

## PROF-5103：Profile Composition

允许基础 profile + target profile + mission constraints 的受控组合；冲突必须显式诊断。最终 effective profile canonical 化并参与 build/Semantic ID。

## PROF-5104：Profile Audit 与 LSP

提供：

```text
zero check --profile <name>
zero audit --profile <name>
zero explain profile
```

LSP 在保存/检查时显示违反 Profile 的具体 Effect、能力或无界来源。

# 5. BND：有界资源与终止

## BND-5201：Bound 类型与表达式

**依赖：RFC-K504。**

定义：

- compile-time constant；
- profile parameter；
- range type；
- collection capacity；
- loop trip bound；
- recursion depth；
- task/actor count；
- stack/arena budget；
- message size。

## BND-5202：循环和递归检查

实现分层状态：

```text
StaticallyBounded
ProvedTerminating
RuntimeGuarded
Forbidden/Unknown
```

Critical 中允许哪些状态由 Profile 决定。递归可自动转换为有界 work queue 仅作为明确 code action，不得默默改语义。

## BND-5203：内存预算

计算/验证：

- static data；
- stack upper bound；
- arena/buffer；
- queue/mailbox；
- task/actor state；
- device memory（若 profile 允许）；
- transient peak；
- error/fallback path。

结果绑定 target ABI 和编译版本。

## BND-5204：资源预算诊断

诊断给出：

```text
budget
estimated/proved usage
largest contributors
path/provenance
unknown assumptions
candidate transformations
```

# 6. NODE：同步反应式节点

## NODE-5301：Node 语法与语义

**规模：L；依赖：RFC-K502。**

最小模型：

```fsharp
node 姿态控制 (传感器: 传感帧)
    every 10.ms
    deadline 2.ms
    : 控制输出 =
    ...
```

需要规范：

- logical tick；
- input sampling；
- output commit；
- persistent state；
- initialization；
- absence/presence；
- clock domain；
- deterministic evaluation order；
- Fault/overrun；
- composition。

## NODE-5302：Node Checked Core

显式表示：

- input/output port；
- state cells；
- tick transition；
- clock/period；
- deadline；
- dependency graph；
- feedback delay；
- Fault transition；
- Contract hooks。

拒绝 instantaneous cyclic dependency，除非规范定义可求解固定点且已证明。

## NODE-5303：静态调度

生成 node graph 的 topological/static cyclic schedule：

- dependency analysis；
- rate/clock compatibility；
- multi-rate bridge；
- priority/period；
- release/deadline；
- overrun policy；
- scheduler manifest。

## NODE-5304：虚拟时间参考 Runtime

用于 conformance：

- deterministic virtual clock；
- exact tick；
- injected input；
- output trace；
- overrun simulation；
- Fault/fallback；
- replay integration。

## NODE-5305：Native Node Runtime

- static memory；
- no general allocation；
- fixed schedule；
- target timer primitive；
- watchdog；
- safe state transition；
- startup/shutdown；
- telemetry outside hard-real-time path。

## NODE-5306：Node/Actor 边界

明确桥接：

```text
Actor → sampled input queue → Node
Node → bounded output event → Actor
```

硬实时 node 不等待 Actor、网络或动态 service；桥接缓冲、丢弃/过期和 fallback 都由 profile 决定。

## NODE-5307：Node conformance

覆盖：

- initialization；
- multi-tick state；
- multi-rate；
- stale/missing input；
- deadline hit/miss；
- fallback；
- restart/safe mode；
- replay；
- static schedule deterministic。

# 7. CTR：Contract

## CTR-5401：Contract 语法与 AST/Core

**依赖：RFC-K503。**

支持最小集合：

```text
requires
ensures
invariant
assert
assume（必须受限并记录）
```

Contract 表达式默认 pure、total 或满足规范允许的受限 Effect。

## CTR-5402：Contract 状态模型

每条 obligation 具有：

```text
Proved
RuntimeChecked
Assumed
Unknown
Failed
NotApplicable
```

状态进入 Audit、Graph、Evidence；UI 使用不同图标/颜色，但不能隐藏文本状态。

## CTR-5403：Runtime Contract Check

先实现参考执行：

- precondition at call；
- postcondition at return；
- invariant at declared boundary；
- instance values；
- source provenance；
- Fault category；
- Profile 可禁止 runtime-only check。

## CTR-5404：Verification Condition Generation

生成版本化 Proof IR/VC：

- SSA/path conditions；
- pre/post；
- loop invariants；
- arithmetic model；
- memory/alias facts；
- Effect facts；
- source mapping；
- trusted assumptions。

## CTR-5405：Solver/Proof Checker Adapter

外部 solver 只能作为候选证明生成器；最终接受路径需：

- proof certificate 或可重放 query；
- fixed solver/version/config；
- timeout/unknown；
- proof checker；
- no silent trust of solver stdout；
- TCB 清单。

## CTR-5406：优化器使用 Contract 的规则

只有满足规范可信等级的 `Proved` 事实可以驱动语义改变型优化。`RuntimeChecked/Assumed/Unknown` 不得作为消除安全检查的依据。

## CTR-5407：Contract LSP/Zed

- hover 显示条款和状态；
- diagnostics 显示 counterexample/failed instance；
- code lens 跳转 proof/evidence；
- gutter 状态；
- rename 保持 contract reference；
- Audit 展开隐式条件。

# 8. PROOF：证明内核与可信边界

## PROOF-5501：Proof IR

**依赖：RFC-K505。**

设计一个小而版本化的证明/验证中间层，避免把整个编译器加入 TCB。包含：

- sorts/types；
- terms；
- hypotheses；
- theorem；
- arithmetic/memory axioms；
- proof steps/certificate reference；
- source/provenance。

## PROOF-5502：独立 Checker

`zero-proof-check` 或库：

- 无 compiler global state；
- 可离线；
- 输入有大小/深度限制；
- deterministic；
- fuzzed decoder；
- clear TCB；
- 验证结果 machine-readable。

## PROOF-5503：假设注册表

所有无法证明的外部事实进入：

```text
assumption id
description
source
scope
owner/reviewer
expiry/version
risk class
affected obligations
```

Evidence Bundle 必须列出，不得埋在注释中。

# 9. MC：有界模型检查

## MC-5601：有限状态投影

**依赖：RFC-K506。**

从 Task/Actor/Node 构建：

- state variables；
- bounded mailbox/queue；
- transitions；
- scheduler choices；
- Fault/restart；
- time abstraction；
- property；
- explicit bound。

## MC-5602：探索引擎

第一版可采用明确算法：

- BFS/DFS；
- partial-order reduction（后置）；
- state hashing；
- bounded depth；
- counterexample trace；
- timeout/memory bound；
- deterministic search mode。

## MC-5603：报告语义

只允许表达：

```text
CounterexampleFound
NoCounterexampleWithinBounds
Inconclusive
InvalidModel
```

禁止把 `NoCounterexampleWithinBounds` 写成“已证明系统安全”。

## MC-5604：Replay Counterexample

把模型检查 counterexample 转为 deterministic scheduler/replay fixture，在参考 runtime 中执行并链接源码位置。

# 10. TIM：时间与 WCET 证据

## TIM-5701：Timing IR 与 Path

记录：

- target instruction/block；
- control-flow path；
- loop bound；
- cache/memory assumption；
- interrupt/scheduler model；
- device/FFI call bound；
- source map。

## TIM-5702：测量与静态分析分离

报告分别标记：

```text
Measured
Estimated
StaticallyBounded
Assumed
Unknown
```

实测平均/最大值不能冒充 WCET 证明。

## TIM-5703：Deadline Check

把 node deadline 与：

```text
WCET bound
scheduler interference
I/O bound
margin
```

比较。结论绑定 target/profile/build ID。

# 11. EVD：Evidence Bundle

## EVD-5801：Bundle Schema

**依赖：RFC-K507。**

目录/容器至少包含：

```text
manifest
program/source/semantic IDs
spec/RFC versions
dependencies/lock/build graph
profile/target/toolchain
canonical Audit Source
conformance/property/fuzz results
contract obligations/results/proofs
model-check reports/traces
timing/memory reports
replay fixtures
FFI/Target Package/TCB
assumptions/exemptions/known limits
AI provenance
human review/signoff metadata
artifact hashes
```

## EVD-5802：独立验证器

`zero evidence verify <bundle>`：

- schema/version；
- canonical/hash；
- artifact linkage；
- proof certificates；
- test report signatures/identity；
- lock/toolchain；
- missing/unknown fields；
- offline mode；
- no code execution from bundle。

## EVD-5803：可重复构建绑定

从 bundle manifest 在受控环境重建，比较：

- source/semantic id；
- object/binary hash；
- accepted documented non-determinism；
- generated source/proof provenance。

## EVD-5804：AI Provenance

记录工程级事实，不要求暴露私密完整对话：

```text
agent/tool identity
input semantic snapshot
task/goal
changed semantic nodes
preserved contracts
new obligations
test/verification commands
human approval
```

AI provenance 不是正确性证据，只是追踪来源。

# 12. CBK：Critical Backend

## CBK-5901：可信编译路线决策

**依赖：RFC-K508。**

比较：

- 经过验证的受限后端；
- translation validation；
- proof-producing lowering；
- 受控 C 子集桥接；
- 目标机器码验证。

选择的首版只覆盖小型 Critical Core 和有限 target。

## CBK-5902：Lowering Validator

即使 backend 未完全形式验证，也为每次 lowering 生成/检查：

- type/layout；
- control flow；
- value mapping；
- contract preservation facts；
- memory/alias；
- source/binary correspondence；
- unsupported construct rejection。

## CBK-5903：Critical Runtime/Target Package

- static scheduler；
- no general heap；
- bounded stack；
- deterministic startup；
- watchdog/safe state；
- qualified target primitive list；
- no host OS service unless declared；
- target-specific evidence。

# 13. 编辑器与审计体验

Zed/LSP 本阶段提供：

- profile violation diagnostics；
- `node`、period、deadline、state、contract 高亮；
- Contract 状态 code lens/gutter；
- counterexample 跳转与 replay task；
- memory/timing contribution hover；
- assumption/TCB/evidence navigation；
- `zero audit --canonical`、`zero evidence verify` tasks；
- Critical 文件默认显示更严格 lint/profile；
- 不允许 UI 仅用绿色图标掩盖 `Assumed/Unknown`。

# 14. 建议执行批次

```text
B50A RFC-K501/K504 + Critical negative corpus
B50B Profile checker + bounds/memory budget
B50C RFC-K502 + Node Core/reference runtime
B50D static schedule + Native node runtime

B51A RFC-K503/K505 + Contract Core/runtime checks
B51B VC/Proof IR + independent checker
B51C RFC-K506 + bounded model checker/replay
B51D timing/WCET evidence model
B51E RFC-K507/K508 + Evidence/critical lowering
B51F Zed/LSP/audit UX
B51G v0.5 independent review and exit
```

# 15. v0.5 出口门禁

- [ ] Critical Profile 精确列出允许/禁止能力并在 Lowering 前检查；
- [ ] 无界分配、递归、循环、队列、任务或 Actor topology 不会进入 Critical build；
- [ ] Node tick/state/clock/deadline/overrun/Fault 语义有规范和 conformance；
- [ ] hard-real-time path 不依赖 Actor/Network/GC；
- [ ] Contract 状态不会混淆 Proved、RuntimeChecked、Assumed、Unknown；
- [ ] Proof checker 独立、离线、输入有界并有 fuzz；
- [ ] 模型检查完整披露 bounds、assumptions 和未覆盖状态；
- [ ] counterexample 可转为可重复 runtime/replay fixture；
- [ ] timing 结论区分 measured/estimated/bounded/assumed；
- [ ] Evidence Bundle 可由独立工具离线验证；
- [ ] Target Primitive/TCB/assumptions/豁免全部可查询；
- [ ] 不在文档或 UI 中宣称超出证据范围的认证或完全正确性；
- [ ] v0.5 支持矩阵只承诺实际覆盖的 profile/target/toolchain。
