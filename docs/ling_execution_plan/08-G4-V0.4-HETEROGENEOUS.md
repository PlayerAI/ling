# G4 / Ling v0.4 Heterogeneous 详细执行计划

> 目标版本：`v0.4 Heterogeneous`  
> 前置门禁：G3 的内存、ABI、Native IR 与 Resource 语义稳定  
> 本阶段结果：受限 Kernel 子语言、CPU 参考执行、SIMD、首个 GPU backend、显式 Placement 和可解释设备数据移动  
> 非目标：一次覆盖全部 GPU/TPU 厂商、让 backend 错误替代语言诊断、默认自动把任意函数搬到设备

## 1. 阶段原则

1. 程序首先表达计算性质、数据依赖和约束，硬件只是 Placement 选择；
2. `kernel` 是经过检查的受限子集，不是“任何 Ling 函数前加一个属性”；
3. CPU scalar reference 是设备语义基线；
4. Device Buffer 的 ownership、address space、transfer、sync 和 Fault 必须显式；
5. 数值语义、reduction 顺序和 determinism class 不能由驱动默认决定；
6. 设备缺失、feature 不足或编译失败只能按规范拒绝或执行显式允许的 fallback；
7. Placement 必须可解释、可记录、可重放；
8. 设备缓存键必须包含程序身份、target、toolchain、driver、profile 和数值模式。

## 2. 规范门禁

| RFC | 决策内容 | 阻断 |
| --- | --- | --- |
| RFC-H401 Kernel Subset | 类型、控制流、Effect、递归、分配、alias、shape | KCHK-* |
| RFC-H402 Device Memory | Buffer、address space、ownership、transfer、sync | DBUF-* |
| RFC-H403 Numeric & Determinism | precision、NaN、FMA、reduction、容差、determinism | CPU/SIMD/GPU |
| RFC-H404 Device IR | backend-neutral ops、shape/layout、barrier、source map | DIR-* |
| RFC-H405 Placement | `requires/prefers`、fallback、cost、record/replay | PLC-* |
| RFC-H406 Backend Support | 首个 GPU backend、tier、driver/toolchain matrix | GPU-* |

## 3. 目标架构

```text
General Checked Typed Core
    ↓
Kernel Subset Verifier
    ↓
Kernel Core
    ├── CPU Scalar Reference
```

# 4. KCHK：Kernel 子集检查器

## KCHK-4101：Kernel 允许能力矩阵

**规模：M；依赖：RFC-H401。**

建立机器可读矩阵：

| 语言能力 | Kernel Stable | 条件/诊断 |
| --- | --- | --- |
| scalar/value record | 是 | 固定布局 |
| ADT | 受限 | 固定 tag/layout |
| Managed | 否 | `KERNEL_MANAGED_FORBIDDEN` |
| Resource | 仅 DeviceBuffer/view | 不允许任意 Drop |
| dynamic allocation | 否 | 需 host 预分配 |
| recursion | 首版否 | 后续需可证明上界 |
| Task/Actor/Network | 否 | 非设备 Effect |
| loops | 是 | 必须可 lower/界定 |
| function calls | 受限 | kernel-pure、可内联/设备可用 |
| trait dispatch | 静态唯一实例 | 禁止隐式动态派发 |

矩阵进入 docs、Graph schema 和 compiler tests。

## KCHK-4102：Kernel Effect 与 Capability 检查

允许的 Effect 默认极小：

```text
Pure
DeviceRead<Buffer>
DeviceWrite<Buffer>
DeviceBarrier（如 RFC 接受）
```

禁止 Clock、Network、File、Actor、Console、随机数（除非采用显式 deterministic RNG kernel）。

## KCHK-4103：Shape、Index 与 Bounds

- shape/type 表示；
- index range；
- static/dynamic dimension；
- bounds check 或证明消除；
- overflow；
- host/device 一致 Fault；
- source-level diagnostic 不依赖 backend log。

## KCHK-4104：Alias 和并行写冲突

Checker 分析：

- buffer view overlap；
- read/write set；
- per-index ownership；
- reduction/atomic；
- race-free condition；
- 无法证明时拒绝或要求显式安全 primitive。

## KCHK-4105：Kernel Core 与 Verifier

建立设备无关、版本化 Kernel Core，并独立验证：

- legal type/control flow；
- no forbidden Effect；
- buffer/address space consistency；
- legal barrier；
- race/alias annotations；
- deterministic serialization。

# 5. CPU：参考执行与差分基线

## CPU-4201：Scalar Reference Backend

**优先级最高。**

逐步实现：

1. element-wise map；
2. multidimensional index；
3. conditional；
4. bounded loop；
5. buffer read/write；
6. reduction；
7. explicit Fault。

该路径尽量直接、可审计，不追求优化，是所有 GPU/TPU 的语义 oracle。

## CPU-4202：Reference Trace

测试模式可输出：

```text
logical work item
buffer reads/writes
index
operation
Fault
```

trace 只用于测试/解释，不作为稳定高性能接口。

## CPU-4203：Kernel Corpus

建立：

- vector add；
- matrix multiply 小规模；
- image filter；
- reduction；
- histogram/atomic（若支持）；
- invalid bounds；
- alias conflict；
- floating-point edge；
- Unicode source mapping。

# 6. SIMD：CPU 向量化

## SIMD-4301：向量化合法性分析

分析：

- independent iterations；
- alignment；
- vector width；
- tail；
- alias；
- reduction；
- strict/relaxed FP；
- target feature。

不合法时 scalar fallback 只能在 RFC 允许时发生，并记录原因。

## SIMD-4302：Portable SIMD IR

在 Native/Device IR 中表示：

- lanes；
- vector load/store；
- mask；
- shuffle；
- horizontal reduction；
- scalarization fallback；
- target capability。

## SIMD-4303：SIMD Differential

比较 CPU scalar 与 SIMD：

- integer exact；
- strict FP exact/规定语义；
- relaxed FP 在明确 tolerance 内；
- tail/unaligned；
- overflow；
- Fault location。

# 7. DBUF：设备内存与数据移动

## DBUF-4401：Device 类型与 Capability

定义：

```text
DeviceId
DeviceKind
DeviceCapability
AddressSpace
Buffer<Device, T, Shape>
ReadView / WriteView
TransferToken
Fence/Event
```

API 不暴露任意 raw device pointer。

## DBUF-4402：Buffer Ownership

- host/device ownership；
- exclusive write；
- shared read；
- subview；
- mapping；
- pinning；
- async transfer 生命周期；
- drop 等待或取消规则；
- actor/task crossing。

## DBUF-4403：Transfer Effect

示例表达：

```fsharp
let! gpu数据 = transfer 数据 to gpu
```

Semantic Graph/Audit 必须显示：

```text
bytes
source/destination address space
synchronization
possible Fault
Capability<DeviceTransfer>
```

编译器不得让隐式大规模传输看起来免费。

## DBUF-4404：同步模型

定义：

- command queue；
- event/fence；
- host await；
- device barrier；
- cross-queue ordering；
- buffer hazard；
- cancellation；
- device lost。

# 8. DIR：Backend-neutral Device IR

## DIR-4501：Device IR Schema

**规模：L；依赖：RFC-H404。**

表达：

- workgroup/grid；
- scalar/vector/tensor types；
- address spaces；
- memory ops；
- control flow；
- barrier/atomic；
- shape/layout；
- numeric mode；
- source map；
- capabilities；
- required backend feature。

## DIR-4502：Kernel Core → Device IR

分片实现，保持 verifier：

1. elementwise；
2. index/shape；
3. local memory；
4. reduction；
5. vector/tensor op；
6. synchronization；
7. source diagnostic map。

## DIR-4503：Device IR Canonicalization

- deterministic node/block ordering；
- canonical constants；
- target-independent hash；
- separate target specialization hash；
- no driver path/timestamp；
- schema version and migration tests。

# 9. GPU：首个设备 Backend

## GPU-4601：Backend Spike 与选择

隔离评估可选路径（实际候选以开发时 RFC 为准）：

- SPIR-V/Vulkan；
- WGSL/WebGPU；
- CUDA/PTX；
- MLIR-based bridge；
- vendor SDK。

指标：

```text
platform coverage
compiler/runtime API
source/debug support
numeric control
CI hardware availability
license
cache/reproducibility
maintenance cost
```

## GPU-4602：Backend Adapter

实现窄接口：

```text
compile(DeviceIR, TargetSpec) -> DeviceBinary
allocate/transfer/launch/sync
query capabilities
map Fault
collect stable diagnostics
```

vendor-specific 逻辑不进入 front-end core。

## GPU-4603：Launch 与 Runtime

- device discovery；
- capability match；
- module load；
- buffer bind；
- launch dimensions；
- queue submit；
- sync；
- device lost；
- resource cleanup；
- metrics/explain plan。

## GPU-4604：差分和硬件矩阵

每个 stable 组合记录：

```text
OS
GPU
architecture
runtime/driver
backend compiler
numeric mode
known limitations
```

CPU reference 与 GPU 比较；没有覆盖的组合标记 Experimental，而非推定可用。

## GPU-4605：错误归一化

将 vendor log 转为稳定分类：

```text
UnsupportedFeature
DeviceUnavailable
CompileFailure
LaunchFailure
OutOfDeviceMemory
DeviceLost
NumericModeUnsupported
```

保留 vendor detail 作为非稳定附加字段，不让其成为 public error code。

# 10. ACC：TPU/NPU/其他加速器插件

## ACC-4701：Accelerator Plugin Interface

只允许插件消费经过验证的 Device IR/Kernel Core；插件必须声明：

- supported ops/types；
- shape/layout constraints；
- numeric modes；
- device capability；
- target identity；
- cache identity；
- fallback policy；
- diagnostic mapper。

## ACC-4702：Experimental 适配器

首个 TPU/NPU 适配器可以是 Experimental，不阻断 v0.4 Stable，除非支持矩阵明确列入。不得在核心编译器复制 vendor graph semantics。

# 11. PLC：Placement、成本和缓存

## PLC-4801：Placement 约束模型

**依赖：RFC-H405。**

语义区分：

```text
requires gpu
prefers gpu
forbids remote
same_node_as X
near BufferY
fallback cpu
```

Placement 是约束求解，不是随意 runtime 猜测。

## PLC-4802：静态候选与运行时选择

流程：

```text
compile-time legality/capability filter
    ↓
artifact preparation
    ↓
runtime available-device match
    ↓
policy/cost choice
    ↓
record decision
```

Critical/Strict replay 默认固定 Placement；普通 Native 可允许记录后重放。

## PLC-4803：Cost Model v0

先使用可解释、保守模型：

- input bytes；
- transfer bytes；
- operation count；
- memory footprint；
- launch overhead；
- device occupancy hint；
- deadline/energy policy（仅元数据）。

不得把未经校准的估计宣传为保证。

## PLC-4804：`zero explain placement`

输出：

```text
candidate devices
rejected reasons
chosen device
transfers
numeric mode
fallback
cache hit/miss
record/replay identity
```

## PLC-4805：设备二进制缓存

Cache key 包含：

```text
Program/Semantic ID
Device IR version
backend/version
target architecture
runtime/driver compatibility
numeric mode
profile
compiler options
```

缓存损坏安全回退重编译，不改变程序语义。

# 12. 编辑器和开发体验

LSP/Zed 增加：

- `kernel`、`placement`、`Buffer<Device,...>` 的语法与 semantic tokens；
- 禁止 Effect/Managed/recursion 的精确错误；
- buffer alias/race 的 related ranges；
- device capability hover；
- `zero explain kernel|placement|transfer` task；
- CPU/GPU differential test runnable；
- Device IR/Audit navigation；
- 可选 Code Lens：CPU/GPU 支持状态和 benchmark（Preview）。

编辑器不主动选择设备，也不缓存编译器未签名的语义结果。

# 14. v0.4 出口门禁

- [ ] Kernel verifier 在 backend 前拒绝所有越界能力；
- [ ] CPU scalar reference 覆盖稳定 Kernel 子集；
- [ ] SIMD 对齐、尾部、alias、overflow 和 FP 模式有差分测试；
- [ ] Device Buffer 生命周期、地址空间、传输与同步进入 Core/Graph/Audit；
- [ ] Device IR 有独立 verifier、canonical encoding 和 schema version；
- [ ] 至少一个 GPU backend 在列明硬件矩阵通过测试；
- [ ] unsupported device/feature 不静默改变数值或 Effect 语义；
- [ ] CPU/GPU 的 exact/tolerance 比较遵守 RFC-H403；
- [ ] Placement 选择可解释、可记录、可重放；
- [ ] 缓存键包含所有必要 target/toolchain/driver 输入；
- [ ] TPU/NPU 未承诺部分明确 Experimental；
- [ ] LSP/Zed 能显示 Kernel/Buffer/Placement 诊断而不复制语义；
- [ ] v0.4 支持矩阵列出每个已验证硬件与软件组合。
