# RFC-0037: Checked LSP Hover Preview / 已检查 LSP Hover Preview

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-23
> 目标版本：v0.1 Preview
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001; GAP-SEMANTIC-PROTOCOL-LIFECYCLE-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines Ling's checked, bounded LSP `textDocument/hover` surface. It
closes IDE-2302 by composing accepted checked-type/effect/capability,
resolver-reference, Trait-dictionary, request-snapshot, and source-position
boundaries without publishing resolver or Semantic IDs.

本 RFC 定义 Ling 已检查且有界的 LSP `textDocument/hover` 接口。它组合已接受的
类型、Effect、Capability、resolver 引用、Trait dictionary、请求快照与源码位置
边界，同时不发布 resolver ID 或 Semantic ID，从而关闭 IDE-2302。

## Summary

`ling.lsp.hover/0.1` resolves an exact current document position against one
complete checked workspace snapshot. Hover targets include user declarations,
local and parameter declarations, and resolved references to user, Prelude, or
builtin definitions and local bindings. A successful target returns one exact
identifier range and deterministic bilingual plaintext or Markdown containing
the normalized name/signature, target kind, mutability when applicable,
non-empty Effects and module Capability closure, and an exact selected Trait
witness when the checked call has one. A valid position with no target returns
`null`.

- Stable implementation basis: `yes` for this Preview protocol.

    implementation ordinals, source paths/provenance, profile/stability claims,

## Normative changes

### 1. Negotiation and discovery

Initialize recognizes optional `capabilities.textDocument.hover`. If present,
it MUST be an object. Its optional `contentFormat` MUST be a non-empty array of
strings. The server chooses the first supported value in client order from
`plaintext` and `markdown`; an array with no supported value is InvalidParams.
Malformed known shapes reject initialize without lifecycle mutation. Absence
selects `plaintext`, and the selected format is immutable for the session.

Every successful initialize MUST advertise `hoverProvider: true` and this exact
Experimental member, with `markup` equal to the negotiated value:

```json
"lingHover": {
  "maxContentBytes": 65536,
  "maxEntries": 16384,
  "markup": "plaintext",
  "version": "ling.lsp.hover/0.1"
}
```

The capability adds no custom request.

### 2. Request, position, and snapshot

`textDocument/hover` accepts a request object containing required string
`textDocument.uri` and required `position` with unsigned-u32 `line` and
`character`. Unknown ordinary fields are ignored. Wrong known shapes, unknown
documents, or positions that cannot map exactly through the negotiated
UTF-8/16/32 source map return InvalidParams `-32602`; positions are never
clamped or rounded. A notification with this method does no work.

The server MUST be Ready and capture one immutable path-free request snapshot.
Non-temporary requests check the complete non-temporary snapshot. A temporary
request checks only that exact temporary source plus project inputs. Exact
visible bytes, logical source identities, origins, versions, revisions,
workspace inputs, and position encoding come from that snapshot.

The complete snapshot MUST be recaptured before success, including `null`.
Any difference makes the result stale and returns RequestFailed without
partial output or mutation. Version 0.1 advertises no work-done or partial
result channel and cannot observe later cancellation in the synchronous host.

### 3. Compiler checked-hover index

The compiler builds a complete immutable index only after parsing, HIR
lowering, resolution, type checking, Effect checking, Capability closure, and
Trait dictionary lowering succeed. It records declaration spans for resolver
user definitions, local bindings, and parameters, plus exact resolver-filtered
reference spans. References reuse their exact checked target facts; no
spelling-based fallback is permitted.

The target taxonomy is `Value`, `Type`, `Constructor`, `Builtin`,
`TraitMember`, `ImplementationMember`, `Binding`, and `Parameter`. User
definition kinds derive from resolver metadata. Prelude/builtin entries exist
only at references when they have no user declaration span. Binding mutability,
type, Effect row, and target-module Capability closure are copied from the
checked program. Empty/missing Effect and Capability sets are not invented.

For a checked concrete Trait member application, the reference entry MUST join
the exact `TraitMemberCall` to its dictionary witness and member ordinal. The
public observation contains only normalized Trait name, canonical receiver,
and member name. Resolver IDs, implementation IDs/modules/ordinals, obligation
ordinals, and diagnostic origin data remain internal. Any inconsistent join
rejects the complete index.

Type display walks the existing resolved checked type but alpha-canonicalizes
inference variables by first appearance: the first distinct variable is `'a`,
the second `'b`, through `'z`, then `'t26`, `'t27`, and so on. Equal variables
reuse the same spelling. Arena IDs such as `'t91` MUST NOT enter hover output.
Nominal/source names and all non-variable type syntax retain the existing
checked display spelling.

Entries sort by logical source name, SourceId, start byte, end byte, kind,
normalized target name, and internal identity tie-breaker. At most 16384
declaration, binding, and reference entries are allowed. Overflow or a missing
checked join returns no index.

### 4. Target selection

The request position converts to one exact original byte offset. An entry
contains the position iff `span.start <= offset < span.end`. Zero-length spans
cannot match. If compiler invariants ever produce overlapping entries, the
smallest span wins, followed by the canonical index order. With no matching
entry, the successful result is exactly `null`.

The returned `range` is the selected entry's exact identifier span projected
through the negotiated position encoding. It is not the declaration location
for a reference and does not authorize navigation, rename, or an edit.

### 5. Content model

The renderer first forms these semantic lines in fixed order:

1. `<normalized-name>: <canonical-type>` when a checked type exists, otherwise
   `<normalized-name>`;
2. `种类 / kind: <kind>` using lowercase labels `value`, `type`, `constructor`,
   `builtin`, `trait-member`, `implementation-member`, `binding`, or
   `parameter`;
3. `可变 / mutable: true` only for a mutable target;
4. `效果 / effects: <labels>` only for a non-empty canonical Effect row;
5. `能力 / capabilities: <labels>` only for a non-empty target-module
   Capability closure; and
6. `Trait 选择 / Trait selection: <trait><<receiver>>.<member>` only for an
   exact checked concrete selection.

Effect and Capability labels retain their already canonical sorted order and
join with `, `. No locale, clock, path, debug value, hash-map order, or client
text enters rendering. The semantic content is limited to 65536 UTF-8 bytes;
overflow returns RequestFailed rather than truncation.

For `plaintext`, the lines join with LF and the LSP `contents` value is
`{"kind":"plaintext","value":"..."}`. For `markdown`, the signature is one
`ling` fenced code block and remaining lines are Markdown bullet items with
their values in inline code. All dynamic values are restricted compiler
spellings that cannot contain backticks; a violated safety invariant rejects
the response. The `contents.kind` is `markdown`. Both formats convey identical
facts in identical order.

The successful response has exactly `contents` and `range`. It omits
`MarkedString`, custom data, documentation, source/provenance, IDs, versions,
diagnostics, and edit fields.

### 6. Failures and compatibility

Syntax/HIR/resolution/type/Effect/Capability/Trait failure, invalid checked
join, index/content overflow, unsafe Markdown value, projection failure, stale
completion, or an encoded body above RFC-0004's 1 MiB maximum returns LSP
RequestFailed `-32803` with fixed bilingual message
`悬停信息不可用 / hover information unavailable`. No compiler diagnostic is
allocated, no partial result is emitted, and diagnostics/publication/document
state remains unchanged.

An incompatible target, selection, type normalization, label, format, field,
order, bound, snapshot, or error change requires a new protocol marker and
migration evidence. Additive language constructs need an Accepted hover
mapping before they appear.

## Compatibility impact

- **Protocol:** adds Preview `ling.lsp.hover/0.1`; no predecessor.
- **Compiler query:** adds one bounded immutable checked hover index by joining
  existing accepted checked/resolver observations; no semantic authority moves
  into LSP.
- **Diagnostics/identity:** no code allocation or Semantic/resolver ID schema
  change; no internal identity enters the wire.
- **Language/runtime/data:** no Ling syntax/semantics, Typed Core evaluation,
  interpreter, runtime, bytecode, VM, ABI, filesystem/network/cache, or Unicode
  17.0.0 behavior changes.

## Unresolved alternatives

Markdown-only output was rejected because plaintext is safer and broadly
supported; both are negotiated here. Returning compiler arena variable IDs was
rejected as unstable implementation leakage. Returning partial hover after a
failed checked pipeline was rejected because it would misrepresent inferred
facts. Exposing selected implementation IDs or ordinals was rejected because
they are compiler identity, not hover presentation.

Documentation, arbitrary expression hover, imports/modules, profile/stability,
resource/borrow facts, unresolved recovery, dynamic registration, progress,
partial results, asynchronous cancellation, caching promises, fixes,
Workspace Edits, Semantic Transactions, and Stable lifecycle remain future
work.
