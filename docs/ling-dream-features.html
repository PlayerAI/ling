先看懂状态标记

“任务 Done”只表示某个有边界的实现或证据切片完成，不自动等于公开、稳定或可从 CLI 使用。

✅ 已实现 已有代码、测试和文档；仍可能处于 Experimental 或 Preview。
🔬 内部实验 真实代码或测试证据存在，但公开语言入口仍被明确拒绝。
🚧 正在推进 当前焦点；可能正在做规范、验收证据或编码准备。
⛔ 等待规范 没有 Accepted 决议就不能实现，避免代码偷偷创造语义。
🧭 梦想规划 路线图方向，不是发布日期或兼容性承诺。

梦想特性逐条清单

可以用下面的按钮只看某种状态。页面打印时会自动恢复为完整清单。

01 写代码：让人读得懂，也让机器不含糊

  • ✅ 已实现中文标识符是一等公民

    变量、函数和类型可以直接用中文命名；编译器按 Unicode 17、NFC 和混淆字符规则检查，不把“长得一样”当成“就是同一个”。

  • ✅ 已实现小而清楚的 Seed 语法

    已有 let、函数、if、空格函数调用、pipeline、record、ADT 和穷尽 match，先把常用表达能力做扎实。

  • ✅ 已实现局部类型推导与模式匹配

    常见代码少写类型标注，编译器仍会检查 Option、Result、tuple、record 和 variant 是否被正确处理。

  • ✅ 已实现默认不可变，修改必须说清楚

    普通绑定不能暗中变化；只有声明为 mutable 的 Place 才能用 <- 更新，读代码时能一眼看见状态改变。

  • ✅ 已实现Effect 与 Capability 分开

    Effect 说明“程序做了什么”，Capability 说明“程序获准做什么”。这为可测试 I/O、最小权限和未来 Replay 打基础。

  • ✅ 已实现第一阶段 Effect Handler

    Effect row 推导、约束求解、Checked Core 表示和解释器/VM handler 执行已有 Experimental 切片，不再只是文档设想。

  • ✅ 已实现基础 Trait 静态分派

    声明、约束收集、coherence/orphan 检查、solver 和 dictionary lowering 已完成；高级 specialization 和动态分派没有偷跑。

  • ⛔ 等待规范Trait 的完整 IDE 与性能承诺

    已有 Semantic Graph 投影和只读查询证据，但完整 IDE 体验、solver 性能边界与终止承诺仍不能对外宣称。

02 执行：同一份语义，多种可靠跑法

  • ✅ 已实现先检查，再执行

    源码必须经过解析、名称解析、类型与 Effect 检查，执行器只消费 Checked Typed Core，不会把未解决的 AST 节点当成合法程序。

  • ✅ 已实现解释器与事务式 REPL

    ling run 和 REPL 能执行当前支持范围；REPL 的失败输入不会把半截状态悄悄留在会话里。

  • ✅ 已实现版本化 Bytecode 与独立 Verifier

    ling.bytecode/1.0 有确定性编码、bounded decoder 和 verifier；非法跳转、版本与资源问题在执行前被拒绝。

  • ✅ 已实现库级 VM 与差分测试

    函数、闭包、递归、聚合、match、可变 Place、Effect/Capability/Fault 已有 VM 路径，并与解释器比较可观察结果。

  • ⛔ 对外未开放CLI 选择 VM 后端

    VM 是真实的 Experimental 库能力，但目前没有 Accepted 的 CLI bytecode 读写命令、backend selector 或默认资源上限。

  • 🧭 梦想规划Interpreter ↔ VM ↔ Native 三方一致

    未来不同执行引擎要跑同一套 conformance，并明确浮点、Fault、I/O 和资源释放允许出现哪些差异。

03 工程体验：从单文件到可维护项目

  • ✅ 已实现项目、模块和本地锁定依赖

    已有 manifest、确定性模块发现、跨包可见性、vendored path dependency 和 canonical lockfile；锁定后可离线解析。

  • ⛔ 不在当前支持面在线包安装、发布与中心 Registry

    Ling 目前重视可重复的本地依赖，不假装已经拥有成熟包生态；Registry 行为至少推迟到 1.0 之后再决定。

  • ✅ 已实现增量查询与可丢弃缓存

    Source、parse、resolve、type/effect 和 semantic 有明确查询边界；增量结果会与 clean 结果比较，坏缓存可以回退重算。

  • ✅ 已实现Formatter 与 Audit Source 分工

    ling fmt 面向作者代码并追求幂等、保留注释；Audit Source 负责展开隐含语义，两者不是同一份文本。

  • ✅ 已实现统一 CLI 工作流

    init/check/run/test/fmt/semantic/audit/query/patch/build/lsp/completion 已有统一命令模型、退出行为和帮助证据，但各命令只承诺自己的受支持边界。

  • ✅ Preview够用的 LSP 主干

    已有诊断、symbols、hover、definition、references、rename、completion、code action、semantic tokens、formatting、取消与资源上限。

  • ✅ 已实现Tree-sitter 语法与编辑查询

    已有语法、错误恢复、高亮、括号、缩进等查询，并与编译器 corpus 做差分；编辑器解析不会冒充语言权威。

  • ⛔ 等待规范完整 Zed 扩展与 DAP 调试器

    当前有兼容性边界证据，但安装、发现、任务、崩溃恢复、Marketplace、断点和变量查看尚未形成可发布产品。

  • ✅ 已实现Semantic Graph 与 AI 可审计修改

    工具可以按稳定身份查询定义和关系，并通过语义事务检查前置条件；AI 生成文本本身不进入 Trusted Computing Base。

04 并发：任务、Actor 与可重放世界

  • ✅ ExperimentalStructured Task 主干

    已有语法、Checked Core、状态机、生命周期 Runtime、确定性测试调度器和本地固定 worker pool。

  • ✅ 有边界可运行task main ()

    精确的文件/工程入口可由 ling run 解释执行；test、build、REPL、bytecode、VM、Native 与 Wasm 仍明确拒绝 Task。

  • 🔬 内部实验Actor、隔离状态与 bounded mailbox

    身份、消息可发送性、背压、turn/reentry、Runtime 和压力性质已有实现切片；公开 Actor 源码执行仍以 L-ACTOR-0002 拒绝。

  • 🔬 内部实验Supervisor 与重启预算

    内部模型、restart budget、circuit breaker 和测试已经存在，但没有公开 Supervisor 语言/API 协议。

  • 🔬 内部实验Determinism Class 证据

    REP-2501 已完成私有、test-only 的确定性分类证据；它不是公开 metadata，也不是 Replay 格式。

  • 🚧 正在推进·规范阶段Replay 记录结构证据

    REP-2502 是下一焦点。Proposed DEC-0280 只拟授权 crate-private、非序列化证据；接受前不能编码。

  • ⛔ 等待规范真正的录制与重放

    公开 schema、Effect recorder、Replay player、checksum、隐私裁剪、损坏检测和跨进程验收仍全部缺失。

  • 🧭 梦想规划Remote Actor，但不假装“网络透明”

    未来远程消息会显式暴露延迟、断连、重试、重复或丢失，不把网络调用伪装成本地函数调用。

05 Native：性能建立在清楚的资源语义上

  • ⛔ 等待规范Value / Managed / Resource 真正落地

    三分内存模型目前是设计方向；Copy/Move、Drop、finalization 和 Profile 边界未形成可执行稳定语义。

  • 🧭 梦想规划Ownership / Borrow / Region 检查

    目标是提前抓住 use-after-move、别名冲突、region escape 和错误 drop 顺序，同时不泄露 Rust 实现细节。

  • 🧭 梦想规划最小 Managed Runtime 与 GC

    Explore/Native 可以有受管对象，但 root、finalization、OOM 和 FFI pinning 必须先说清楚；Critical 不引入通用 GC。

  • 🧭 梦想规划可验证 Native IR 与 AOT

    Checked Core 先 Lower 到 backend-neutral IR，再接一个基线 Native backend；后端只负责实现语义，不能自己发明语义。

  • 🧭 梦想规划Typed FFI 与可审计 TCB

    FFI 声明要说清 ABI、ownership、线程、重入、Fault 与 Capability，不安全部分集中在可盘点的 Target Primitive Package。

06 异构计算：先有 CPU 标尺，再谈 GPU

  • ⛔ 整块等待规范受限 Kernel 子集

    要先定义可用类型、控制流、Effect、递归、分配和数值模式；不允许拿 backend 编译失败代替语言诊断。

  • 🧭 梦想规划CPU Reference 与 SIMD

    先用标量 CPU 建立可比较语义，再做合法向量化、尾部处理与 fallback，优化不能改变声明的确定性等级。

  • 🧭 梦想规划Device Buffer 与 Device IR

    显式建模 buffer ownership、address space、传输 Effect、同步和 canonical device IR。

  • 🧭 梦想规划GPU / TPU / NPU 插件

    先接一个可测试的 GPU backend；其他加速器走窄插件接口，不让每个厂商在编译器里复制一套语言规则。

  • 🧭 梦想规划可解释 Placement

    “为什么放在这个设备上”要能查询、记录和重放；设备缺失时明确拒绝或执行规范允许的 fallback。

07 Critical 与 1.0：把“可靠”变成证据

  • ⛔ 尚未实现Explore / Native / Critical Profile 选择

    三个 Profile 目前只是路线图模型；CLI 没有 profile 选项，也没有 profile validation pass。

  • 🧭 梦想规划有界资源与时间

    让循环、递归、内存预算和 deadline 能被静态检查或明确标成运行时义务，而不是一句“应该不会超”。

  • 🧭 梦想规划Node 与虚拟时间

    面向可预测系统建立静态调度、虚拟时间参考 Runtime，并定义 Node 与 Actor 的清楚边界。

  • 🧭 梦想规划Contract 与证据等级

    前置条件、后置条件和不变量要区分 Proved、RuntimeChecked、Tested、Assumed、Unverified，测试绝不冒充证明。

  • 🧭 梦想规划Proof IR 与独立检查器

    编译器可以产出证明证据，但最终由更小、更容易审计的独立 checker 复核，并公开所有假设。

  • 🧭 梦想规划有界模型检查与可重放反例

    探索 Task/Actor/Node 的有限状态；报告必须写出搜索边界，找到反例后交给 Replay 复现。

  • 🧭 梦想规划Evidence Bundle 与 AI provenance

    把源码身份、构建、测试、分析、假设和 AI 修改来源装进可独立验证的证据包。

  • 🧭 最终目标Ling 1.0 兼容承诺

    冻结语言核心、Semantic Graph、诊断、CLI 和关键 schema，完成历史 corpus、迁移、fuzz、安全审计与多平台发布证据。

三个最容易误解的地方

这三条决定了本文为什么没有把所有 Done 项都涂成绿色。

看到的状态 真实含义 不能推出什么
Done 登记任务的 Accepted 范围、实现或证据已经闭合。 不能自动推出“Stable”“所有入口都能用”或“已经达到 1.0 质量”。
*-OBSERVATION Done 边界、缺失项或内部结构已有可执行/文档证据。 不能推出它的 BlockedSpec 父功能已经实现。
任务 351 / 499 Done 说明治理和切片推进很多，且 148 项仍为 BlockedSpec。 不能直接换算成“1.0 完成 70%”；后续 Native、GPU、Critical 的风险与体量远高于普通观察任务。
