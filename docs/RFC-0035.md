# RFC-0035: LSP diagnostic transcript fixtures / LSP 诊断 transcript fixtures

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-23
> 目标版本：v0.1 Preview
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001; GAP-SEMANTIC-PROTOCOL-LIFECYCLE-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines executable, path-free JSON-RPC transcript fixtures for the
current Ling LSP diagnostic surface. It closes LSP-2205 by pinning observable
wire behavior from Accepted RFC-0004 and RFC-0031 through RFC-0034 without
creating a new editor method or changing compiler diagnostic authority.

本 RFC 为当前 Ling LSP 诊断接口定义可执行、无路径的 JSON-RPC transcript
fixtures。它依据已接受的 RFC-0004 与 RFC-0031 至 RFC-0034 固定可观察线协议行为，
不新增编辑器方法，也不改变编译器诊断权威，从而关闭 LSP-2205。

## Summary

Each fixture case contains raw UTF-8 JSON-RPC input and expected-output payload
files, one compact JSON value per LF-terminated line. The conformance harness
adds and removes RFC-0004 `Content-Length` framing only at the transport edge,
runs the real stdio server twice, and requires exact response-body bytes,
frame order, exit state, and repeated-run identity.

## Normative changes

### 1. Corpus layout and metadata

The corpus root is `tests/fixtures/lsp-diagnostics-v1/`. Its `manifest.json`
MUST be UTF-8 JSON with exact top-level members `schema` and `cases`.
`schema` MUST equal `ling.test.lsp-diagnostic-transcripts/1`. Each case MUST
contain exact string members `id`, `input`, and `output`; an integer
`exitCode`; and a non-empty string array `protocols`. Case IDs and file names
MUST be unique, relative single path components, and sorted by `id`.

The manifest is an internal test-data contract, not a Ling public protocol,
JSON-RPC method, compiler schema, or editor integration surface. Any
incompatible corpus-layout change requires a new manifest schema marker and
migration evidence in the same change.

### 2. Transcript payload grammar

Input and output files MUST be UTF-8 without a BOM. Each non-empty line MUST
contain exactly one compact JSON object and end with LF. Blank lines, leading
or trailing JSON whitespace, duplicate object keys, non-object roots, and a
missing final LF are invalid. Payload files contain no transport headers.

The harness MUST frame each input line as
`Content-Length: <UTF-8-byte-count>\r\n\r\n<payload>`, concatenate frames in
file order, and pass the bytes to the real `run_stdio` host. It MUST strictly
decode every output frame, compare each body byte-for-byte with the expected
output line at the same ordinal, and reject extra, missing, malformed, or
trailing bytes.

### 3. Determinism and isolation

Every case MUST execute twice in a fresh server and both complete framed
outputs, exit codes, and terminal lifecycle states MUST be identical. The
harness and fixtures MUST use only repository bytes and locked-offline crate
dependencies. Fixtures MUST contain Ling URIs only and MUST NOT observe host
paths, environment values, clocks, process IDs, network, registries, caches,
allocation addresses, hash-map iteration, or debug renderings.

Expected objects use the exact compact key ordering emitted by the current
writer. This byte fixture is Preview compatibility evidence for the protocol
markers listed by the case, not authority to change the semantics of an
existing compiler diagnostic.

### 4. Required cases

The v1 corpus MUST contain at least these independently executable cases:

1. `push-unicode-recovery`: initialize UTF-16, open BOM/CRLF Chinese source
   containing a later emoji, apply an incremental edit before the emoji that
   creates a registered diagnostic, assert its exact code/range/bilingual
   message/version, repair the same range, and assert an exact empty
   versioned replacement before clean shutdown.
2. `pull-parity-recovery`: negotiate pull, publish one current push
   diagnostic, request a full document report containing a byte-identical
   diagnostic array, repair the source, publish empty clearance, and request a
   full empty report using the prior result ID.
3. `storm-control-recovery`: configure document/workspace limits, publish
   retained roots plus the exact `L-LSP-0001` omission summary, repair the
   source, and assert summary clearance.
4. `invalid-control-initialize`: reject an out-of-range known control limit as
   InvalidParams without lifecycle mutation or diagnostic output.

The harness MUST additionally assert the push/pull diagnostic-array equality
inside the parity case rather than relying only on duplicated fixture text.

### 5. Boundaries not representable by sequential transcripts

The RFC-0004 host processes one complete message at a time. A later cancel
notification therefore cannot race an active pull request, and an externally
authored transcript cannot complete an old analysis ticket after a newer
mutation. Server-observable cancellation is unsupported by RFC-0033; stale
ticket rejection remains executable in the in-process push/pull integration
tests. These facts MUST NOT be represented by fabricated wire messages or
placeholder fields.

Related-file adapter projection, UTF-8/UTF-32 negotiation, malformed internal
adapter values, oversized responses, URI insertion-order invariance, and
simultaneous document/workspace summaries remain covered by focused executable
tests under `crates/ling-lsp/tests/`. The transcript corpus complements rather
than duplicates those lower-level failure-injection boundaries.

## Conformance plan

- Validate manifest shape, sorted/unique cases, safe relative names, exact
  protocol markers, transcript grammar, final LF, and JSON object roots.
- Frame raw input payloads, execute the real stdio host twice, strictly decode
  output frames, compare exact bytes/order/count, exit code, and terminal state.
- Assert the required case set and semantic cross-frame invariants for
  versioned recovery, push/pull parity, omission summary, and initialization
  failure atomicity.
- Run the locked/offline workspace suite, strict Clippy, CI, governance, LSP,
  support, status, RC0, traceability, formatting, and diff gates.

## Compatibility impact

- **Protocol:** no new public protocol; the corpus records RFC-0004 and the
  current diagnostic adapter/push/pull/control markers.
- **Diagnostics:** no code, severity, message, Fact, repair, Semantic ID, or
  compiler diagnostic schema change.
- **Language/runtime/data:** no syntax, semantics, Typed Core, interpreter,
  runtime, bytecode, VM, ABI, filesystem/network/cache, or Unicode 17.0.0
  behavior change.
- **Testing:** adds one internal Preview manifest format and exact wire bytes;
  incompatible fixture-layout changes require a new internal marker.

## Unresolved alternatives

Golden transport headers were rejected because their byte lengths duplicate
payload data and obscure review; the harness tests the exact framing logic
while keeping payloads readable. Editor-driven snapshots were rejected because
LSP-2205 explicitly requires protocol-independent tests. A fixture update mode
was rejected so expected bytes cannot silently bless implementation drift.
