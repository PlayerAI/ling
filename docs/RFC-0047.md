## Summary

This RFC defines the compiler-owned typed semantic-token generation boundary
required by LSP-2402. Revision `ling.semantic-token-generation/0.1` converts one
immutable checked workspace and one exact source snapshot into deterministic,
original-UTF-8 token spans under the taxonomy fixed by RFC-0046. If complete
checking fails, it emits only an explicitly marked whole-source lexical
fallback. It does not advertise an LSP provider or define full/delta transport.

本 RFC 定义 LSP-2402 所需、由编译器拥有的类型化语义 Token 生成边界。版本
`ling.semantic-token-generation/0.1` 将一个不可变的已检查工作区和一个精确源码快照，按照
RFC-0046 固定的分类转换为确定性的原始 UTF-8 token span。完整检查失败时，只生成明确标记
的全文件词法回退。本 RFC 不公布 LSP provider，也不定义 full/delta 传输。

## Normative changes

### 1. Generation identity and value model

The generation identity is `ling.semantic-token-generation/0.1`. A generator
MUST consume one exact `FileSnapshot`, its lexer token source, and either the
complete checked workspace containing that source or the failure of that
analysis. Its immutable result contains only:

- the existing session-local source identity and VFS revision;
- the logical source name;
- generation mode `typed` or `lexical-fallback`; and
- source-ordered entries containing a nonempty original UTF-8 span, one
  RFC-0046 canonical token type, a canonical-order modifier set, and evidence
  `checked-identity`, `checked-structure`, or `lexical-fallback`.

The mode and evidence are internal observations. They MUST NOT be serialized
as LSP token types, modifiers, result IDs, or Semantic IDs. A repeated query
for an equal compiler query key MUST produce an equal immutable result; a
source or relevant workspace revision change MUST produce a distinct query
result without mutating an older result.

### 2. Complete checked input

`typed` mode is permitted only after parsing, AST lowering, HIR lowering,
resolution, type checking, and Effect/Capability checking succeed for the
complete workspace used by the query. Generation MUST read the resulting
checked program and its resolved HIR. It MUST NOT interpret an unchecked AST,
Tree-sitter capture, diagnostic message, previous snapshot, or source spelling
as semantic identity.

In typed mode, evidence is selected in this order:

1. `checked-identity` for an exact resolver definition, binding, pattern
   constructor, or reference target;
2. `checked-structure` for an exact source role retained by successfully
   checked HIR where no resolver identity is required;
3. lexer classification for RFC-0046's six lexical families, recorded as
   `checked-structure` because the complete snapshot is checked.

Lower evidence MUST NOT replace a higher-evidence entry. Two incompatible
roles at the same precedence or any overlapping final spans are generator
errors; the generator MUST NOT select by map order or silently discard one.

### 3. Checked source-role rules

The RFC-0046 mapping is specialized to the current Seed HIR as follows:

| Checked source construct | Type | Required modifiers |
| --- | --- | --- |
| explicit module-name segment | `namespace` | `definition` |
| imported module-name segment | `namespace` | none |
| import alias declaration | `namespace` | `declaration` |
| record / variant / alias type name | `struct` / `enum` / `type` | `definition` |
| Trait name | `interface` | `definition` |
| named type / Trait reference | `type` / `interface` | none |
| declared or referenced type variable | `typeParameter` | `definition` on its declaration |
| parameter binding | `parameter` | `definition` and exactly one of `readonly` / `mutable` |
| local or value binding | `variable`, or `function` when its checked declaration has parameters | `definition` and exactly one of `readonly` / `mutable` |
| record field declaration or checked field label/projection | `property` | `definition` plus exactly one of `readonly` / `mutable` on declarations; target mutability on exact references |
| variant case declaration or resolved constructor pattern/reference | `enumMember` | `definition` on declarations |
| top-level callable value declaration/reference | `function` | declaration mutability modifiers as above |
| Trait member signature | `method` | `declaration` |
| implementation and implementation-member source names | `interface` / `method` | `definition` where a name token exists |
| builtin or Prelude value/type/constructor reference | its ordinary role | `defaultLibrary` |
| checked assignment root | its ordinary role | target mutability plus `modification` |

Record literal/update and pattern labels are `property`. A projection field is
`property` even when its resolver target is represented through a broader
definition kind. A constructor qualifier and a resolved import-alias qualifier
are `namespace`. Type-syntax `Name` atoms are `type`; `Variable` atoms are
`typeParameter`. Callable classification MUST come from the target declaration,
Trait/implementation membership, builtin identity, or an exact call relation;
capitalization and spelling are never evidence.

Names in `requires` clauses, handler operation paths, unresolved references,
wildcards, recovery nodes, and other roles not fixed above emit no identifier
token. Effect and Capability facts remain metadata without a source-token role.

### 4. Modifiers and reference propagation

Modifiers MUST be sorted in the RFC-0046 canonical order and deduplicated.
`declaration` and `definition`, and `readonly` and `mutable`, are mutually
exclusive. A definition or binding reference inherits `readonly` or `mutable`
only from its exact resolver target. `modification` is added only to the exact
resolved assignment root. A declaration with no body receives `declaration`;
an executable or structural definition receives `definition`.

Documentation comments receive only `documentation`. Ordinary comments,
keywords, booleans, literals, and operators receive no modifier. Builtin and
Prelude user shadowing MUST retain the user target's role and MUST NOT receive
`defaultLibrary`.

### 5. Whole-source lexical fallback

If any stage required by §2 fails, the result mode MUST be
`lexical-fallback`. Every emitted entry MUST use `lexical-fallback` evidence,
carry no modifier, and belong to exactly one RFC-0046 lexer-proven family:

- Seed keywords including `true` and `false` → `keyword`;
- line, block, and documentation comments → `comment`;
- text literals → `string`;
- integer and float literals → `number`;
- comparison, assignment, arithmetic, boolean, pipe, and arrow operators →
  `operator`.

Identifiers, punctuation, delimiters, apostrophes, whitespace, newline,
layout, lexer errors, EOF, and zero-width synthetic tokens emit nothing.
Documentation comments in fallback mode carry no `documentation` modifier,
because RFC-0046 forbids fabricated modifiers after checked analysis fails.

Version 0.1 deliberately uses whole-source lexical fallback. It does not mix
typed entries from a failed workspace with guessed parsed-error regions; a
future mixed-mode design requires Accepted error-region and partial-analysis
authority.

### 6. Spans, splitting, ordering, and failure

Every output span MUST be a nonempty subspan of one emitted lexer token in the
exact original source bytes. Multiline comments and text literals MUST split
at LF or CRLF boundaries. Neither LF nor the CR byte belonging to CRLF is part
of a segment; empty segments are omitted. All segments inherit their parent's
type, modifiers, and evidence.

Entries MUST sort by original start byte, end byte, token type's RFC-0046
canonical ordinal, modifier ordinals, and evidence ordinal. After sorting,
spans MUST be strictly nonoverlapping. Invalid UTF-8 boundaries, out-of-source
spans, cross-source spans, incompatible duplicate roles, or overlap make the
query fail atomically. No partial index is published.

Position encoding remains a later adapter concern. The index MUST NOT clamp,
convert to line/column, read disk, derive a URI, or bind an LSP document
version.

### 7. Privacy and compatibility boundary

Definition IDs, binding IDs, reference IDs, type text, Effect rows, Capability
sets, Trait witnesses, Semantic IDs, paths, source text, diagnostics, and debug
output MAY be consumed transiently for exact classification but MUST NOT be
retained in an entry. The result contains no client legend index or wire value.

The generator MAY be cached only by existing compiler query identity. Cache
hits, allocation, addresses, timing, and thread scheduling are not observable
behavior. Provider negotiation and transport remain prohibited until an
Accepted LSP-2403 authority defines them.

## Conformance plan

- Cover every current Seed declaration/reference role, modifiers, callable and
  non-callable values, Trait/implementation members, fields, constructors,
  patterns, type syntax, import aliases, builtins, Prelude values, and user
  shadowing.
- Verify exact resolver identity wins, same spelling in nested scopes remains
  distinct, writes receive `modification`, unresolved names emit nothing, and
  no unchecked AST is interpreted.
- Cover keywords, booleans, each comment/literal/operator family, punctuation
  exclusions, lexical errors, parse/resolution/type/effect failures, and exact
  whole-source fallback provenance without modifiers.
- Cover Chinese identifiers, emoji and combining prefixes, BOM, CRLF,
  multiline comments/text, source-byte slicing, nonempty splitting,
  non-overlap, deterministic ordering, repeated queries, and revision changes.
- Prove the result retains no compiler identity, source text, type/effect/
  capability metadata, path, URI, document version, position, LSP legend
  index, result ID, or partial transport state.

## Compatibility impact

- **Compiler/query:** adds internal `ling.semantic-token-generation/0.1` and
  one snapshot-keyed abstract token index; it does not change checked facts.
- **LSP/protocol:** no provider, method, capability, request/response, full/
  delta, result ID, or current public semantic-token protocol is added.
- **Diagnostics/schema/identity:** no `L-*` allocation, JSON schema, Semantic
  ID, Definition ID, or canonical-byte change.
- **Language/runtime/data:** no syntax, language semantics, Typed Core
  evaluation, interpreter, runtime, bytecode, VM, ABI, package, filesystem,
  network, dependency, or Unicode 17.0.0 table change.
- **Migration:** incompatible generation mode, evidence, mapping, modifier,
  fallback, span, order, privacy, or failure behavior requires a new marker and
  migration evidence.

## Unresolved alternatives

LSP provider negotiation, URI/document version, UTF-8/16/32 wire positions,
full/delta encoding, result IDs and bases, request policy, cancellation,
limits, freshness publication, fixture wire schema, Zed presentation, Stable
lifecycle, and general Semantic Transactions remain LSP-2403 through LSP-2504
work.

Mixed checked/error-region output and parsed fallback are rejected for 0.1
because the repository has no Accepted partial-analysis boundary that could
prove an AST node was checked. Custom Effect, Capability, resource, actor,
node, kernel, Semantic-ID, ownership, borrow, unsafe, and generated categories
remain excluded by RFC-0046.
