## Summary

This RFC defines the bounded scheduling contract required by LSP-2503. It
keeps JSON-RPC state transitions and responses in wire order, classifies
derived work as interactive, analysis, or background, retains deterministic
message-boundary diagnostic debounce, bounds logical priority bursts, and
cancels a diagnostic ticket when a newer accepted source state supersedes it.
The public marker is `ling.lsp.scheduling/0.1`.

本 RFC 定义 LSP-2503 所需的有界调度契约。JSON-RPC 状态转换与响应保持 wire
顺序；派生工作分为交互、分析与后台三类；诊断继续采用确定性的消息边界 debounce；
逻辑优先级 burst 有固定上限；较新的已接受源码状态会取消旧诊断 ticket。公开标记为
`ling.lsp.scheduling/0.1`。

## Normative changes

### 1. Discovery

Every successful initialize response MUST advertise this exact member at
`capabilities.experimental.lingScheduling`:

```json
{
  "classes": ["interactive", "analysis", "background"],
  "debounce": "message-boundary",
  "maxInteractiveBurst": 8,
  "maxNonBackgroundBurst": 16,
  "requestOrder": "wire-order",
  "supersession": "cancel-stale-analysis",
  "version": "ling.lsp.scheduling/0.1"
}
```

The marker adds no request, notification, client capability, configuration, or
dynamic registration. An incompatible class, bound, ordering, debounce,
supersession, or discovery change requires a new marker and migration evidence.

### 2. Work classes

The following Ready-state compiler work has a logical class:

| Class | Current methods or work |
| --- | --- |
| Interactive | hover, definition, declaration, type definition, references, prepare rename, rename, completion, completion resolve, and every otherwise unclassified request |
| Analysis | push diagnostic compilation, `textDocument/diagnostic`, `workspace/diagnostic`, semantic-token full, and semantic-token delta |
| Background | `workspace/symbol` index construction and filtering |

Lifecycle and document synchronization are ordered state barriers, not
reorderable analysis. Unknown future methods default to Interactive only for
internal admission; that default does not claim successful method support.
Classification MUST NOT change existing method parameters, results, errors,
cancellation, freshness, or atomic-publication rules.

### 3. Wire order and service order

The stdio reader MAY observe cancellation independently, but the one mutable
server executor MUST apply lifecycle and source messages and select request
responses in accepted wire order. Priority MUST NOT move a request across an
earlier state barrier, reorder two client requests, or let a dependent request
observe a future snapshot.

When complete pending push-diagnostic work and a Background request are both
ready at one executor boundary, Analysis MUST be serviced first. Interactive
request responses retain RFC-0032 response-before-caused-notification order and
MUST NOT wait for speculative Background index construction. No proactive
workspace index is required; a `workspace/symbol` request still performs its
own bounded RFC-0045 work synchronously.

### 4. Deterministic debounce and supersession

RFC-0032 message-boundary debounce remains authoritative: one accepted change
array is one mutation, multiple successful mutations before an explicit flush
coalesce to the newest complete state, and stdio performs one flush boundary
after each handled frame. No wall clock is observed and no latency promise is
created.

Each successful source or workspace mutation that marks diagnostics pending
MUST cancel the prior pending diagnostic ticket and install a fresh session-
local token for the new complete state. A ticket MUST check cancellation before
source traversal, at each source/stage boundary, through cancellable type/trait
checking, after adaptation, and immediately before ledger mutation. Cancelled
work returns no partial diagnostic collection, emits no notification, changes
no publication ledger, and leaves newer pending work intact. A result already
completed against an older snapshot retains RFC-0032 `Stale` rejection.

### 5. Bounded fairness

An internal ready-work queue MUST retain FIFO sequence within each class. When
multiple classes remain ready, it MAY prefer higher priority, but it MUST admit
one Analysis item after at most 8 consecutive Interactive selections and one
Background item after at most 16 consecutive non-Background selections. A
forced lower-class selection resets the relevant logical burst counter.

The counters and enqueue sequence are process-local, non-serialized values.
Selection depends only on class and enqueue order, never clock time, thread
identity, CPU count, host load, allocation, map iteration, path, or source text.
The stdio executor's wire-order rule takes precedence when only client requests
are ready; fairness does not authorize response reordering.

### 6. Failure, privacy, and limits

Sequence exhaustion remains a typed internal failure and MUST NOT wrap.
Cancelled, stale, compiler-failed, oversized, or transport-failed work MUST NOT
publish a partial result or an invented Ling diagnostic. Scheduling adds no
`L-<DOMAIN>-<NUMBER>` allocation. Class, counters, queue sequence, tokens,
revisions, request IDs, timing, paths, source bytes, compiler identities, and
Rust/debug values MUST NOT be serialized except the fixed discovery fields.

## Conformance plan

- Verify exact discovery fields and protocol fixture bytes.
- Verify class mapping, priority-before-FIFO selection, duplicate opaque work
  IDs, clear/sequence behavior, the 8-item Interactive bound, and the 16-item
  non-Background bound without sleeps or timing assertions.
- Verify JSON-RPC state and response wire order, response-before-caused-
  diagnostic publication, and Analysis-before-Background service.
- Cover multi-change batches, repeated mutations, cancelled old diagnostic
  tickets, stale completed results, current replacement/clearance, and no
  partial publication or checked-cache insertion.
- Cover lexical, parse, type, Trait, Effect, Unicode, BOM, CRLF, UTF-8/16/32,
  malformed messages, cancellation storms, repeat equality, and writer errors.
- Run locked offline workspace tests, strict Clippy, CI, governance, LSP,
  support, status, RC0, traceability, formatting, diff, and execution-plan
  checksum gates.

## Compatibility impact

- **Protocol:** adds Preview `ling.lsp.scheduling/0.1` discovery with no
  predecessor and no new JSON-RPC method.
- **LSP behavior:** retains request/state wire order and RFC-0032 debounce;
  adds fixed logical classes, bounded internal fairness, Analysis-before-
  Background service, and cooperative diagnostic supersession.
- **Compiler/query:** adds cancellable complete workspace diagnostics and uses
  the existing typed cancellation path; successful facts, keys, and spans are
  unchanged.
- **Diagnostics/schema/identity:** no Ling code, standalone schema, diagnostic
  shape, Semantic ID, Definition ID, or canonical-byte change.
- **Language/runtime/data:** no syntax, semantics, Typed Core evaluation,
  interpreter, runtime, bytecode, VM, ABI, package, filesystem/network, or
  Unicode 17.0.0 change.
- **Migration:** clients that ignore Experimental discovery are unchanged;
  incompatible scheduling behavior requires a new marker.

## Unresolved alternatives

Wall-clock timers, configurable debounce, deadline scheduling, dynamic
priority, host-load adaptation, worker pools, parallel mutable requests,
response reordering, progress, partial results, quotas, persistent indexes,
Stable lifecycle, and Semantic Transactions remain deferred. They require
separate accepted authority because they would introduce new timing, resource,
or compatibility behavior.
