# RFC-0026: Bounded LSP document formatting / 有界 LSP 文档格式化

> 状态：Accepted
> 类型：Standards Track<br>
> 创建日期：2026-08-23<br>
> 目标版本：v0.1 Preview<br>
> 作者/Owner role：ide-protocol-design<br>
> 相关缺口：GAP-FORMATTER-AUTHOR-SOURCE-001 | GAP-LSP-TRANSACTION-PROTOCOL-001<br>
> 生命周期记录：`docs/governance/lifecycle.toml`

## Summary

This RFC completes the bounded FMT-1507 formatter integration by adding
`textDocument/formatting` to the accepted synchronous `ling lsp --stdio`
server. The method formats exactly the current open writable overlay through
the existing compiler-CST formatter and returns zero or one whole-document LSP
`TextEdit` in the negotiated position encoding.

本 RFC 通过在同步 `ling lsp --stdio` 服务中增加
`textDocument/formatting`，完成有界的 FMT-1507 格式化集成。该方法只格式化
当前已打开且可写的覆盖文档，并通过现有编译器 CST 格式化器返回零个或一个使用
协商位置编码的整文档 LSP `TextEdit`。

The server never applies the returned edit. This extension does not define a
`WorkspaceEdit`, Semantic Transaction, range formatting, format-on-save,
filesystem read, parallel request execution, or Stable editor contract.

- Current lifecycle state: `Accepted`
- Stable implementation basis: `yes` for the Experimental

  - RFC-0004 lifecycle/transport, extended only by the method and capability below;

  - DEC-0002 and DEC-0029 position projection;

  - `ROADMAP-1.0.md` §5.2 and FMT-1507.

## Normative changes

### 1. Protocol and capability

The extension marker is `ling.lsp.formatting/0.1`. It is Experimental and
current-writer-only. A successful `initialize` response MUST advertise
`capabilities.documentFormattingProvider: true` in addition to the existing
capabilities. This field advertises only document formatting; clients MUST NOT
infer range formatting, on-type formatting, Workspace Edit, or format-on-save.

The extension adds exactly one method:

| Method | Kind | State | Result |
| --- | --- | --- | --- |
| `textDocument/formatting` | request | `Ready` | zero or one LSP `TextEdit` |

A notification with this method produces no response and no work. Lifecycle
errors retain RFC-0004 meanings. The server processes the request completely
and flushes its response before reading the next framed message.

### 2. Request parameters

`params` MUST be an object containing exactly:

```json
{
  "textDocument": {"uri": "ling://workspace/src/Main.ling"},
  "options": {"tabSize": 4, "insertSpaces": true}
}
```

Both nested objects and all four fields are required. Unknown fields,
`tabSize` other than integer `4`, or `insertSpaces` other than boolean `true`
return JSON-RPC `-32602`. Ling style is fixed by the accepted formatter and is
not client-configurable in this version.

The URI MUST satisfy RFC-0023 and identify a currently open writable workspace
or untitled overlay. A missing or closed document returns `-32602`. A dependency
document returns the existing bilingual read-only error `-32005`. Invalid URI
forms return `-32006`. Rejection MUST NOT mutate text, version, or VFS revision.

### 3. Snapshot and formatter boundary

Formatting consumes the immutable VFS snapshot and client document version
current when the request is dispatched. Because the accepted server is
single-threaded and writes the response before accepting another message, no
later `didChange` may race this request inside the server. A later change makes
the earlier response obsolete at the client; this RFC adds no cross-request
transaction or server-side application mechanism.

The implementation MUST construct the existing `SourceFile`, parse it with the
compiler lexer/parser, build the existing compiler-CST `FormatDocument`, and
call `format_core_edit`. It MUST NOT introduce an LSP parser, regex formatter,
Tree-sitter semantic path, unchecked AST evaluator, or alternate style engine.

An invalid/recovery source, rejected candidate, or unchanged valid source
returns an empty array. A changed safe candidate returns exactly one edit. The
server MUST NOT update the overlay, client version, VFS revision, disk, project,
lock, cache, Semantic Graph, Semantic ID, Audit bytes, or runtime state.

### 4. TextEdit projection

The single result edit has exactly `range` and `newText`. `range.start` is
`{line: 0, character: 0}`. `range.end` is the original document end projected
through DEC-0029 in the encoding negotiated at initialize. Lines and characters
are zero-based. The edit range is measured against the exact request snapshot.

`newText` is the exact accepted formatter replacement. If the original source
has a leading UTF-8 BOM, LSP position zero denotes the first lexical scalar
after that BOM; therefore the adapter preserves the existing BOM outside the
edit and removes exactly one leading BOM from `newText`. It neither creates nor
duplicates a BOM. CRLF source ranges are projected from original bytes while
the existing formatter continues to emit its accepted LF output.

No `annotationId`, document version, URI, metadata, extension field, minimal
diff, or second edit is emitted. Field and array ordering are deterministic
under the existing compact JSON writer, but consumers MUST interpret JSON
structurally rather than depend on object-key byte order.

### 5. Failures and compatibility

Malformed parameters and document state use the errors above. An impossible
internal source, formatter, or position-projection failure returns JSON-RPC
`-32603` with the bilingual message
`文档格式化失败 / document formatting failed`. It exposes no path, Rust error,
debug representation, allocation identity, or partial edit. These JSON-RPC
errors are not Ling compiler diagnostics and allocate no `L-*` code.

Incompatible request/result fields, option meanings, edit cardinality, or
snapshot behavior require a new extension version and migration evidence.

## Conformance plan

- Verify initialization advertises only the implemented document-formatting
  capability and retains all lifecycle/overlay fields.
- Format Unicode source under UTF-8, UTF-16, and UTF-32 and assert exact hard-
  coded end positions, replacement bytes, response IDs, and zero mutation.
- Verify BOM preservation, CRLF projection, latest prior overlay version,
  repeated-call determinism, and one-edit cardinality.
- Verify unchanged, invalid, and recovery sources return no edits.
- Reject closed, missing, dependency, invalid-URI, malformed-option, extra-field,
  preinitialize, post-shutdown, and notification forms without mutation.
- Retain formatter idempotence, semantic-equivalence, comment, Audit separation,
  LSP framing, overlay, position, workspace, offline, and determinism suites.

## Compatibility impact

- **Source/language:** no syntax, type, Effect, runtime, or Unicode rule changes.
- **Formatter:** reuses accepted Author Source behavior; no new style rule.
- **LSP:** adds one Experimental method, capability, and marker. Existing
  lifecycle and overlay methods remain byte/meaning compatible.
- **Diagnostics:** no `L-*` allocation; only standard JSON-RPC `-32603` is added
  for fail-closed internal projection.
- **Semantic IDs/Audit:** unchanged; formatter publication remains disjoint.
- **Data/ABI:** no disk write, artifact, schema file, Rust ABI, or host-path claim.
- **Determinism:** response depends only on the negotiated encoding and current
  immutable overlay bytes; no clock, environment, filesystem, or map order.
- **Migration:** no predecessor. Future incompatible behavior requires a new
  marker and explicit migration guidance.

## Unresolved alternatives

- Configurable style and optional LSP formatting fields are deferred until
  accepted style semantics and compatibility evidence exist.
- Minimal/token edits and range/on-type formatting are deferred because they
  require independently safe CST regions and overlap rules.
- `WorkspaceEdit`, versioned multi-document edits, Semantic Transactions,
  cancellation, asynchronous publication, and format-on-save remain open under
  `GAP-LSP-TRANSACTION-PROTOCOL-001` and
  `GAP-SEMANTIC-PROTOCOL-LIFECYCLE-001`.
- A future filesystem-backed LSP workspace may format closed files only after
  accepted URI/root/project and freshness rules exist.
