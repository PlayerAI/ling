## Summary

This RFC defines the first bounded CLI surface for Semantic Query and Semantic
Transaction. `ling query --symbol NAME SOURCE` performs an exact NFC symbol
lookup over one checked file program. `ling patch TRANSACTION SOURCE` validates
one full-source replacement proposal against the current Program ID and
declared semantic-preservation constraints.

本 RFC 定义首个有界的 Semantic Query 与 Semantic Transaction 命令行接口。
`ling query --symbol NAME SOURCE` 在单个已检查文件程序中执行精确 NFC 符号查询；
`ling patch TRANSACTION SOURCE` 根据当前 Program ID 和声明的语义保持约束验证一个
整文件替换提案。

Both commands are offline and deterministic. Query is read-only. Patch has only
`Graph.Read` and `Graph.Propose` authority: it never writes the source, applies
an edit, runs code/tests, or claims `Graph.Commit`. A future commit operation
requires separate Accepted atomic-publication authority.

  - exact NFC lookup of checked user definitions by identifier;

## Normative changes

### 1. Command forms and selection

The implementation adds exactly these forms:

```text
ling query --symbol NAME [OUTPUT] SOURCE
ling patch [OUTPUT] TRANSACTION SOURCE
```

`SOURCE` MUST be one explicit filesystem path ending in `.ling` and MUST NOT be
`-`. `TRANSACTION` MUST be one distinct explicit filesystem path ending in
`.json` and MUST NOT be `-`. Neither command searches parent directories,
loads a project manifest, reads environment configuration, uses the network,
or writes any file. Filesystem link resolution retains ordinary host file-read
behavior and is not a Ling semantic guarantee in this version.

The checked program MUST contain exactly one non-Prelude module and no imports.
This restriction makes the replacement input complete and prevents an
unversioned project-selection convention. Invalid command shape is usage exit
`2`. Source compilation failures retain their registered diagnostics and exit
`3`; internal and snapshot failures retain existing exits `70` and `4`.

### 2. Semantic Query 0.1

The response protocol is `ling.semantic-query/0.1`. `NAME` MUST be a valid
Unicode 17.0.0 Ling identifier and is compared after the authoritative NFC
normalization. Matching considers only definitions whose `origin` is `user`.
The result array retains canonical Semantic Graph definition order and each
item contains exactly:

```text
definition_id, body_id, module, name, kind, type, effects, capabilities
```

The response also contains `schema`, `semantic_schema`, `language_version`,
`unicode_version`, `program_id`, normalized `symbol`, and `matches`. Zero
matches is a successful empty result. Query MUST NOT evaluate Checked Core,
mutate compiler/VFS/filesystem state, expose paths or spans, or synthesize
facts outside the checked Semantic Graph.

Human output is a deterministic bilingual summary followed by one stable line
per result. JSON output is a deterministic compact protocol object plus LF;
version 0.1 does not claim canonical byte encoding.

### 3. Semantic Transaction 0.1 input

The request protocol is `ling.semantic-transaction/0.1`. The JSON object MUST
contain exactly:

```json
{
  "schema": "ling.semantic-transaction/0.1",
  "base_program_id": "experimental:blake3:...",
  "target_ids": ["experimental:blake3:..."],
  "operation": {"kind": "replace_source", "content": "module Main\n..."},
  "preserve": ["definition_set", "types", "effects", "capabilities"],
  "provenance": {"actor": "...", "reason": "..."}
}
```

Unknown or duplicate fields are rejected. `target_ids` MUST be non-empty,
unique, byte-sorted, and identify current user definitions. `preserve` MUST be
non-empty, unique, in the exact canonical order shown above, and MUST include
all four values in version 0.1. Actor and reason MUST be non-empty UTF-8 text
of at most 128 and 512 bytes respectively. Content MUST be non-empty, valid
Ling source within the compiler's existing source-size limit. Input files are
bounded to 1 MiB before decoding.

### 4. Validation and preserve semantics

Patch MUST execute in this order:

1. compile `SOURCE` through the existing checked pipeline;
2. reject unless `base_program_id` exactly equals its Program ID;
3. validate every target against the current checked user-definition set;
4. compile the replacement content in memory under the same logical source;
5. compare current and candidate canonical Semantic Graph definitions;
6. reject unless the complete definition-ID set is unchanged;
7. reject any type, Effect, or Capability change;
8. compute definitions whose Body ID changed and reject unless the set is
   non-empty and every changed ID is listed in `target_ids`;
9. emit the validated proposal report.

All comparisons are structural, not rendered-text comparisons. Prelude
definitions participate in preservation but cannot be targets. Compiler
diagnostics from the candidate are emitted unchanged. A transaction-level
rejection emits one registered bilingual transaction diagnostic and no
successful report; ordinary candidate compiler warnings retain their existing
behavior.

The successful report protocol is `ling.semantic-transaction-result/0.1` and
contains exactly `schema`, `transaction_schema`, `status` (`validated`),
`committed` (`false`), `base_program_id`, `candidate_program_id`, sorted
`target_ids`, sorted `changed_body_ids`, canonical `preserved`, and the supplied
provenance. It MUST NOT contain source content or a compiler-derived host path;
provenance is caller-supplied audit text and MUST be treated as untrusted data.

### 5. Nonmutation, capabilities, and compatibility

Patch validation grants only `Graph.Read` and `Graph.Propose`. Success and every
failure MUST leave source bytes, metadata, directories, compiler inputs, and
runtime state unchanged. The command does not run `main`, tests, benchmarks,
or proofs. It does not emit or apply an edit.

Incompatible request/result fields, ordering, constraint meaning, selection,
or authority require a new protocol version and migration evidence. Version
0.1 readers reject unknown core fields. No compatibility bridge to LSP exists.

## Conformance plan

- Query exact ASCII, NFC-equivalent, Unicode, zero-match, multi-match, invalid-
  identifier, imported/multi-module, malformed-option, human/JSON, ordering,
  repeat-process, and nonmutation cases.
- Patch valid body-only change, stale base, malformed/oversized JSON, duplicate
  or unordered targets, missing/unknown constraints, invalid targets, empty or
  unchanged changes, candidate compiler failure, definition/type/effect/
  capability drift, unauthorized body change, Unicode/CRLF, deterministic
  report, and exact input nonmutation cases.
- Validate query/request/result schemas with valid, invalid, and canonical
  fixtures; register both protocols and all version markers.
- Retain workspace tests, Clippy, CI, governance, support, status, RC0,
  traceability, rustfmt, offline, and deterministic-diff gates.

## Compatibility impact

- **Source/language:** no syntax, type, Effect, Capability, ownership, runtime,
  or evaluation rule changes.
- **CLI:** adds two Preview roots and `--symbol`; existing commands/options and
  exits are unchanged.
- **Diagnostics:** adds transaction-input, stale-base, and preserve-violation
  codes; existing code meaning is unchanged.
- **Schemas:** adds one query response, one transaction request, and one result
  schema, all version 0.1 and current-reader-only.
- **Semantic IDs:** consumes DEC-0012 IDs without changing their canonical bytes
  or algorithm.
- **Data/ABI:** no source write, artifact, cache, binary ABI, or path field.
- **Determinism/Unicode:** fixed by canonical graph order and Unicode 17.0.0;
  no clock, environment, map order, or random input participates.
- **Migration:** no predecessor; incompatible changes require new versions.

## Unresolved alternatives

- Project/workspace query and patch require accepted package selection and
  multi-file transaction identity.
- Search expressions, reference traversal, pagination, fuzzy matching, rename,
  partial/source-range edits, and formatter-aware edits remain future work.
- `Graph.Commit`, atomic disk publication/rollback, LSP `WorkspaceEdit`,
  delegated capabilities, required tests, benchmarks, proofs, contracts, ABI,
  and Stable lifecycle remain blocked by the open transaction gaps.
