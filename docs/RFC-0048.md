## Summary

This RFC defines the bounded Preview LSP transport required by LSP-2403. The
transport projects RFC-0047's snapshot-bound abstract tokens through RFC-0046's
client-selected legend and the negotiated position encoding, publishes standard
LSP 3.17 full and delta responses, retains a bounded session-local result
history, and rejects stale or partial publication. Its public marker is
`ling.lsp.semantic-tokens/0.1`.

本 RFC 定义 LSP-2403 所需的有界 Preview LSP 传输。传输按照 RFC-0046 的客户端选择
legend 和协商后的位置编码，投影 RFC-0047 的快照绑定抽象 token，发布标准 LSP 3.17
full 与 delta 响应，保留有界的会话内结果历史，并拒绝陈旧或部分发布。公开版本标记为
`ling.lsp.semantic-tokens/0.1`。

## Status and scope

- Current lifecycle state: `Accepted`.
- Stable implementation basis: `yes` for this Preview protocol revision.
- In scope:
  - static initialize negotiation and exact provider discovery;
  - `textDocument/semanticTokens/full` and
    `textDocument/semanticTokens/full/delta`;
  - relative integer encoding in negotiated UTF-8, UTF-16, or UTF-32 units;
  - deterministic result identities, bounded retention, delta-base validation,
    canonical edits, full fallback, cooperative cancellation, freshness, and
    response limits.
- Out of scope:
  - range requests, dynamic registration, refresh, partial results, work-done
    progress, and wire `$/cancelRequest`;
  - persistent or cross-session result IDs, client-configurable retention,
    multi-edit optimization, or Semantic Transaction identity;
  - new token categories, mixed checked/error-region generation, language
    semantics, diagnostics, filesystem discovery, or editor presentation.
- Normative dependencies: RFC-0047, RFC-0046, RFC-0004, RFC-0023, RFC-0029,
  RFC-0030, DEC-0002, DEC-0012, DEC-0019, DEC-0029, DEC-0031, DEC-0071,
  DEC-0084, DEC-0085, DEC-0086, and DEC-0087.

## Normative changes

### 1. Protocol identity and capability parsing

The protocol marker is `ling.lsp.semantic-tokens/0.1`. A provider MAY be
enabled only when `capabilities.textDocument.semanticTokens` is an object that:

- contains `requests` as an object and `requests.full` as `true` or an object;
- contains `tokenTypes`, `tokenModifiers`, and `formats` as arrays of strings;
- includes `relative` in `formats`; and
- produces a nonempty selected type legend under RFC-0046 §5.

If present, `requests.full.delta` and the standard boolean members
`dynamicRegistration`, `overlappingTokenSupport`, `multilineTokenSupport`,
`serverCancelSupport`, and `augmentsSyntaxTokens` MUST have their standard
types. `requests.range` MUST be a boolean or object when present. A malformed
known member makes initialize fail with `-32602`; ordinary unknown members and
unknown string values in capability arrays are ignored. Duplicates do not
change RFC-0046 canonical legend order.

The server uses static registration only. If enabled, initialize MUST advertise:

```json
"semanticTokensProvider": {
  "full": {"delta": true},
  "legend": {"tokenTypes": [], "tokenModifiers": []},
  "range": false,
  "workDoneProgress": false
}
```

The arrays are the exact RFC-0046 selected legends. `full.delta` is `true`
only when the client supplied `requests.full` as an object with `delta: true`;
otherwise it is `false`. Discovery MUST also include:

```json
"lingSemanticTokens": {
  "delta": true,
  "generation": "ling.semantic-token-generation/0.1",
  "maxDataElements": 163840,
  "maxRetainedResults": 32,
  "positionEncoding": "utf-16",
  "taxonomy": "ling.semantic-token-taxonomy/0.1",
  "version": "ling.lsp.semantic-tokens/0.1"
}
```

`delta` and `positionEncoding` contain the negotiated values. The server MUST
omit both provider and discovery when the provider is not enabled.

### 2. Requests and lifecycle

The provider adds exactly these standard requests:

| Method | Required parameters | Result |
| --- | --- | --- |
| `textDocument/semanticTokens/full` | `textDocument.uri` string | `SemanticTokens` |
| `textDocument/semanticTokens/full/delta` | `textDocument.uri` string and `previousResultId` string | `SemanticTokensDelta` or `SemanticTokens` |

The URI MUST be nonempty, contain no NUL, and be at most 4096 UTF-8 bytes.
`previousResultId` MUST be nonempty, contain no NUL, and be at most 80 UTF-8
bytes. Unknown parameter members, including progress tokens, are ignored.
Invalid parameter shape or value returns `-32602`. A notification performs no
work and emits no response.

The full method is unavailable with `-32601` when no provider was advertised.
The delta method is unavailable with `-32601` unless delta support was
advertised. Existing RFC-0004 lifecycle failures retain their codes and
bilingual messages.

### 3. Immutable document snapshot

Each request MUST capture one complete immutable `RequestSnapshot`, select the
exact tracked document by URI, and generate tokens from that snapshot only. It
MAY serve an open overlay, tracked closed disk document, dependency document,
or requested temporary document already present in the snapshot. It MUST NOT
read the filesystem, discover an untracked document, or combine revisions.

The compiler adapter MUST use the exact captured bytes and workspace inputs.
RFC-0047 generation MUST bind to the compiler source corresponding to the
selected document. Immediately before success, the handler MUST recapture the
complete snapshot and require equality with the original capture. For an open
document this equality includes the same client document version. A change
causes atomic `-32803`; no result or history mutation is published.

### 4. Legend projection and relative encoding

Each RFC-0047 entry is projected through the RFC-0046 selected type and
modifier legends. A directly supported type keeps its type. An unsupported
type uses RFC-0046's first supported fallback or is omitted. Unsupported
modifiers are omitted; supported modifiers retain canonical order and set the
corresponding legend bits.

Every retained line-local span MUST project through DEC-0029 in the negotiated
position encoding. Start and end MUST be on the same line and produce a
positive length. Entries MUST remain strictly source ordered and nonoverlapping
after projection. Invalid source identity, boundary, position, order, overlap,
length, type index, or modifier mask fails the request atomically.

The `data` array uses standard relative groups of five unsigned integers:
`deltaLine`, `deltaStart`, `length`, `tokenType`, and `tokenModifiers`.
`deltaStart` is relative to the previous token start only on the same line;
otherwise it is the absolute start character. The first token is relative to
line and character zero. No group may be partial.

### 5. Result identity and bounded history

Every successful full computation has a lowercase opaque result ID of the form
`st1-` followed by 64 hexadecimal BLAKE3 digits. Its canonical hash input
contains only the protocol marker, exact request URI, open-document version or
closed-document sentinel, negotiated position encoding, selected legend
strings, and complete encoded `data` array with explicit lengths. It MUST NOT
contain or hash source text, VFS revisions, internal query keys, paths,
Definition IDs, Semantic IDs, types, Effects, Capabilities, diagnostics, debug
text, allocation, timing, or addresses.

Equal client-visible inputs produce the same result ID. A collision with an
unequal retained value is a request failure. Result IDs are session-local
capabilities, not persistent content identities or cross-session promises.

The server retains at most 32 distinct successful results globally. Each entry
contains only result ID, URI, selected protocol identity, and encoded data.
Insertion order is FIFO; reusing an equal retained result does not reorder it.
Publishing a 33rd distinct result evicts the oldest. Failed, cancelled, stale,
or oversized work MUST NOT mutate history.

### 6. Delta validation and canonical edit

A delta base is valid only when the exact `previousResultId` is retained for the
same URI and current selected protocol identity. Missing, expired, foreign-URI,
or otherwise invalid bases MUST return a complete `SemanticTokens` result, not
an error and not a guessed delta.

For a valid base, compare the previous and current unsigned-integer arrays.
Retain the longest equal prefix, then the longest equal suffix that does not
cross that prefix. The canonical delta contains exactly one edit replacing the
remaining previous middle with the remaining current middle. Its `start` and
`deleteCount` are element offsets in the previous array. Omit `data` when the
inserted middle is empty. Equal arrays return an empty `edits` array. Applying
the response edits to the exact base MUST reproduce the current full array.

If the canonical delta response exceeds the transport limit but the full
response fits, the server returns full. No alternative multi-edit optimizer is
part of 0.1.

### 7. Cancellation, freshness, bounds, and failures

The handler MUST accept the existing DEC-0031 cooperative cancellation token
and check it before compiler work, while projecting entries and constructing a
delta, and immediately before publication. Cancellation returns standard
RequestCancelled `-32800` with
`语义 Token 查询已取消 / semantic token query cancelled`. The synchronous
stdio loop still does not claim wire `$/cancelRequest`.

At most 32,768 tokens and 163,840 integer elements may be encoded. A response
MUST fit RFC-0004's 1 MiB frame bound. Compiler, source, projection, identity,
collision, limit, or freshness failure returns RequestFailed `-32803` with
`语义 Token 不可用 / semantic tokens unavailable`. Such failures produce no
partial result, Ling diagnostic, cache update, document mutation, or source
repair.

### 8. Privacy and compatibility boundary

Wire output contains only standard token integers and the opaque result ID.
Generation mode and evidence provenance remain internal and are not encoded as
types, modifiers, fields, or identity material. Host paths, source text,
compiler identity, Semantic IDs, Definition IDs, type/effect/capability facts,
and Rust/debug data MUST NOT enter responses or retained results.

## Conformance plan

- Verify exact all/partial/empty legends, standard/custom modifier selection,
  type fallbacks, malformed known capabilities, ignored unknown members,
  full-only and full-plus-delta discovery, and disabled methods.
- Cover full encoding in UTF-8/UTF-16/UTF-32 with Chinese, emoji, combining
  prefixes, BOM, LF, CRLF, multiline comments/text, omitted categories,
  deterministic order, non-overlap, and exact relative groups.
- Cover insertion, deletion, replacement, and reorder deltas; equal arrays;
  invalid, expired, foreign-URI, and collision bases; FIFO eviction; full/delta
  equivalence; and deterministic result IDs and bytes.
- Verify overlays, closed and temporary documents, repeated snapshots,
  document/dependency edits, stale recapture, cancellation at each observable
  boundary, compiler failures, token/data/frame limits, and atomic history.
- Prove no source bytes, revision, compiler/Semantic/Definition identity,
  type/effect/capability data, paths, diagnostics, or debug text enters the
  result ID, response, or retained history.
- Run exact protocol fixtures plus locked offline workspace tests, strict
  Clippy, CI, governance, LSP, support, status, RC0, traceability, formatting,
  diff, and execution-plan checksum gates.

## Compatibility impact

- **LSP/protocol:** adds Preview `ling.lsp.semantic-tokens/0.1`, one static
  provider, two standard LSP 3.17 request methods, full and delta response
  shapes, and a disposable bounded session history. There is no predecessor.
- **Compiler/query:** consumes RFC-0047's immutable index without changing its
  query identity, checked facts, fallback, spans, or cache semantics.
- **Diagnostics/schema/identity:** adds no `L-*` allocation, standalone JSON
  schema, Semantic ID, Definition ID, or canonical-byte change. JSON-RPC errors
  remain transport errors.
- **Language/runtime/data:** no Ling syntax or semantics, Typed Core evaluation,
  interpreter, runtime, bytecode, VM, ABI, package, filesystem/network, or
  Unicode 17.0.0 table change.
- **Migration:** incompatible capability, legend, encoding, result-ID, history,
  delta, failure, limit, privacy, or freshness behavior requires a new protocol
  marker and migration evidence.

## Unresolved alternatives

Range tokens, refresh, dynamic registration, partial/work-done results, wire
`$/cancelRequest`, asynchronous scheduling, configurable limits, persistent
history, multiple optimized edits, mixed checked/error-region generation,
Stable lifecycle, editor presentation, and general Semantic Transactions remain
future work.
