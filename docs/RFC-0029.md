# RFC-0029: LSP incremental document changes / LSP 增量文档变更

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-23
> 目标版本：v0.2 Experimental
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC extends the accepted full-text overlay with bounded, ordered,
failure-atomic incremental changes. It closes only LSP-2104 and does not define
compiler request snapshots, diagnostics, Workspace Edits, or Semantic
Transactions.

本 RFC 为已接受的全文覆盖层增加有界、有序且失败原子的增量变更；它只关闭
LSP-2104，不定义编译器请求快照、诊断、Workspace Edit 或 Semantic Transaction。

## Summary

`ling.lsp.overlay/0.2` accepts one to 64 `contentChanges` entries in protocol
order. Each entry is either an exact full replacement or a range replacement
measured in the encoding selected during initialize. All entries are applied
to immutable local source snapshots; the VFS and client version are published
once only after the complete batch succeeds.

## Status and scope

- Current lifecycle state: `Accepted`
- Stable implementation basis: `yes` for this Experimental/current-writer-only
  extension
- In scope:
  - `ling.lsp.overlay/0.2` and explicit incremental-sync advertisement;
  - ordered full/range change batches of one through 64 entries;
  - range projection through the negotiated UTF-8, UTF-16, or UTF-32 encoding;
  - immutable per-entry source-map rebuilding and one final VFS publication;
  - version, URI, state, writability, range, boundary, size, and failure-
    atomicity rules;
  - equivalence with the corresponding full replacement.
- Out of scope:
  - save notifications, host files, project reload, compiler query scheduling,
    request snapshots, stale analysis results, diagnostics, cancellation,
    Workspace Edits, Semantic Transactions, and Stable compatibility.
- Normative dependencies:
  - RFC-0004 lifecycle/transport;
  - RFC-0023 full-text overlay and URI/version policy;
  - DEC-0002 original-byte authority;
  - DEC-0029 negotiated position projection;
  - DEC-0069 immutable UTF-8 edits;
  - DEC-0070 ordered position-edit projection.

## Normative changes

### 1. Protocol revision and capability

The current overlay marker becomes `ling.lsp.overlay/0.2`. Initialize success
MUST advertise:

```json
{
  "capabilities": {
    "experimental": {
      "lingOverlay": {
        "changeLimit": 64,
        "version": "ling.lsp.overlay/0.2"
      }
    },
    "textDocumentSync": {
      "change": 2,
      "openClose": true
    }
  }
}
```

These fields extend the other Accepted capability fields. `change: 2` means
incremental synchronization. The negotiated `positionEncoding` remains the
sole unit for every range. Version 0.2 continues accepting the version-0.1
single full-replacement form; no 0.1 reader or separate server mode exists.

### 2. Change envelope

`didChange.params` MUST contain `textDocument.uri`, a non-negative version
strictly greater than the open document version, and `contentChanges` with one
through 64 entries. Empty or larger arrays are invalid. URI, open state,
writability, and version are validated before any edit work.

Every entry MUST be an object with a UTF-8 JSON string `text` no larger than
1 MiB. `rangeLength` is rejected in all forms. Unknown ordinary JSON fields
remain ignored consistently with the Preview parser.

- Without `range`, the entry replaces the complete current snapshot.
- With `range`, the value MUST contain `start` and `end`; each position MUST
  contain non-negative `line` and `character` integers representable as `u32`.
  The half-open range is measured against the snapshot produced by the
  preceding entry using the initialize-selected encoding.

Full and ranged entries MAY be mixed. They are applied exactly in array order;
a later range therefore observes every preceding replacement. Before each
ranged entry, the server rebuilds the source map and line index for the current
snapshot. The array order is semantic and MUST NOT be sorted or coalesced.

### 3. Projection, validation, and bounds

Each ranged entry is converted through DEC-0029's `SourceFile`/`SourceMap`
API and applied through DEC-0069/DEC-0070. Lines outside the source, characters
beyond a line, UTF-8 scalar interiors, UTF-16 surrogate interiors, reversed
ranges, invalid BOM placement introduced by a range, and a current snapshot
that cannot be projected as a Ling `SourceFile` are rejected without clamping.
CRLF is one normalized lexical newline, so positions before and after it map
through `SourceMap` without exposing either original interior byte as an editor
boundary.

A full replacement retains RFC-0023 behavior: its exact UTF-8 JSON string is
accepted even while the editor buffer is not a valid Ling source snapshot. A
later ranged entry in the same or a subsequent change requires that current
buffer to admit DEC-0029 projection. Failure is atomic for the entire batch.

After every entry, the exact original UTF-8 result MUST be no larger than
1 MiB. Position lines use the BOM-free, LF-normalized lexical view, while the
result preserves exact original BOM and CRLF bytes. Successful ranged
transformations preserve the session-local source ID and logical name and
rebuild their source map and line index.

### 4. Atomic publication and errors

The server holds the evolving bytes locally and constructs immutable
`SourceFile` values for ranged transformations. It MUST NOT mutate the VFS,
document version, last-version history, or visible bytes until all entries and
the final size have succeeded. It then publishes the final exact bytes as one
overlay update and records the new client version.

Stale versions retain RFC-0023 error `-32004`; read-only dependencies retain
`-32005`; invalid URIs retain `-32006`. Malformed arrays, positions, ranges,
boundaries, replacement results, or sizes return JSON-RPC `-32602` with a
stable bilingual message for request-form conformance probes. Notifications
remain response-free on both success and failure. No Ling compiler diagnostic
code is allocated.

### 5. Explicit non-claims

VFS publication establishes only the visible document snapshot. This RFC does
not define compiler request identity, analysis cancellation, stale-result
publication, diagnostic triggers, Workspace Edit atomicity, disk writes, or a
Semantic Transaction. Those remain governed by later tasks and gaps.

## Conformance plan

- Cover ordered multi-range batches, mixed full/range batches, UTF-8/16/32,
  Chinese text, emoji, combining marks, BOM, CRLF, newlines, and line-index
  rebuilding after preceding edits.
- Compare incremental batches with exact full replacement across a table of
  source/range/replacement cases and repeated runs.
- Reject empty and over-limit arrays, malformed positions, rangeLength,
  reversed/out-of-bounds/scalar/surrogate ranges, CRLF boundary transitions, invalid BOM
  results, oversized intermediate/final text, stale versions, closed files,
  and dependency edits.
- For every failed batch, compare visible bytes, client version, VFS revision,
  and last-version behavior before and after failure.
- Verify exact capability fields and retain RFC-0023 full-change compatibility.
- Run workspace, CI, governance, support, status, RC0, traceability, Clippy,
  formatting, locked/offline, and deterministic-diff gates.

## Compatibility impact

- **LSP:** advances the Experimental overlay marker from 0.1 to 0.2, adds
  explicit incremental-sync capabilities, accepts range/multi-change inputs,
  and retains the 0.1 single-full-change form.
- **Migration:** no tool is needed because the 0.2 server accepts every valid
  0.1 change message. Clients discover 0.2 and incremental support from
  initialize capabilities; incompatible future changes require another marker.
- **Diagnostics:** no `L-*` allocation; existing JSON-RPC errors are reused.
- **Language/compiler:** no syntax, semantics, Checked Core, Semantic ID,
  source-span, runtime, bytecode, VM, ABI, or package change.
- **Filesystem/network:** none; edits are session-local and path-free.
- **Determinism/Unicode:** protocol order is explicit, publication is singular,
  source maps are rebuilt deterministically, and Unicode remains 17.0.0.

## Unresolved alternatives

Concurrent changes, version vectors, rangeLength validation, save semantics,
host-file resolution, project reload, compiler snapshots, diagnostics,
cancellation, Workspace Edits, Semantic Transactions, and Stable compatibility
remain deferred. Parallel or coalesced batch application is rejected because
it would change protocol-order semantics.

## Supersession

- Supersedes: `None`; this is a backward-compatible extension of RFC-0023.
