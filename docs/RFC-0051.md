## Summary

This RFC defines deterministic hard limits for the current Preview LSP. It
bounds transport bodies, individual and aggregate open-overlay bytes, live
request associations, completion results, diagnostic results, and Trait solver
nesting. It also allocates one bilingual tool diagnostic and an exact discovery
marker. The public marker is `ling.lsp.resource-limits/0.1`.

本 RFC 为当前 Preview LSP 定义确定性的硬上限，包括传输 body、单文档及聚合打开
overlay 字节、live request 关联、completion 结果、diagnostic 结果以及 Trait solver
嵌套深度；同时分配一个双语工具诊断与精确 discovery marker。公开标记为
`ling.lsp.resource-limits/0.1`。

- Current lifecycle state: `Accepted`.
- Stable implementation basis: `yes` for this Preview protocol revision.
- In scope:
  - fixed units, accounting scopes, hard limits, precedence, cleanup, retry,

  - aggregate accounting for accepted open overlays;
  - admission accounting for queued or executing requests with cancellable IDs;

## Normative changes

### 1. Discovery and fixed limits

Every successful initialize response MUST advertise this exact member at
`capabilities.experimental.lingResourceLimits`:

```json
{
  "completionItemsPerRequest": 256,
  "diagnosticDefaultPerDocument": 100,
  "diagnosticDefaultPerWorkspace": 1000,
  "diagnosticHardMaxPerDocument": 4096,
  "diagnosticHardMaxPerWorkspace": 65536,
  "documentBytes": 1048576,
  "errorCode": "L-LSP-0002",
  "liveRequests": 128,
  "openDocumentBytes": 8388608,
  "solverNestedObligations": 64,
  "transportFrameBytes": 1048576,
  "unit": "utf8-bytes-and-counts",
  "version": "ling.lsp.resource-limits/0.1"
}
```

All listed limits are hard bounds. Only diagnostic retained-result limits MAY
be lowered through the already accepted `lingDiagnosticControl`
initialization option; the advertised default fields remain defaults and the
hard-max fields remain maxima. All other limits are fixed for this revision
and are not configurable. An incompatible unit, scope, value, precedence,
failure shape, or configuration rule requires a new marker and migration
evidence.

### 2. Byte accounting

`documentBytes` counts the exact UTF-8 bytes of one open-overlay JSON string
after JSON decoding and before source normalization. `openDocumentBytes` counts
the sum of those exact bytes for every accepted open overlay in one server session,
including writable workspace, read-only dependency, and untitled documents.
Closed disk snapshots, workspace inputs, generated artifacts, response buffers,
caches, allocator overhead, and duplicate backing storage are excluded.

`didOpen` MUST reserve the full decoded text length before publishing a new
overlay. `didChange` MUST validate and construct the complete candidate first,
then atomically reserve or release the difference from the current overlay.
`didClose` MUST release the exact visible overlay length even when a disk
snapshot remains. An exact-boundary reservation succeeds. Arithmetic overflow
or a value above either byte limit fails without changing bytes, version,
revision, document state, diagnostics, cache state, or accounting.

### 3. Live request admission

A live request is a structurally recognized JSON-RPC message with a string or
number ID that has been accepted by the stdio router and has not completed.
Queued and executing requests count; notifications, responses, malformed IDs,
duplicate rejected IDs, and resource-rejected requests do not. At most 128
live request associations may exist in one server session.

Cancellation notifications are routed first. For a new request ID, exact live
duplicate detection precedes the live-request limit. A duplicate returns the
existing Invalid Request response. A distinct 129th live request is rejected
before creating a cancellation token or queue-owned association. Completion,
cancellation, transport failure, executor shutdown, or dropped queued work MUST
release every accepted association exactly once. A later request MAY retry
after capacity is available; no ordering priority or eviction is implied.

### 4. Existing bounded result and solver composition

One completion response retains the RFC-0042 maximum of 256 items. Diagnostic
publication retains the accepted configurable defaults of 100 per document and
1,000 per workspace and hard maxima of 4,096 and 65,536 respectively; omitted
roots continue to use `L-LSP-0001`. Transport request and response bodies remain
bounded to 1,048,576 bytes and partial oversized responses remain forbidden.

RFC-0005 §2.5 remains the sole language authority for the 64 nested-obligation
Trait solver bound. LSP advertises that existing bounded static-checking fact
but MUST NOT introduce an LSP-only solver result, accept a program rejected by
another compiler entry point, or reinterpret its original source diagnostic.
The source-size, grammar, cycle, and nesting restrictions together keep the
current solver input finite; a future total-work/fuel metric requires a
language-wide Accepted compiler RFC rather than an editor-only semantic fork.

### 5. Resource-limit failure

`L-LSP-0002` means only that an LSP-owned hard resource limit was exceeded. A
request-form failure MUST use JSON-RPC code `-32803`, the bilingual message
`资源上限已超出 / resource limit exceeded`, and this exact `error.data` shape:

```json
{
  "code": "L-LSP-0002",
  "facts": {
    "actual": 129,
    "maximum": 128,
    "resource": "live_requests",
    "scope": "session"
  },
  "version": "ling.lsp.resource-limits/0.1"
}
```

`actual` and `maximum` are non-negative integers. Current `resource` values are
`document_bytes`, `open_document_bytes`, and `live_requests`; current `scope`
values are `document` and `session`. Notification-form failures remain
response-free but MUST leave state unchanged. The diagnostic carries no URI,
path, request ID, source bytes, allocator values, Rust/debug output, or timing.

### 6. Failure precedence and atomicity

Malformed JSON/envelopes and malformed method parameters retain their existing
JSON-RPC errors. For document synchronization, URI, monotonic version,
open/read-only state, edit-range, and individual-document validation precede
aggregate accounting. Cancellation observed before complete result publication
retains `-32800`; a completed resource admission failure is not converted to
cancellation or stale. Host allocation failure is not caught or serialized as
`L-LSP-0002`.

No resource failure may publish a partial completion list, diagnostic set,
semantic-token history item, Workspace Edit, checked cache entry, overlay,
version, revision, or cancellation association. Accounting and selection depend
only on accepted bytes and counts, never allocator behavior, CPU count, host
load, thread identity, map iteration, paths, or wall time.

## Conformance plan

- Verify exact discovery and stable `-32803`/`L-LSP-0002` error data.
- Cover exact and one-over individual/aggregate byte boundaries, open/change/
  close/reopen cleanup, failed edits, read-only and untitled overlays, and retry.
- Cover 128 accepted live IDs, distinct 129th rejection, duplicate precedence,
  cancellation and completion cleanup, string/number IDs, and deterministic
  framed execution without sleeps or timing assertions.
- Retain completion, diagnostic, frame, and RFC-0005 solver-bound tests; prove
  that resource enforcement publishes no partial result or state.
- Cover multibyte Unicode, BOM, CRLF, malformed input, cancellation/stale races,
  repeated bytes, writer failure, and locked offline repository gates.

## Compatibility impact

- **Protocol:** adds Preview `ling.lsp.resource-limits/0.1` discovery and one
  structured JSON-RPC resource failure with no new method.
- **Diagnostics:** allocates `L-LSP-0002` with fixed meaning and integer/string
  Facts; `L-LSP-0001` and source diagnostics are unchanged.
- **LSP behavior:** adds aggregate overlay and live-request hard limits while
  exposing existing document, transport, completion, diagnostic, and solver
  bounds.
- **Compiler/schema/identity:** no successful compiler fact, source span,
  standalone schema, Semantic ID, Definition ID, or canonical byte changes.
- **Language/runtime/data:** no syntax, semantics, Typed Core evaluation,
  interpreter, runtime, bytecode, VM, ABI, package, filesystem/network, or
  Unicode 17.0.0 change.
- **Migration:** clients that ignore Experimental discovery are unchanged;
  rejected request-form operations can inspect the stable code and facts and
  retry after releasing session capacity.

## Unresolved alternatives

Allocator/RSS limits, configurable non-diagnostic quotas, eviction, partial
results, progress, deadlines, total compiler fuel, general dependency/workspace
memory accounting, persistent sessions, Stable lifecycle, and Semantic
Transactions remain deferred. They require separate accepted authority and
executable migration evidence.
