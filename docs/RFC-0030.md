# RFC-0030: LSP atomic workspace reload / LSP 原子工作区重载

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-23
> 目标版本：v0.1 Experimental
> 作者/Owner role：ide-protocol-design
> 相关缺口：GAP-LSP-TRANSACTION-PROTOCOL-001 | GAP-INCREMENTAL-CACHE-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines a bounded, client-published workspace reload request over
host-independent Ling URIs and exact UTF-8 bytes. It closes `LSP-2105` without
making filesystem watchers, paths, debounce timing, or host event ordering part
of Ling semantics.

本 RFC 使用与主机无关的 Ling URI 和精确 UTF-8 字节，定义有界的客户端发布工作区
重载请求。它关闭 `LSP-2105`，但不把文件系统 watcher、路径、去抖时间或主机事件
顺序纳入 Ling 语义。

## Summary

`ling.lsp.workspace/0.1` adds the request `ling/workspace/reload`. A client or
embedding host submits unique source and project-input deltas against an exact
session revision. The server validates and canonicalizes the complete batch,
applies it to a private VFS candidate, and publishes that candidate only if all
changes succeed. Open overlays continue hiding disk-source changes.

## Status and scope

- Current lifecycle state: `Accepted`
- Stable implementation basis: `yes` for this Experimental/current-writer-only
  protocol
- In scope:
  - exact session-revision preconditions and failure-atomic publication;
  - bounded upsert/removal deltas for workspace/dependency source snapshots;
  - bounded upsert/removal deltas for manifest, lock, config, profile, and
    target inputs;
  - canonical application order, no-op detection, overlay precedence, and
    immutable request snapshots;
  - targeted revision invalidation without eager full compilation.
- Out of scope:
  - filesystem access, `file://`, path/root discovery, symlink policy, watcher

  - document save semantics, changing an open editor buffer, diagnostics,

    Transactions, and Stable compatibility.
- Normative dependencies:
  - RFC-0002 locked local project model;
  - RFC-0004 lifecycle and transport;
  - RFC-0023 path-free URI, overlay, and document-version rules;
  - RFC-0025 single-root locked/offline project selection;
  - DEC-0019 revision-aware query invalidation;
  - DEC-0071 immutable workspace-state snapshots.

## Normative changes

### 1. Capability and method

Initialize success MUST extend `capabilities.experimental` with:

```json
{
  "lingWorkspaceReload": {
    "inputLimit": 5,
    "sourceLimit": 1024,
    "totalByteLimit": 1048576,
    "version": "ling.lsp.workspace/0.1"
  }
}
```

The method `ling/workspace/reload` MUST be a JSON-RPC request in the Ready
lifecycle state. A notification form is invalid and MUST NOT mutate state.

### 2. Request envelope

The request params are:

```json
{
  "baseRevision": "42",
  "inputs": [
    {"name": "manifest", "text": "..."},
    {"name": "lock", "text": null}
  ],
  "sources": [
    {"uri": "ling://workspace/src/Main.ling", "text": "..."},
    {"uri": "ling://dependency/math/src/Old.ling", "text": null}
  ]
}
```

`baseRevision` MUST be the canonical unsigned-decimal spelling of the current
session-local VFS revision: `0` or a nonzero digit followed only by digits,
with no sign, whitespace, or leading zero. Decimal strings avoid JSON-number
precision loss. A mismatch returns server error `-32007` and changes nothing.

`sources` and `inputs` MUST be arrays, and at least one entry MUST be present
across them. There may be at most 1,024 source entries and five input entries.
Unknown fields are ignored; required fields and their types are exact.

### 3. Source deltas

Each source entry contains a unique `uri` and `text`. The URI MUST use the
accepted `ling://workspace/` or `ling://dependency/` form; temporary and host
URIs are invalid. A string `text` upserts the exact UTF-8 disk snapshot and
MUST be no larger than 1 MiB. `null` removes an existing closed source. Removing
an unknown source or any source with an open overlay is invalid.

An upsert beneath an open overlay changes only the disk layer; the overlay
remains the visible request text until `didClose`. Reload never changes a client
document version or the monotonic version history for a URI.

### 4. Project-input deltas

Each input entry contains a unique `name` from `manifest`, `lock`, `config`,
`profile`, or `target`, plus `text`. A string upserts exact UTF-8 bytes no larger
than 1 MiB. `null` removes a present input; removing an absent input is a no-op.
No input is parsed during publication. Locked/offline project loading and
semantic validation remain later consumers of the immutable snapshot.

Manifest and lock revisions participate in project/cache identity. Config,
profile, and target revisions retain their accepted query-key roles. A changed
source allocates only its VFS revision; the server MUST NOT eagerly rebuild all
sources merely because one event arrived.

### 5. Bounds, ordering, and atomicity

The combined UTF-8 byte length of all string `text` fields MUST NOT exceed
1 MiB, matching the accepted transport body ceiling. Duplicate source URIs or
input names are invalid. After validation,
source entries are applied in canonical URI order and input entries in declared
input-name order. Client array order is not semantic.

The server MUST apply the batch to a private candidate including VFS,
document records, and request-snapshot inputs. Any invalid URI, bound, stale
revision, missing/open removal target, VFS failure, or revision exhaustion
rejects the whole request without changing visible bytes, disk bytes, inputs,
document state, version history, or revision. A successful batch publishes the
candidate exactly once.

### 6. Result and errors

A successful response is:

```json
{"changed": true, "revision": "45"}
```

`revision` is the canonical decimal VFS revision after publication. `changed`
is false only when every upsert equals existing bytes and every requested input
removal is already absent; such a no-op retains the base revision.

Malformed params, bounds, duplicate identities, invalid URIs, and invalid
removals return JSON-RPC `-32602` with a stable bilingual message. A stale base
uses `-32007` with a stable bilingual message. These are protocol errors, not
Ling compiler diagnostics, so no `L-<DOMAIN>-<NUMBER>` allocation is added.

### 7. Explicit non-claims

This protocol is a publication boundary, not a host watcher. It does not say
how a client observes files, coalesces OS events, resolves symlinks, maps paths
to Ling URIs, reads bytes, or retries. It does not promise that successful
publication produces valid syntax, a valid project graph, diagnostics, or a
completed compiler request.

## Conformance plan

- Verify capability and exact request/result bytes, canonical decimal revision
  parsing, lifecycle/request-only behavior, and current-writer-only discovery.
- Cover source/input add, change, removal, no-op, canonical order, revision
  allocation, open-overlay precedence, close-after-disk-change, and immutable
  request snapshots.
- Reject stale bases, malformed/duplicate/over-limit batches, unknown source
  removal, open-overlay removal, unsupported/temporary URIs, and oversized
  individual/aggregate text while proving complete failure atomicity.
- Exercise manifest/lock/config/profile/target inputs, workspace/dependency
  sources, Unicode names/text, BOM, CRLF, repeated runs, and different client
  array orders with identical results.
- Verify locked/offline workspace tests, strict Clippy, CI, governance, support,
  status, RC0, traceability, formatting, and deterministic diff gates.

## Compatibility impact

- **Protocol:** adds Experimental `ling.lsp.workspace/0.1` and capability;
  there is no earlier reader or migration path.
- **Source/CLI/diagnostics/schema/Semantic ID/runtime/ABI:** none; reload accepts
  opaque exact bytes and allocates no compiler diagnostic or public schema.
- **Cache:** the package-lock input joins disposable internal query identity;
  no persistent public cache format or cross-process revision is introduced.
- **Unicode:** identifiers, source maps, and tables remain Unicode 17.0.0.

## Unresolved alternatives

Standard `workspace/didChangeWatchedFiles` was rejected for this version because
its URI-only events would require unspecified host filesystem access. Sending
host paths was rejected because paths and symlink identity are not Ling
semantics. A complete-snapshot payload was rejected because large workspaces
would be republished for a one-file change.

Host watcher adapters, `file://` mapping, multi-root projects, network-backed
dependencies, compiler-result cancellation/staleness, diagnostics refresh,
and Stable protocol lifecycle remain future work under their existing gaps.
