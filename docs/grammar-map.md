# Ling Seed grammar map

> Task: `TS-3101`
> Scope: `v0.0.1` Seed Author Source only
> Status: implementation map; not a language specification
> Updated: 2026-08-20

This document maps the current Ling compiler syntax surface to the proposed Tree-sitter CST and its corpus obligations. It is the input contract for `TS-3102`; it does not implement a Tree-sitter grammar and does not make Tree-sitter an authority for Ling validity.

## 1. Authority and status

Language behavior follows the repository authority order. The syntax sources relevant to this map are:

1. Accepted decisions: [DEC-0004](decisions/0004-pipeline-syntax.md), [DEC-0005](decisions/0005-seed-literals-and-delimiters.md), [DEC-0006](decisions/0006-offside-layout.md), [DEC-0007](decisions/0007-module-and-file-boundaries.md), [DEC-0009](decisions/0009-seed-borrow-and-mutation-boundary.md), [DEC-0010](decisions/0010-state-and-capability-model.md), [DEC-0013](decisions/0013-main-and-runtime-failures.md), [DEC-0014](decisions/0014-seed-prelude-option-result.md), and [DEC-0017](decisions/0017-seed-boolean-operators.md).
2. Draft specifications: [RFC-0001 §7–8](RFC-0001.md), [SEMANTICS §3, §6, §8–11, and §29](SEMANTICS.md), and [LANGUAGE §4, §5, and §19](LANGUAGE.md).
3. Existing conformance tests and compiler behavior: [`ling-syntax`](../crates/ling-syntax/src/parser.rs), [`ling-ast`](../crates/ling-ast/src/lib.rs), and the [Seed conformance corpus](../tests/conformance/).

`RFC-0001` remains Draft. Therefore a row marked **Seed baseline** describes the implemented `v0.0.1` surface but is not a Stable syntax promise. The open [`GAP-GOV-RFC-STATUS-001`](status/spec-gaps/GAP-GOV-RFC-STATUS-001.md) remains the release-level blocker. A row marked **Accepted** has a direct Accepted decision; it may still depend on Draft surrounding productions.

Tree-sitter must be no more authoritative than these sources. A Tree-sitter parse may support incomplete editing states, while `ling-syntax` remains the validity oracle and preserves original UTF-8 byte spans.

## 2. Mapping conventions

- Proposed Tree-sitter named nodes use `snake_case` and should remain shallow and query-friendly.
- A leading underscore denotes a private grammar helper. Private helpers do not appear as named CST nodes and do not become Ling syntax.
- Tree-sitter's built-in `ERROR` and `MISSING` nodes represent recovery only. They must never be lowered as successful Ling AST nodes.
- Keywords and punctuation should normally be anonymous tokens. Semantic roles such as type, constructor, parameter, or field are resolved by queries/LSP rather than by duplicating identifier tokens.
- `source_file` is the Tree-sitter root name; it maps to compiler `NodeKind::Program` rather than creating a second program concept.
- The planned corpus locations below are relative to `editors/tree-sitter-ling/test/corpus/`, the standalone-ready in-tree development mirror used while the grammar and compiler corpus evolve together. Existing evidence links to this repository.
- Before a new public grammar rule is added, this map must gain an Accepted source or explicitly classify the rule as a private recovery helper.

## 6. Expressions and precedence

The proposed Tree-sitter CST deliberately uses one named `binary_expression` node for boolean, arithmetic, comparison, and equality operators. Precedence is encoded in grammar precedence declarations rather than exposed as a tower of named wrapper nodes. This mirrors the compiler's `NodeKind::BinaryExpression` and keeps queries shallow.

From lowest to highest binding strength, Accepted DEC-0017 fixes the Seed order as assignment, pipeline, boolean `||`, boolean `&&`, equality, comparison, additive, multiplicative, application, projection, prefix unary, and primary forms. Assignment is non-associative at one unparenthesized layer; pipeline, boolean/binary operators, application, and projection are left-associative; prefix unary operators are right-associative.

## 7. Private helper and recovery map

These rules are permitted only as implementation structure. They must remain private, must not appear as semantic nodes, and must not be cited as language features.

| Helper purpose | Compiler analogue | Tree-sitter helper | Required recovery corpus |
| --- | --- | --- | --- |
| Select top-level declaration forms | `parse_program` token dispatch | `_declaration` | `errors.txt: declaration/unknown-and-out-of-order` |
| Select expression alternatives | `parse_expression` | `_expression`, `_primary_expression` | `errors.txt: expression/incomplete-primary` |
| Select pattern alternatives | `parse_pattern` / HIR pattern classification | `_pattern` | `errors.txt: pattern/incomplete-*` |
| Select type alternatives | `parse_type`, `parse_type_atom` | `_type`, `_type_atom` | `errors.txt: type/incomplete-*` |
| Separate record/list members | `eat_member_separators` | `_member_separator` | `errors.txt: delimiter/wrong-separator` |
| Start/end an offside body | `parse_body_expression`, `parse_sequence` | named `block` plus TS-3103 external `_indent`, `_dedent`, `_newline`, and `_soft_newline` tokens | Existing: `layout.txt`, scanner state/integration tests. TS-3107 still owns malformed indentation recovery. |
| Continue after an operator, case-leading `|`, or line-leading `|>` | `continuation_operand_start`, `consume_continuation_prefix`, match-case loop | private `_line_leading_bar` plus indented continuation tokens | Existing: `layout.txt: Operator continuation and line-leading pipeline`, `layout.txt: Match cases align and case bodies indent`. TS-3105 owns exhaustive precedence cases. |
| Preserve incomplete editing state | compiler `NodeKind::Error` and bounded recovery; no AST lowering | Tree-sitter built-in `ERROR` / `MISSING` only | `errors.txt: unclosed-string-record-tuple`, `errors.txt: missing-equals-arrow-with`, `errors.txt: partial-unicode-identifier`, `errors.txt: random-edit-smoke` |

Additional private helpers are allowed only when they factor repeated grammar structure. Adding a named recovery node, accepting an otherwise invalid source form, or making a helper visible to queries requires updating this map first.

## 8. Deliberately unmapped or deferred syntax

The following must not receive successful Tree-sitter language nodes in `TS-3102`:

| Surface | Reason | Expected Tree-sitter behavior | Corpus |
| --- | --- | --- | --- |
| `and` recursive binding groups | `and` is lexed/reserved, but no current Seed production or executable corpus defines mutual-recursion syntax; DEC-0012 explicitly defers multi-definition recursive groups | finite `ERROR`; do not invent a declaration node | `future-keywords.txt: and-binding-group`, `errors.txt: declaration/and` |
| Per-parameter annotation such as `(value: T)` | Appears in Draft design examples but is not the current parser's let-header grammar; only the declaration-level return annotation is implemented | finite `ERROR`; no parameter-annotation node | `future-keywords.txt: parameter-annotation` |
| Character, raw, interpolated, or multiline string literals | Explicitly outside DEC-0005 Seed literals | finite `ERROR`; preserve surrounding tree | `future-keywords.txt: future-literals`, `errors.txt: literal/unsupported-char-and-string` |
| Empty record, comma-separated record/list members, or singleton tuple | Rejected by DEC-0005 | finite `ERROR` / `MISSING` | `errors.txt: delimiter/rejected-shapes` |
| Shebang | Not accepted; the Zed plan explicitly forbids assuming it | finite `ERROR` at file start | `future-keywords.txt: shebang` |
| Localized keyword aliases or raw identifiers | Open alias/localization design; no Accepted syntax | identifiers only where the compiler accepts them; otherwise finite `ERROR` | `future-keywords.txt: localized-keywords-and-raw-identifiers` |
| Trait, impl, Resource/Borrow, Effect Handler, Task, Actor, Node, Kernel, Contract, package, test, async, and placement syntax | Outside the Seed subset; reserved words or future concepts are not placeholder features | mirror the current compiler's lexical treatment (most are still `Identifier`), but never create a successful feature node or highlight them as active syntax | `future-keywords.txt: post-seed-syntax` |

The compiler currently has token kinds for some deferred words/operators. A lexer token is not a grammar production and does not authorize Tree-sitter to accept a feature.

## 9. TS-3102 entry checklist

`TS-3102` may begin from this map when it preserves these constraints:

- implement only `source_file`, declarations, types, patterns, expressions, identifiers, literals, comments, and the private helpers listed here;
- create the six planned corpus files and at least one case for every generated named rule; TS-3103 through TS-3108 add the detailed layout, Unicode, precedence, pattern/type, recovery, and differential cases named in the rows above;
- keep `binary_expression` shallow while testing every precedence pair and associativity boundary;
- treat offside/layout tokens as parsing mechanics, not Semantic Hash inputs;
- keep Unicode validation, NFC, confusable detection, and diagnostics authoritative in the compiler;
- ensure the TS-3102 positive corpus and grammar-local examples parse without `ERROR`/`MISSING`, while its invalid and future cases terminate with a finite tree; full shared Seed corpus parity is the staged exit condition of TS-3103 through TS-3108;
- preserve surrounding declarations during incomplete edits without manufacturing a successful Ling AST;
- update this map before adding, renaming, or exposing any grammar rule.

No Tree-sitter node name in this document is a public Ling protocol or Semantic ID input. Node-name compatibility begins only if a later Accepted tool-protocol decision explicitly declares it.
