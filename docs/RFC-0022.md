# RFC-0022: Trait Semantic IDE Projection / Trait 语义 IDE 投影

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-22
> 目标版本：v0.1 Living
> 作者/Owner role：type-system-design
> 相关缺口：GAP-TRAIT-COHERENCE-001
> 生命周期记录：`docs/governance/lifecycle.toml`

This RFC defines the first, intentionally bounded, editor-facing projection
of the immutable Trait dictionary witnesses established by RFC-0021. It adds
an optional `x-ling-trait-ide` extension to the existing semantic graph JSON
documents. The extension is data-only: an editor can use it to identify a
Trait member, its selected implementation, and the original source spans
without repeating Trait selection.

本 RFC 规定 RFC-0021 建立的不可变 Trait dictionary witness 的首个、明确受限的编辑器
投影。它在现有 Semantic Graph JSON 文档中增加可选的 `x-ling-trait-ide` 扩展。该
扩展仅承载数据：编辑器可以据此识别 Trait 成员、已选实现和原始源码 span，而不再
重新执行 Trait 选择。

## Summary

The projection is emitted only when a checked program contains a concrete,
statically selected `Trait.member` witness. It preserves the selected
implementation and ordered member identities from Checked Core, includes
original UTF-8 byte spans for navigation, and uses path-free deterministic
IDs. Programs with no Trait witnesses serialize exactly as before.

The RFC does not define JSON-RPC methods, document synchronization, request
versions, Workspace Edits, rename transactions, diagnostics, repairs, generic
Traits, blanket implementations, trait objects, or a Stable 1.0 editor claim.
Those surfaces require separate accepted authority.

- Current lifecycle state: `Accepted`
- Stable implementation basis: `yes` for the experimental v0.1 projection
- In scope:
  - the optional `x-ling-trait-ide` extension on `ling.semantic/0.1` and
    `ling.semantic/0.2` graphs;
  - concrete nominal receivers and immutable witnesses selected by RFC-0005
    and lowered by RFC-0021;
  - deterministic Trait, implementation, and member identities;
  - original source-name and UTF-8 byte-span provenance for Trait and

- Out of scope:
  - LSP/JSON-RPC methods, document overlays, cancellation, stale versions,

  - generic/blanket implementations, associated types, default methods,

  - changes to the v0.0.1 Seed support matrix or a Stable 1.0 promise;

  - RFC-0005 §4.1–§4.2;

  - DEC-0012 semantic graph canonical identity and extension policy.

## Normative changes

1. A graph MAY contain one root-level field named `x-ling-trait-ide`. The
   field MUST be omitted when the checked dictionary table is empty. When
   present it MUST be an object with `version: "0.1"` and a `witnesses` array.
   This is an `x-*` extension and does not change the core semantic schema
   version.
2. `witnesses` MUST be sorted by ascending `obligation_order`. Each witness
   MUST contain `trait_id`, `trait_name`, `trait_module`, `receiver`,
   `implementation_id`, `implementation_module`, `obligation_order`, and
   `members`.
3. `trait_id` MUST be the string form
   `experimental:blake3:<64 lowercase hex digits>`. Its digest input MUST be
   the length-prefixed UTF-8 sequence, in order:
   `ling.trait-ide-id/v1`, language version, semantic schema, optional package
   coordinate, canonical Trait module, Trait name, and the ordered Trait
   member DefinitionIds. It MUST NOT include host paths, source spans,
   allocation details, or map iteration order.
4. `implementation_id` MUST use the same string form. Its digest input MUST
   be the length-prefixed UTF-8 sequence, in order:
   `ling.impl-ide-id/v1`, language version, semantic schema, optional package
   coordinate, canonical implementation module, `trait_id`, canonical
   receiver, and the ordered implementation member DefinitionIds.
5. Every member entry MUST contain `ordinal`, `name`,
   `trait_definition_id`, `implementation_definition_id`, `trait_source`,
   `trait_span`, `implementation_source`, and `implementation_span`.
   Members MUST be sorted by ascending ordinal, and ordinals MUST be unique.
   Definition IDs MUST be the exact IDs carried by the checked witness and
   resolved program; the projection MUST NOT synthesize a second callable ID.
6. A span object MUST contain `source`, `start`, and `end` unsigned integers,
   where `start <= end` and the range denotes original UTF-8 bytes in the
   named source. The projection MUST preserve the original span and MUST NOT
   normalize CRLF, Unicode scalars, or BOM bytes.
7. A reader MUST reject an unknown extension version, malformed digest,
   duplicate or unsorted witness/member ordinals, empty required identities,
   invalid span ordering, or a member whose selected implementation does not
   match the checked witness. It MUST never re-run coherence or solver
   selection while reading the graph.
8. The extension is observational only. It MUST NOT alter `program_id`,
   bytecode revisions, interpreter/VM behavior, CLI command availability,
   diagnostics, or Unicode data. The existing canonical dictionary bytes
   remain the source of checked semantic identity.

## Conformance plan

- Serialize a concrete same-module Trait witness and verify all witness and
  member fields, original byte spans, and deterministic ordering.
- Verify that a Seed graph without Trait witnesses is byte-for-byte unchanged.
- Round-trip valid extension JSON through `read_json` and `read_project_json`.
- Reject wrong extension versions, malformed IDs, duplicate/unsorted ordinals,
  invalid spans, and mismatched member identities without evaluating data.
- Compare repeated processes, source presentation names, module order, and
  package-aware graphs; IDs and logical ordering MUST remain stable while
  source-name/span provenance remains available.
- Keep LSP request/response, rename, repair, stale-document, and transaction
  fixtures explicitly deferred to a later accepted protocol.

## Compatibility impact

- Source: no new syntax and no change to v0.0.1 source acceptance.
- Semantic graph: adds one optional `x-*` extension; existing readers that
  follow the extension policy may ignore it, while this reader validates the
  known `0.1` form.
- Identity: no new program-id input; witness identity remains governed by
  RFC-0021 canonical bytes.
- Diagnostics, CLI, LSP wire, bytecode, VM, package lock, ABI/FFI, and Unicode
  17.0.0: unchanged.
- Stability: the extension is Experimental until the v1.0 gates and an
  accepted editor protocol provide stronger compatibility guarantees.

## Unresolved alternatives

- A new `ling.semantic/0.3` core schema is deferred because the existing
  extension policy already provides a versioned, opt-in data boundary.
- JSON-RPC query methods and Workspace Edit/transaction semantics require a
  later RFC covering snapshots, document versions, cancellation, and stale
  result behavior.
- Generic dispatch, trait objects, and repair synthesis remain separate
  language and safety decisions.
