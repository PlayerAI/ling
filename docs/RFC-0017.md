# RFC-0017: Seed mutable-place lowering / Seed 可变 Place Lowering

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-21
> 目标版本：v0.0.1 Seed
> 作者/Owner role：vm-design
> 相关缺口：GAP-BYTECODE-SEMANTICS-001
> 生命周期记录：`docs/governance/lifecycle.toml`

## Summary

This RFC defines how the already-checked Seed mutation boundary is lowered to
the existing `ling.bytecode/1.2` model. It makes mutable local bindings and
mutable record-field assignment executable without exposing Rust cells,
aliasing, or host layout as Ling behavior.

本 RFC 规定已通过检查的 Seed mutation boundary 如何降低到现有
`ling.bytecode/1.2` 模型。它使可变局部绑定和可变 record 字段赋值可执行，
同时不把 Rust cell、别名或宿主布局暴露为 Ling 行为。

## Status and scope

- Current lifecycle state: `Accepted`
- Stable implementation basis: `yes` for the Experimental v1.2 bytecode slice
- In scope:
  - mutable local assignment (`let mutable name = value; name <- value`);
  - mutable record-field assignment rooted at that local;
  - nested record-place updates;
  - deterministic control-flow joins after mutation;
  - differential agreement with the checked Seed interpreter.
- Out of scope:
  - mutable lexical captures and mutation through closures;
  - function-parameter or imported/global mutation;
  - borrow inference, `&mut`, Resource values, async/Actor turns, and native ownership;
  - aggregate equality, serialization, lists, and recursive wire types.
- Normative documents or clauses affected:
  - `DEC-0009` (Seed borrow and mutation boundary);
  - `docs/SEMANTICS.md` §9 and §29;
  - `docs/LANGUAGE.md` assignment examples;
  - `RFC-0014` and `RFC-0016` bytecode evaluation and aggregate instructions.

## Normative changes

1. The checker remains the sole authority for assignment legality. The lowerer
   MUST consume checked Typed Core and MUST reject an absent or inconsistent
   place/type record rather than infer mutability again.
2. A mutable local root MUST be represented by the current SSA value in the
   lowering environment. `name <- value` MUST evaluate `value` once, replace
   the current root value, and produce `Unit`.
3. A field assignment MUST create an independent record value. For a place
   `root.f1...fn`, the lowerer MUST update the innermost record first and then
   rebuild each enclosing record through the existing immutable `UpdateRecord`
   instruction. The final rebuilt root becomes the current root value.
4. Assignment evaluation MUST preserve source order and MUST not introduce
   observable aliasing. Record copies remain independent values; a mutable
   field is a write permission, not a shared runtime cell.
5. When control flow branches, every mutable root visible before the branch
   MUST have a typed value at the merge block. Each predecessor MUST pass its
   current value as a block argument, and the post-merge environment MUST use
   the corresponding block parameter. This applies to `if`, checked `match`,
   and short-circuit boolean operators.
6. The lowering MUST NOT add an opcode, wire field, or protocol revision.
   Existing v1.2 readers and verifiers remain authoritative; v1.0 and v1.1
   artifacts retain their existing behavior and rejection boundaries.
7. Mutable lexical captures, parameters, top-level bindings, and non-mutable
   fields MUST remain rejected by the checked pipeline. The VM MUST NOT perform
   borrow inference or reinterpret an unchecked assignment.
8. Source maps MUST retain the original UTF-8 byte span for assignment and
   derived record-update instructions. Ordering MUST remain deterministic and
   independent of Rust allocation or hash-map iteration order.

## Conformance plan

- Lower and execute mutable local reassignment with scalar values.
- Lower and execute mutable field assignment, nested field assignment, and
  record-copy independence.
- Lower assignments in both branches of `if`, checked `match`, and boolean
  short-circuit expressions; verify block parameters and post-merge reads.
- Reject immutable roots/fields, parameters, imports, top-level mutation, and
  mutable lexical capture with the existing bilingual diagnostic codes.
- Compare checked-interpreter and verified-VM values, effects, and source spans.
- Verify deterministic bytes/disassembly, malformed-input safety, and unchanged
  v1.0/v1.1 compatibility.

## Compatibility impact

- Source semantics: implements only the assignment forms already authorized by
  `DEC-0009`, `SEMANTICS`, and `LANGUAGE`.
- Bytecode: no new opcode or revision; v1.2 lowering gains coverage using
  existing `UpdateRecord` and CFG block parameters.
- CLI, diagnostics, JSON schemas, Semantic IDs, canonical semantic bytes, ABI,
  and Unicode 17.0.0 tables: None changed.
- Runtime layout: no public cell or ownership representation is introduced.

## Unresolved alternatives

- Borrow/resource semantics for later versions remain governed by future RFCs.
- Mutable closure captures remain intentionally rejected until a separate
  capture/aliasing authority and executable protocol are accepted.
- A dedicated runtime place instruction remains a possible future optimization,
  but is not part of this RFC.
