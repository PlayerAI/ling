## Summary

This RFC defines `ling completion <shell>` and the canonical
`ling.cli-completion/0.1` scripts for Bash, Zsh, Fish, and PowerShell. The
scripts expose only the command, subcommand, option, alias, and enumerated
value inventory already accepted and implemented by the current CLI.

本 RFC 定义 `ling completion <shell>`，以及面向 Bash、Zsh、Fish 和
PowerShell 的规范化 `ling.cli-completion/0.1` 脚本。脚本只公开当前 CLI
已经接受并实现的命令、子命令、选项、别名和枚举值。

Generation is offline, deterministic, and independent of the working
directory, environment, clock, network, locale, and filesystem contents. This
RFC versions generated script bytes; it does not freeze ordinary help wording
or layout.

## Normative changes

### 1. Command and exit contract

The implementation adds exactly:

```text
ling completion <bash|zsh|fish|powershell>
```

The command MUST accept exactly one UTF-8 shell operand and MUST accept no
output-policy or command-specific option. A supported operand writes one script
to stdout, writes nothing to stderr, and exits `0`. Missing, extra, non-Unicode,
or unsupported operands produce the existing usage error on stderr, no stdout,
and exit `2`. A stdout host failure uses the existing host-fault diagnostic and
exit `4`; no new diagnostic code is allocated.

The command MUST NOT read stdin, source files, manifests, lockfiles, project
state, shell configuration, environment variables, or the network. It MUST NOT
write a file or install/activate the script. Users explicitly redirect or source
stdout according to their shell's own policy.

### 2. Authoritative inventory

The internal CLI command catalog remains the implementation source for command
names. Completion MUST include exactly these root candidates, in this order:

```text
run check repl semantic audit query patch fmt init test build project lsp completion
```

At root level it MUST also include `--help`, `-h`, `--version`, and `-V`.
`project` MUST offer only `check`; `completion` MUST offer only the four shell
operands. Each command MUST offer exactly the options the accepted parser
supports for that command. Enumerated values MUST be offered for `--format`,
`--language`, `--color`, `--capability`, `--profile`, and `--target`.

No planned, rejected, hidden, deprecated, or stale `zero`/`.zero` spelling may
appear. The scripts do not complete positional paths or names in version 0.1;
the native shell may retain its ordinary fallback behavior outside this
generator's candidate set.

An internal invariant test MUST compare completion roots with the parser
catalog, mapping the hierarchical catalog entry `project check` to root
`project`. Adding, removing, renaming, or reordering a public command, option,
subcommand, alias, or enumerated value requires an Accepted authority update,
new fixtures, and a completion protocol version review.

### 3. Canonical script bytes

The protocol marker is `ling.cli-completion/0.1`; every script MUST contain it
in a comment. For each shell, output MUST be a deterministic, BOM-free UTF-8
document using LF line endings and exactly one final LF. The committed fixtures
under `tests/protocols/cli-completion/` are the canonical bytes for version 0.1.

All generated candidate literals are fixed ASCII tokens and MUST use static
shell quoting. Scripts MUST NOT evaluate generated command text, invoke `ling`,
enumerate files, inspect processes, or contact external services while
completing. Bash registers `_ling` with `complete`; Zsh registers `_ling` with
`compdef`; Fish emits `complete -c ling` declarations; PowerShell registers one
native argument completer for `ling`.

### 4. Help lifecycle

`ling --help` and `ling -h` MUST advertise the implemented `completion` form and
remain semantically equal, truthful UTF-8 output under DEC-0040. Their layout,
wording, line wrapping, and exact bytes remain non-canonical and may change
without changing `ling.cli-completion/0.1`, provided the accepted command
inventory stays consistent.

## Conformance plan

- Generate all four scripts in independent processes and compare exact bytes
  against committed canonical fixtures.
- Verify repeated generation, UTF-8, LF-only bytes, one final LF, protocol
  markers, current root/option/value coverage, hierarchy, and stale-name
  exclusion.
- Verify missing, unknown, extra, and output-policy operands exit `2`, leave
  stdout empty, and render truthful usage on stderr.
- Parse each committed fixture with Bash, Zsh, Fish, or PowerShell whenever the
  corresponding shell is installed on the test host; retain platform-neutral
  structural inventory tests when a shell is absent.
- Verify help aliases include `completion` without freezing help bytes and run
  workspace, CI, governance, support, status, RC0, traceability, Clippy,
  rustfmt, offline, and deterministic-diff gates.

## Compatibility impact

- **Source/language:** no syntax, type, Effect, Capability, ownership, runtime,
  or evaluation rule changes.
- **CLI:** adds one Preview root with four fixed operands; existing command
  forms and exit meanings are unchanged.
- **Diagnostics:** no new code; usage and host-output failures reuse accepted
  classes.
- **Protocol:** adds canonical text protocol `ling.cli-completion/0.1` and four
  exact script fixtures; there is no predecessor or migration adapter.
- **Help:** adds a truthful command line but makes no help-byte promise.
- **Semantic IDs/data/ABI:** no Semantic ID, schema JSON, source span, artifact,
  cache, bytecode, VM, ABI, or filesystem mutation.
- **Determinism/Unicode:** output is fixed ASCII plus UTF-8/LF framing and does
  not depend on Unicode tables; Unicode remains 17.0.0 elsewhere.

## Unresolved alternatives

Dynamic path/package/module/symbol completion, descriptions and localization,
shell-specific installation commands, completion for future commands, plugin
or daemon discovery, and Stable 1.x compatibility require separate Accepted
authority. A third-party argument parser/completion library remains unnecessary
for the current fixed inventory.
