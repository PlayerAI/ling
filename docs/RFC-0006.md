# RFC-0006: Effect Rows and First-Order Handlers / Effect Row 与一阶 Handler

> 状态：Accepted
> 类型：Standards Track
> 创建日期：2026-08-22
> 目标版本：v0.2 Concurrent (Experimental)
> 作者/Owner role：effect-system-design
> 相关缺口：GAP-EFFECT-STATE-MASKING-001 | GAP-EFFECT-HANDLER-001
> 生命周期记录：`docs/governance/lifecycle.toml`

RFC-0006 closes the missing v0.2 Effect authority required by the G2 plan.
It defines the canonical row/operation model and a first-order handler
contract while preserving the v0.0.1 Seed implementation boundary. Runtime
execution, Task/Actor lifecycle, replay, and public protocol integration remain
separate authorities.

本 RFC 关闭 G2 所需的 v0.2 Effect 权威，规定 canonical Effect Row、operation
signature 和一阶 handler contract，同时保持 v0.0.1 Seed 实现边界不变。Runtime
执行、Task/Actor 生命周期、Replay 与公共协议仍由独立 RFC 决定。

## Summary

The v0.2 model represents an Effect row as a sorted, duplicate-free set of
canonical labels plus either a closed tail or a named row variable. Operations
carry an explicit input/output signature and a declared resume cardinality.
Handlers are lexical, checked regions that remove only the operations they
declare and leave a residual row; they never grant host Capability authority.
`State<T>` remains visible in the row in this revision. Task, Actor, Remote,
and Replay behavior may use these labels only after their own accepted RFCs
define lifecycle and transport rules.

## Normative changes

1. **Effect identity.** `EffectId` is a non-empty NFC-normalized UTF-8 name
   made of non-empty identifier segments separated by `.`. It is compared by
   its canonical bytes and contains no source path, host address, allocation
   index, Rust type name, or display-only alias. Existing Seed labels retain
   their canonical spellings `Console.Write` and `State`.
2. **Parameterized labels.** An `EffectLabel` is an `EffectId` plus zero or
   more canonical Typed-Core type references. Parameters are compared in order;
   labels are equal only when both identity and every parameter are equal.
   `State<T>` therefore remains distinct for different resolved `T` identities.
3. **Rows.** An `EffectRow` contains a sorted, duplicate-free label set and a
   tail: `Closed` or `Variable(RowVariableId)`. The empty closed row is `Pure`.
   A row variable is a non-negative binder-local integer whose canonical
   ordering is its integer value. A row MUST NOT contain more than one tail.
4. **Row operations.** Union preserves the sorted unique labels and combines
   equal tails. Combining two different open tails is a constraint for
   EFF-2102, not an arbitrary host choice. A handler removes only labels whose
   operation is explicitly declared and preserves the input tail as the
   residual row. No operation silently masks `State<T>`.
5. **Operations.** An `EffectOperation` contains an owning `EffectId`, a
   non-empty operation name, an ordered input type-reference list, one output
   type reference, and a `ResumeMode` of `Never`, `Once`, or `Many`. Input,
   output, and resume references are canonical Typed-Core identities, not
   pretty-printed source types.
6. **Handlers.** A `HandlerContract` is a lexical list of unique operation
   signatures, a residual row, and the declared resume mode for each clause.
   The checker MUST reject an operation clause whose signature does not match
   the handled Effect label. A handler cannot synthesize an operation,
   authorize a Capability, or change a source span. Nested handlers consume
   the inner residual row before the outer row is checked.
7. **Capability separation.** Effect presence describes observable program
   behavior; Capability facts authorize host operations. Handling an Effect
   does not grant or remove a Capability. A host operation still requires its
   accepted Capability closure before evaluation.
8. **Reserved labels.** The registry reserves `Clock`, `Random`, `Console`,
   `State`, `Task`, and `ActorSend` as canonical Effect IDs. `Console.Write`
   and `State<T>` retain the Seed behavior. Clock/Random operation behavior,
   Task/Actor lifecycle, message ownership, cancellation, replay, and remote
   delivery require their respective accepted RFCs and MUST NOT be inferred
   from the label names alone.
9. **Projection and determinism.** A checked projection MAY expose row labels,
   tails, operation signatures, and residual rows in canonical order. It MUST
   preserve original UTF-8 spans when source nodes exist and MUST exclude host
   paths, allocation order, hash-map order, timing, thread scheduling, and
   debug formatting from identity or canonical bytes.
10. **Compatibility.** Existing Seed programs, schemas, diagnostics, Semantic
    IDs, bytecode, VM behavior, CLI, LSP behavior, and Unicode 17.0.0 data are
    unchanged. A v0.2 implementation MUST be explicitly marked Experimental
    until its inference, lowering, runtime, and differential fixtures pass.

## Conformance plan

- Construct pure, closed, open, parameterized, duplicate, and reordered rows;
  compare canonical values and bytes across processes and presentation order.
- Verify `State<Int>` and `State<Text>` remain distinct, while duplicate labels
  collapse and pure remains the empty closed row.
- Verify operation signatures preserve ordered type references and resume
  cardinality; reject empty names, malformed IDs, duplicate clauses, and
  mismatched handled labels.
- Verify nested handler residual rows and explicit `Never`/`Once`/`Many`
  declarations without executing a handler or granting Capability authority.
- Verify Unicode NFC, CRLF, BOM, original byte spans, package coordinates,
  and source-name changes do not enter path-free canonical identities.
- Add positive/negative fixtures for pure rows, Clock/Random registration,
  missing Capability, unhandled residual effects, and deferred Task/Actor
  lifecycle crossings. EFF-2102/2103 own solver and Typed-Core fixtures.

## Compatibility impact

- Source and Seed language: no v0.0.1 syntax or acceptance changes.
- Compiler: the model is available to the future checked pipeline; current
  Seed `EffectRow` remains the existing closed set.
- Diagnostics: future row/handler diagnostics use the registered `L-EFFECT-*`
  domain and bilingual Facts; this RFC does not silently reuse a different
  domain or expose host errors.
- Semantic Graph/Audit: a future versioned projection may carry the model;
  no existing schema field is changed by this RFC alone.
- Runtime/bytecode/CLI/LSP/protocol/package/ABI: unchanged.
- Unicode: all canonical identity and source-span rules remain on Unicode
  17.0.0 and original UTF-8 bytes.

## Unresolved alternatives

- EFF-2102 decides the row-constraint solver, occurs check, generalization,
  minimal conflict facts, and diagnostic allocation details.
- EFF-2103 decides the exact source syntax and Checked-Core handler nodes,
  including scope crossing and resume checking.
- RFC-C202/C203/C204/C205/C206 decide Task, Actor, supervision, Replay, and
  Remote lifecycle/transport semantics.
- State masking is intentionally rejected in this revision; a later RFC may
  add a proof-carrying mask only with migration and differential evidence.
